# 影匠 · 规矩与本项目已犯过的错

> **每个代理开工前先读这份。** 这里每一条都是**实际犯过**的，不是假设。
> 标 🔴 的是**代价最大**的，标 ⚙️ 的是**技术陷阱**（犯过 ≥2 次）。

---

## 一、红线（只有两条，其余一律放开）

1. **不破解加密包**（如 `9876543210-*.js`）。
2. **不伪造设备指纹 / 不绕过授权心跳**。

其余全部放开：**能用就用、能抄就抄、能整段搬就整段搬。不许重写，不许「另行创作」。**

🔴 **犯过的错**：我立过一条「只学设计、不抄代码」的死规矩，结果 5 个代理把飞彩 `.next` 里**已经写好的逻辑**重新想一遍再重写一遍 —— 拿用户的时间和 token 买我自己的清高。**再也不许。**

---

## 二、Token 与上下文（代价最大的一类）

### 🔴 2.1 折叠必须批量，一次一个等于烧钱
压缩会重写整个对话前缀 → 上游缓存全失效 → 整段按**全价重发**。
**我在 9 分钟里一次一个地折了 38 次，每次都是一记完整的 770K 重付 —— 2.77M token，占全程未命中的 73%。**
> **规矩**：`compress` 一次交**所有**可折范围。工具原话「NEVER split the batch across separate calls」是硬约束，不是建议。

### 🔴 2.2 别等上下文涨到 770K 才折
前缀越长，一次重付越贵。早折时前缀短，重付便宜。
> **规矩**：上下文一过 ~150K 就折，不要拖。

### 🔴 2.3 代理结项就立刻派下一个活
用户原话：「一个子智能任务完成了就让他进行去再做啊」。
> **规矩**：收到结项回执的**同一轮**里就发新任务，不要让代理空转、不要让用户等。

### ⚙️ 2.4 别在同一个坑里反复重启
**犯过**：curl 卡 → 改 3 版下载器、写 2 版部署脚本、重启无数次，而根因只有一句话（`hf-mirror` 对 xet 仓 302 跳 `cas-bridge.xethub.hf.co` 后僵死）。
> **规矩**：同一个失败**第二次**出现时，停手定位根因，不许再换参数重试。

## 三、下载与网络

### ⚙️ 3.1 `huggingface_hub` 的 xet 后端在镜像后必死
`hf-mirror.com` 对 xet 仓会 302 跳到 `cas-bridge.xethub.hf.co`，`huggingface_hub` **死在那儿**：`.incomplete` 永远 0 字节、CPU 几乎不动、**既不报错也不超时**。
设 `HF_HUB_ENABLE_HF_TRANSFER=0` **拦不住**，必须 `HF_HUB_DISABLE_XET=1`。
> **规矩**：HF 下载一律先禁 xet；能用 **ModelScope**（阿里自家镜像，有 `Comfy-Org/*` 仓）或 **curl** 就优先。

### 🔴 3.2 短探测测不出长下载的病
**犯过**：curl 前 1 MB 2.1 秒通、前 40 MB 2.4 MB/s 通 —— 就判定「源是好的」，结果长下载在后段僵死。
> **规矩**：CDN 健康度必须用 **≥256 MB 连续下载并跑到底**来验证。前几 MB 通 ≠ 能用。

### ⚙️ 3.3 重启下载前先清 0 字节残骸
`*.lock` / `*.incomplete` / `*.part` 为 0 字节时，下载器会反复在那个坑里重启。
> **规矩**：重启前先扫并清掉 0 字节残骸。

### ⚙️ 3.4 进度指标撒谎（**犯过 3 次**）
- 第 1 次：`进 = (已下 + 本次)` 里 `本次` 每轮清零 → 显示的是「最近 20 秒增量」而非累计，看起来原地踏步。
- 第 2 次：`进度.读()` 只数正式分片，**不数 `.seg` 临时块** → 16 路全速跑时面板一直写 `0 B / 19.09 GB 0.00 MB/s`。
> **规矩**：任何进度必须报 **累计值**，且必须统计**所有写入位置（含临时文件）**。写完自问一句：这个数在「一切正常」时会动吗？

### ⚙️ 3.5 一轮 Range 要太多会被 CDN 掐断
`curl: (18) end of response with 1227594008 bytes missing` —— 单轮 1.19 GB 要不满。改成每轮 ≤256 MB 后稳定。
> **规矩**：分片下载单轮上限 256 MB，取完立刻要下一段。

### ⚙️ 3.6 ssh 不能当大下载的父进程
会话一断，子进程被带走。
> **规矩**：长任务用 **`schtasks`** 或 harness 的 managed background job，**不要**用 ssh 会话持有；`Start-Job` 在一次性 pwsh 调用里也会随父进程死掉。

### ⚙️ 3.7 `hf-mirror` 拉的 zip 可能静默残缺
**犯过**：从 `hf-mirror` 拉的 ComfyUI zip 少文件，解出来不能用。
> **规矩**：装包后必须校验**关键文件存在**（如 `main.py`），不能只看解压退出码。

## 四、模型与 ComfyUI

### 🔴 4.1 「在」不等于「对」
**犯过**：保险只查**文件存在性**，查出「缺 0 项」，于是拿**纯文生图**模型 `qwen_image_2512` 配 `TextEncodeQwenImageEditPlus` 的参考图槽 → 出**满屏黑白棋盘格**的废图。
> **规矩**：模型校验必须校验**语义**（模板里写死「名字须含 `edit`」这类约束），不能只查存在性。

### 🔴 4.2 「大小对上了」不等于「文件在那儿」
**犯过**：我靠推算判定 19 GB 的 Qwen-Edit 已在共享根，**实测不在**。
> **规矩**：文件在不在，**直接列目录确认**，不许靠推算。

### ⚙️ 4.3 模型下错目录 = 白下
**犯过**：往 `ComfyUI-Installs\ComfyUI\ComfyUI\models` 下，但 ComfyUI 实际读 **`D:\Comfy-Desktop\ComfyUI-Shared\models`**（Desktop 版重定向了）。custom_nodes 又各有自己的 `models_root`（如 IndexTTS 是三层上溯）。
> **规矩**：下模型前**先确认目标组件真实的模型根**（读 `extra_model_paths.yaml` / 读节点源码 / 实测 `/object_info`）。

### ⚙️ 4.4 拿纯文生图模型配编辑节点的参考图槽 = 出废图
编辑模型才训练过参考图隐变量。切换模板前必须校验模型齐备，缺就**降级退回文生图并明说**，绝不硬上。

## 五、远端 Windows

### ⚙️ 5.1 远端脚本必须是**纯 ASCII**
Windows PowerShell 5.1 在 zh-CN 机器上把**无 BOM 的 UTF-8 当 GBK 读** → 中文路径全乱码，**第一行就死**。

### ⚙️ 5.2 正在 `pip install` 的 venv 删不掉
`Remove-Item` 报 `[Errno 13] Permission denied: '.venv\Scripts\python.exe'`，留下一个有 `python.exe` 但**没有 pip** 的半尸 venv。
> **规矩**：先杀持有者 → `Start-Sleep 5` → 删 → **验证删掉了** → 再重建 → 检查 `pip.exe`，没有就 `ensurepip --upgrade`。

### ⚙️ 5.3 winget 在 SSH 会话里装不上任何东西
SSH 会话**没有提权**，装不进 `Program Files`。这不是毛病，是固有限制。
> **规矩**：远程装机不指望 winget —— 直接下 zip / 用绿色版。

### ⚙️ 5.4 zip 解出来可能多一层子目录
**犯过**：解出 `ComfyUI-master\` 子目录没提上来，两轮部署都去查错路径然后报「no main.py」。
> **规矩**：解压后先**列一层目录**再决定路径。

## 六、Python / 中文

### ⚙️ 6.1 中文模块名 `import` 可能失败
用 `_装模块()` 兜底（`__import__` 失败退 `spec_from_file_location`）。

### ⚙️ 6.2 `清空()` 走 `保存()`→`载入()` 会让旧数据复活
必须**直接原子写盘**（先写 `.tmp` 再 `os.replace`）。

### ⚙️ 6.3 翻译函数静默丢词
`角色库._译()` 翻不出只 `print` 报警 —— 必须**接成返回值**，否则丢词没人知道。译补表两侧**垫空格**，否则相邻中文短语会黏词（`紫色杏眼` → `purplealmond-shaped`）。

### ⚙️ 6.4 控制台是 cp936
不设 `PYTHONIOENCODING=utf-8` 会 `UnicodeEncodeError`。

## 七、协作与判断

### ⚙️ 7.1 「有别的进程在写」先怀疑自己人
**犯过**：代理报「另一个工位在抢写」并要求停手 —— 实际那个「抢写者」是**它自己的任务书对应的原作者 agent** 在收尾，时间戳连起来是一条完整动作链（备份 → 修 → 更新自测脚本 → 跑 → 出报告）。
> **规矩**：报冲突前先按时间戳把写入链拼起来；先查 `job_list` 和进程命令行，别先怀疑外部。

### ⚙️ 7.2 抽象/推测必须与实测分开写
文档里 **「实测」与「设计意图」分栏标**。挖不到就写「未挖到」，**不许编**。

### ⚙️ 7.3 失败分类要认得出「钱已经花出去」
`引擎.派工()` 超时抛 `RuntimeError("等了 N 秒还没跑完（提示号 …）")` —— 这正是「请求可能已送达供应商、但结果或计费状态无法确认」的现场。账本必须把它映射成 **`未知` 而不是 `失败`**，**绝不自动重试**。

### ⚙️ 7.4 实例级判定必须排在失败分类**之前**
**犯过**：`本机 ComfyUI 502` 被判成「退避后重试」→ **拿着已经废掉的机器死磕退避**。

### ⚙️ 7.5 换实例后必须换 taskId
账本 `重试()` 是**开新任务**，不是把旧账拨回「排队」。循环里继续用旧 id 会撞状态机。
