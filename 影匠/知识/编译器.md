### 三计数的语义（重要）

`通过/失败/没测` 统计的是**自测自己的断言**，不是被检查提示词的得分。

- `没测` = 这条规则**本轮跑不了**（入参缺字段，不猜、不假装通过）。
- 脏样例（故意写入 `no subtitles` / `分镜1 in the top-left corner` 的那组）在检查器里必然报失败，
  这是**预期结果**，已由 4 条断言逐条核对，**不计入**自测的 `失败`。
  否则自测永远 exit 1，等于没有退出码。

## 2. 接口

模块级门面对象 `编译`，另有同名模块级函数 `整体 / 单格 / 宫格 / 检查` 便于 `from 编译器 import 整体`。

### 2.1 `编译.整体(设定, 自定义预设=None) -> str`

同时认中文键（`角色/场景/道具/风格`）。返回一段换行分隔的中文清单。

**输出顺序（17 行位，逐行对齐产物）**

| # | 行 | 条件 |
| --- | --- | --- |
| 1 | `【角色一致性要求 - 所有画面中同一角色外观必须严格保持一致】` | `characters` 非空 |
| 2 | `- 名(#id)：描述` | 每个角色，**描述超 150 字截断加 `…`** |
| 3 | `【场景一致性要求】` | `scenes` 非空 |
| 4 | `- 名(#id)：描述` | 每个场景，`subType === "scene-view"` 的**跳过**；同样 150 字截断 |
| 5 | `【道具一致性要求】` | `props` 非空 |
| 6 | `- 名(#id)：描述` | 每个道具，150 字截断 |
| 7 | `【整体风格要求】` | 总是 |
| 8 | `- 画幅：<aspectRatio>` | 总是 |
| 9 | `- Render type: <label> — <keywords>` | renderType 存在且 **≠ `auto`** 且 keywords 非空 |
| 10 | `- 画质：<label> (<resolution>)` | 总是 |

### 2.2 `编译.单格(景别, 主体与动作, 环境, 时间光照, 风格标签, 排除词="", 描述="", 宫格=9, 限词=True) -> dict`

六段公式（三份 Gem 逐字一致）：`[景别] + [主体与动作] + [环境] + [时间/光照] + [风格标签] + [排除词]`

返回：

```python
{
  "description":  "中文，供分镜面板显示",
  "time_setting": "英文时间/光照短语，且必须出现在 prompt_text 里",
  "prompt_text":  "英文，逗号分隔关键词短语",
  "景别": ..., "景别中文": ..., "词数": ..., "描述字数": ...,
  "排除词": ..., "被剥离": [...], "警告": [...],
}
```

字数/词数带（按宫格分档）：

| 宫格 | `description` 字数 | `prompt_text` 词数 |
| --- | --- | --- |
| 9 | 30–50 | 20–30（C3：25±5） |
| 4 / 25 | 10–20 | 20–30（硬上限 40，H9） |

【分歧】任务书写「`description(中文 30-50 字)`」一刀切；三份 Gem 里 **C7 是按宫格分档的**
（九宫格 30-50 字，四宫格 / 25 宫格 10-20 字）。影匠按 Gem 分档。

限词策略（`限词=True`，顺序固定、每步都写进 `警告`，不静默）：
1. 超 30 词 → 按公式顺序丢掉 `[环境]` 段；
2. 仍超 30 词且 `[风格标签]` > 5 词 → 标签截到 5 词；
3. 仍超 40 词 → 触发 H9 硬上限，截到 40 词。

含中文的英文段一律**剔出** `prompt_text`（C4），并在 `警告` 里点名。
`description` 回落时中文之间不留空格、拉丁词之间保留空格。

### 2.3 `编译.宫格(数量, 主题, 主体英文="", 环境="", 时间光照="", 风格标签="", 排除词="", 分段描述=None, 分段英文=None, 分段环境=None, 分段时间=None) -> list`

| `节拍` / `节奏段` | 该格在板里的功能位 |
| `轮` | 第几轮（25 宫格用） |
| `景别要求` | 该板型的景别配额说明 |
| `板型` | `Beat Board 节拍板` / `Sequence Board 序列板` |

### 2.4 `编译.检查(提示词, 只要问题=False) -> list`

`提示词` 可以是 dict（`{"shots": [...]}` 或裸 list）或字符串。
返回 28 条，每条 `{"编号","级别","名称","结果","说明","位置"}`，`结果 ∈ {通过, 失败, 没测}`。
`只要问题=True` 时只回 `失败` + `没测`。

配套：`编译.摘要(结果列表) -> {"通过":n,"失败":n,"没测":n}`。

## 6. 检查器：28 条

【实测】规则集恰好是 `H1-H10 + C1-C8 + QC1-QC10`（自测里有断言锁死，多一条少一条都会红）。

**硬约束 H1-H10**：文字污染 / `A scene showing` 句式 / 空洞描述 / JSON 模式只出 JSON / 单一视觉焦点 /
≤3 个运动元素 / 风格标签须来自参考图 / `description` 字数上限 / `prompt_text` ≤40 词 / NSFW。

**约束 C1-C8**：标准 JSON 无废话 / shots 必须 4·9·25 / 每格约 25 词(±5) / 禁长难句 /
**C5 纯视觉原则** / **C6 去水印** / `description` 中文且简明 / `time_setting` 英文且融入 `prompt_text`。

**自检 QC1-QC10**：叙事连贯 / 景别多样性 / 节奏呼吸 / 角色一致 / 光影逻辑 / 情绪弧线 /
信息完整 / 风格统一 / 无废话 / 无文字污染。

### C5 / C6 是硬的

飞彩 `Gemini生图专用Gem.txt` 的 C5 逐字：

> 纯视觉原则：prompt_text 内严禁出现任何非画面内容的指令性文字，包括但不限于 'no timecode',
> 'no subtitles', '分镜X in corner', 'Shot X in top-left' 等。这些元指令会被图像模型渲染为画面中的可见文字。

【实测】`单格()` 会**先洗后拼**：任何一段（含排除词）里出现元指令，都被剥掉并记进 `被剥离`。
自测断言：喂 `no subtitles, no timecode` 后，`"no subtitles" not in prompt_text` 且 `被剥离` 长度 ≥ 2；
`检查()` 对同一样例报出 **C5 + C6 + H1 + QC10** 四条失败。

### 【分歧】飞彩自己前后两版打架

`210-5385ca9119171eec.js`（旧版 ShotAgent）明说：「固定添加末尾标签：`no timecode, no subtitles`」，
四宫格模板的 `en` 字段示例也带 `no timecode, no subtitles`；
而 `Gemini生图专用Gem.txt`（新版）的 C5/C6 **严禁**写这些。
**影匠按 C5/C6 执行**（任务书也这么要求），并在 `单格()` 里对旧写法做自动清洗。
另外飞彩 `extractActionDescription()` 自己的清洗正则里也有 `no timecode` / `no subtitles` / `no text` /
`no watermark` 四条，说明新版确实在往回洗——这是影匠这一刀的直接依据。
