# 任务账本 —— 持久化的活账，以及「未知」这条铁律

> 分析对象：`账本.py`（1809 行，零第三方依赖，只用 sqlite3 / json / os / time / hashlib）
> 一句话：**每一次外部调用都先落一条账**。这样进程被强杀、机器重启、供应商回包丢了，
> 你都能回答「这活到底跑没跑」，而不是凭记忆猜。
>
> 本文与 `知识/模型接入层.md`、`知识/审片清单.md` 是配套的：接入层管「调谁」，
> 账本管「调过没有、算不算钱」。

---

## 1. 它解决的是什么问题

影匠的活分两种，代价差三个数量级：

| 活 | 一次多久 | 失败重来的代价 |
|---|---|---|
| 出图（zimage_turbo，8 步 1024²） | 几秒 | 几乎为零，重来就重来 |
| 出片（wan22_i2v，49 帧） | 几分钟 | 几分钟机时 + 一次电费；接了云端就是真钱 |
| 配音 | 十几秒 | 小 |

「重来就重来」在第一种活上是对的，在第二种活上是**错的**。而 `剧组.py` 现在的循环
（`命令_出图` / `命令_出片`）是不知道区别的：它 `try` 一次，`except` 就把这条记成
`失败` 写进 `_渲染日志.tsv`，然后接着下一条。日志只记了「失败了」，没记
**「活有没有交出去」**。

`账本.py` 补的就是这一格。

## 2. 状态机

```
                    ┌──────────────────────────────────────────────┐
                    │                                              │
                    ▼                                              │
              ┌──────────┐                                         │
     新建 ───▶│   排队   │──────────────── 取消 ──────┐              │
              └────┬─────┘                          │              │
                   │ 领取()  ← 并发闸门在这里（默认上限 1）         │
                   │        （闸门满 → 抛 闸门满，留在排队）        │
                   ▼                                │              │
              ┌──────────┐                          ▼              │
              │   运行   │────────────────────▶ ┌────────┐         │
              └────┬─────┘        取消          │  取消  │         │
                   │                            └────────┘         │
        ┌──────────┼──────────┬───────────────┐   （终态）         │
        │          │          │               │                    │
   完成()│     失败()│    未知()│               │                    │
        ▼          ▼          ▼               │                    │
   ┌────────┐ ┌────────┐ ┌──────────┐         │                    │
   │  完成  │ │  失败  │ │   未知   │         │                    │
   └────────┘ └───┬────┘ └────┬─────┘         │                    │
    （终态）      │           │                                   │
                  │           │  ★ 没有任何自动迁移               │
                  │           │    （_迁移表[未知] == ()）         │
                  │           ▼                                   │
                  │      ┌──────────────────────┐                 │
                  │      │  人工核对（人去看）  │                 │
                  │      └──────────┬───────────┘                 │
                  │                 │ 恢复()                       │
                  └──── 恢复() ─────┴─────────────────────────────┘
                        │
                        └──▶ 回「排队」，重新过闸门（领取()）
```

**两个终态表上的细节值得单独说：**

1. **`未知` 是终态**（`终态 = (完成, 失败, 未知, 取消)`），而 `接口/契约.py` 里
   `终态全集 = (完成, 失败)`。两个模块的措辞**故意不一样，而且不冲突**：
   - `契约.py` 说的是「未知不是**收工**」—— 对，它要你去查。
   - `账本.py` 说的是「未知没有任何**自动迁移**」—— 也对，查完只能走人工的 `恢复()`。
   - 合起来的语义是：**未知 = 冻结**。它不会被任何代码路径改掉，只能被人改掉。
     所以 `未知 not in _迁移表[未知]` 是硬断言，写在 `自查()` 里。

2. **`失败 → 运行` 是合法迁移**，靠 `恢复()` 走。这条看着像退步，其实是必要的：
   一条明确失败的活，人确认之后要能用**同一条账**接着跑（保留尝试次数与重试链），
   而不是每恢复一次就多一条新账。

### 字段

| 字段 | 说明 |
|---|---|
| `id` | `t` + 13 位 hex，全局唯一 |
| `类型` | 出图 / 出图四宫格 / 出片 / 配音 / 拼图 / 其他 |
| `戏名` / `镜头` / `格号` | 指回剧组的分镜结构 |
| `状态` | 排队 / 运行 / 完成 / 失败 / 未知 / 取消 |
| `尝试次数` | `领取()` 时 +1（**不是**建账时） |
| `创建时间` / `开始时间` / `结束时间` / `用时` | 用时 = 结束 − 开始（秒，两位小数） |
| `估算成本` / `实际成本` | 内部积分单位（见 §6） |
| `可能已计费` | int 0/1。**这条铁律的开关** |
| `输入摘要` | 16 位 hex 短指纹（`hashlib.sha256` 前 16 位），用来判「同样的活是不是跑过」 |
| `输出路径` | 产物落盘位置 |
| `错误` | 出错原文（截 2000 字） |
| `重试链` / `重试自` | 父任务 id ↔ 子任务 id，重试开的是**新账**不是改旧账 |
| `供应商任务号` | 如 ComfyUI 的 `prompt_id`。**人工核对时最有用的一列** |
| `备注` | 人工留话（`恢复()` 会自动盖一个时间戳） |

## 3. ★ 为什么「未知」不能自动重试

这是整个模块存在的理由，单独一节写清楚。

### 3.1 三个不能自动重试的场景，长得很像「可以重试」

| 现场 | 直觉反应 | 真相 |
|---|---|---|
| `引擎.派工()` 轮询超时：`RuntimeError("等了 1800 秒还没跑完（提示号 ab12cd34）")` | 「没跑完，重来一次」 | **没跑完 ≠ 没跑**。`prompt_id` 已经在 ComfyUI 的队列里了，重来就是再占一次卡、再跑一遍 5 分钟 |
| 接云端后：连接被重置 / 502 / 503 | 「网络抖了，重试」 | 请求**可能已经送达**。云端按次计费的话，这一下可能已经扣钱 |
| 轮询返回一个不认识的 id | 「id 不对，重新提交」 | 那个 id 可能是上一轮的活，也可能是别人的。重新提交等于放弃追踪它 |

这三个的共同点：**「我不知道它成没成」被压缩成了「它没成」**。压缩之后就一定会重试，
而重试在这里不是「再试一次」，是「再花一次」。

### 3.2 所以规则是

```
一个外部调用可能已经送达，但结果或计费状态无法确认
        ↓
   必须停在「未知」态
        ↓
   绝不自动重试（重试() 抛 需人工核对）
        ↓
   人去查（ComfyUI 的 queue / history；云端后台的用量页）
        ↓
   查完了，人做决定：恢复() / 完成() / 就算了
```

`重试()` 撞上未知态时抛的 `需人工核对` 异常，消息里必须有三段人话
（`【去哪查】` `【查什么】` `【怎么办】`），并带上 id / 活是什么 /
可能已计费 / 供应商任务号 / 当时的原因 / 输出路径。实测原文（节选）：

```
✗ 不能自动重试：这条任务处于「未知」态 —— 可能已经送达供应商，
  可能已经计费。自动重试会在你不知情的情况下再花一次钱/再跑一遍。

  任务     teb4a14d65589cc
  活       出图 · 《探查戏》 · 格号 1
  可能已计费 是（不过「否」只是没证据，不代表没送达）
  供应商任务号 prompt-cli-1  ← 拿这个号去查最快
  当时的原因 供应商 1800s 无响应，提示号 xy99

  【去哪查】ComfyUI（本机 5080 上的 http://127.0.0.1:8188，没有外部供应商计费） 后台 / 队列 / 历史记录
  【查什么】这个任务到底跑没跑完、出没出片、算没算钱；有输出路径就直接看文件
  【怎么办】没跑 → python 账本.py 恢复 <id> 接着跑
           跑过了 → python 账本.py 完成 <id> --输出 <路径> 把账结掉
           确认白花了 → 人工决定后 python 账本.py 恢复 <id> 再重跑
```

### 3.3 「未知」不是万能挡箭牌：明确失败要敢判

铁律的反面是**不能把所有错都塞进未知**，否则账本会变成一个只会喊「你自己看」的废物。
所以 `_类别表` 是唯一的事实来源，一行一个类别，三个输出（能不能重试 / 要不要退避 / 是不是存疑）
都从同一行的 `动作` 字段派生，保证它们**不可能互相矛盾**：

| 类别 | 认得出的字样 | 动作 | 为什么 |
|---|---|---|---|
| 服务没起 | 连不上 / `URLError` / `ConnectionRefused` | **停** | TCP 都没建起来，请求到不了对面 —— 不可能被计费，**快速失败**并提示去开 ComfyUI |
| 鉴权/权限 | 401 / 403 | 停 | 重试一百遍也一样 |
| 请求格式/参数 | 400 / 404 / 422 | 停 | 是我们自己写错了 |
| 本地错误 | 文件不存在 / 磁盘满 / 显存不够 | 停 | 与供应商无关 |
| 对端宕机/限流 | 502 / 503 / 504 / 429 | **退避后重试**，且标 `存疑` | 可以重试，但 503/504 可能已经半跑完 —— 注释里写明：贵活（出片）宁可走未知 |
| 超时 | timeout / 超时 / 无响应 | **未知** | 最典型的「说不清」 |
| 中止/断链 | 连接被重置 / 连接中断 | **未知** | 同上 |
| 引擎报错 | 工作流跑挂了 / 拒绝了这个工作流 / 跑完了但没有输出 / `ComfyUI 返回 5xx` | 退避后重试 | 有明确回包、明确没成 |
| （认不出） | 任何其它文本 | **未知** | 默认取最保守的一档 |

退避是指数加长、封顶 30 秒（宕机/限流类封顶 60 秒），并且**不封顶尝试次数** ——
由人看着决定什么时候收手，代码不替人做这个判断。

### 3.4 「抖动」与「服务真没起」为什么要分开

- **抖动**：连续失败，但每一次都是**明确的**失败（有回包、回包说没成）。
  → 可以退避重试。每次多等一点，别把对面打崩。
- **服务真没起**：连不上。请求**从来没到过**对面，所以：
  1. 不可能被计费；
  2. 重试一百遍也一样，只会白等；
  → **快速失败**，并把「先去看 ComfyUI 开没开」这句话直接给到人。
  `剧组.py` 现在自己有一条 `连败 >= 3` 的土办法（`错("连续 3 格失败 —— 多半是 ComfyUI 没开。先停，跑 \`python 引擎.py 体检\` 看看。")`），
  账本把这条经验收进了分类器：**第一次连不上就该快速失败**，不用等三格。

### 3.5 「未知」的现场与处置：`提交未知` → `对账` → `重试`

「未知」原来只是**一个状态**：账本能记、能拦、能提醒，但**没有任何东西会真的走进去** ——
分类器认的是「超时 / 断链」这些字样，而 `引擎.py` 在那两种场合抛的是裸
`RuntimeError("等了 N 秒还没跑完（提示号 …）")`：一没有提示号、二没有「可能已计费」，
调用方只能拿字符串去猜。**这条链现在通了，而且真跑过**：
证据在 `作品/账本自测/未知态端到端.txt`（假对端造语义）和
`作品/账本自测/未知态端到端_真ComfyUI.txt`（真 ComfyUI：账本 2.4 秒放弃、「未知」落账，
而那条活 8 秒后才在真 ComfyUI 上 success，产物 2 MB —— 随后被 `对账 成了` 结掉）。

#### 现场：`引擎.提交未知`（定义在 `引擎.py`）

```python
try:
    r = 引擎.派工(wf)
except 引擎.提交未知 as e:          # ← 只有这一种异常代表「钱可能已经花出去」
    账本.未知因为(任务id, e)        # ← 一行落账，提示号/可能已计费 自动带进去
```

它**只在提示号已经拿到之后**才抛，两种现场：

| 现场 | 抛点 | 为什么是「未知」而不是「失败」 |
|---|---|---|
| 轮询等超时 | `派工()` 里 `time.time()-起 > 上限秒` | 活还在对面跑，可能已经跑完、已经计费 |
| 提交后轮询断链 | 等结果时 `_请求()` 抛出的任何异常 | 提交**已经成功**，是之后才跟丢的 |

它自带账本要的属性：`.提示号` / `.已等秒` / `.可能已计费 = True` / `.供应商任务号` / `.供应商` / `.详情`，
消息里直接印出【去哪查】【查什么】【怎么办】。仍继承 `RuntimeError`，
所以老代码 `except RuntimeError` 照样接得住，不会漏。

**为什么必须靠异常对象、不能靠错误文本** —— 实测里同一个事件，两种读法结论相反：

| 读法 | 类别 | 动作 | 后果 |
|---|---|---|---|
| `分类异常(异常对象)` | 提交后失联（钱可能已经花出去） | **未知** | 停下交人工 |
| `分类异常(内层错误文本)`：`连不上 ComfyUI：目标计算机积极拒绝` | 服务没起（连不上） | **停** | 当明确失败 → 自动重跑 → **可能再花一次钱** |

一件事，一个说「交人」、一个说「重跑」。这就是「说不清」必须由异常对象带出来、
不能靠字符串猜的原因。**推论（容易写错的地方）**：接入时不要写
`if 分类异常(str(e))["动作"] == "未知": 记未知(...)` —— 提交后断链的 `str(e)` 会被判成「服务没起」。
一律用 `未知因为(任务id, e)`，把异常对象本身交进去。

#### 处置：`对账` 是「未知」唯一的出口

`_迁移表` 不许「未知」自动迁移，`对账()` 是**唯一**的人工作业出口：

```
python 账本.py 待人工                                  # 列出所有等核对的账
python 账本.py 对账                                    # 同上 + 逐条打印核对指引
python 账本.py 对账 <id>                               # 只看这一条的指引，不动状态
python 账本.py 对账 <id> --结果 成了 --产物 <路径> [--实际成本 N]
python 账本.py 对账 <id> --结果 没成 [--备注 "..."]
```

- `--结果 没成` → 状态=失败、**清 `可能已计费`**，并留下「人工核对过、没花钱」的流水；
  此后 `可重试()` 才放行（人真去后台看过了，这比机器的文本分类可信）。
- `--结果 成了` → 状态=完成、产物记进 `输出路径`、**清 `可能已计费`**
  （猜测作废：它确实跑成了，钱记进 `实际成本`）。
  没给 `--产物` 且账上也没有输出路径 → 直接拒绝：结到「完成」的账必须能按路径找到那条片。
- 对账的判据写在 **`事件` 表**（`事件='对账'`，只增不改的流水），**不写在 `备注` 里** ——
  备注是给人看的自由文本，拿它当开关，谁手滑改一个字就能把铁律绕过去。
- **没对过账的「未知」账，`重试()` 一律抛 `需人工核对`（退出码 3）。**

## 4. 数据安全：怎么保证「被强杀也不留半截」

| 机制 | 做法 | 防的是什么 |
|---|---|---|
| 事务 | 每次写都是 `BEGIN IMMEDIATE` … `COMMIT`，出错 `ROLLBACK` | 半截行 |
| WAL + FULL | `journal_mode=WAL`、`synchronous=FULL` | 掉电丢已提交的账 |
| 先设超时再开 WAL | `PRAGMA busy_timeout=15000` 必须在 `journal_mode=WAL` **之前** | 见 §4.1 |
| 原子快照 | 用 `Connection.backup()` 写 `.tmp`，再 `os.replace` 到 `.bak` | 抬快照抬到一半被杀 |
| 自愈 | 开库先 `PRAGMA integrity_check`；坏了就把主库改名成 `.坏.<时间戳>` 留证据，再用 `.bak` 顶上，全程往 stderr 吼 | 坏库静默变成空库 |
| 跨进程锁 | `.lck` 文件锁（`O_CREAT\|O_EXCL`），里面写 pid + 时间戳 | 两个进程同时写 |

### 4.1 一个实测踩出来的坑：WAL 会锁库，而 busy_timeout 还没设

最早的 `_连()` 是三行顺着的：

```python
db.execute("PRAGMA journal_mode=WAL")   # ← 这是写事务，会真锁库
db.execute("PRAGMA synchronous=FULL")
db.execute("PRAGMA busy_timeout=15000") # ← 设得太晚
```

`journal_mode=WAL` 不是「WAL→WAL」的空操作，它需要一个短暂的独占窗口。
多个进程同时开库时，谁没抢到就抛 `sqlite3.OperationalError: database is locked` ——
而这时候 `busy_timeout` 还是默认的 0，**立刻死**，死在 `账本.__init__()` 里。
更糟的是它当时还攥着 `.lck`，别人要干等 20 秒才报「账本被另一个进程锁着」，整条产线卡死。

现在的顺序是：**先 `busy_timeout=15000`，再带重试地开 WAL（最多 10 秒）**；
抢不到就降级用默认 journal_mode，并往 stderr 记一条警告 —— 宁可慢一点，不能卡死。

### 4.2 `.lck` 的接管规则（实测过四条）

| 情况 | 行为 | 理由 |
|---|---|---|
| 锁文件里的 pid 已经不存在 | **立刻接管**（实测 0.02 秒），往 stderr 说明理由 | 死锁不该卡人 |
| 锁文件里的 pid 是我自己 | 接管 | 同一进程不可能同时跑两个写操作，只可能是上次没删干净 |
| 锁文件里的 pid 还活着 | **不抢**，等到 `影匠_锁等秒`（默认 90 秒）后报错退出 | 宁可报错，也不把别人正在跑的写操作劈成两半 |
| 只读操作（列表/统计/未完成…） | **根本不走锁** | 在 WAL 下读到的是最后一个已提交状态，没有任何东西会被劈成两半；为了查一眼账去跟一条几分钟的出片抢锁毫无意义 |

（`影匠_锁等秒` 可调：出片一条要几分钟，等待窗口短了会误报。）

## 5. 断点恢复

- `未完成(戏名=None)` → 只返回**排队 + 运行**的账。这是断点表。
- `待人工(戏名=None)` → 返回**未知**的账。这是人工队列，**不是**断点表。
  两个必须分开：未知账混进断点表，就会被「把剩下的跑完」这种脚本顺手重跑一遍。
- `恢复(id)` → 打回**排队**，并清掉 `可能已计费`。
- **`恢复()` 只到「排队」为止，不会把你偷偷塞进「运行」**：接着跑要重新 `领取()` 过闸门
  （否则恢复一次就绕过一次并发闸门，本机一张卡会同时被两个活撕）。

`未完成` 命令的输出分两段，实测长这样：

```
（没有匹配的账）

★ 另有 1 条卡在「未知」态（可能已计费，等人工核对）：
id                类型   戏名    格号  状态  试  用时   创建
teb4a14d65589cc   出图   探查戏   1    未知   1   0.52  2026-10-14 01:21:22
```

## 6. 成本预告：估算还是实测，必须写在脸上

`预估(类型, 数量, 参数)` 返回 `积分 / 秒 / 金额 / 依据 / 说明 / 分项`，其中
**`依据` 只有四种取值**，且 `说明` 里必须写明算法与样本数：

| `依据` | 什么时候出现 | 数据来源 |
|---|---|---|
| `实测均值` | 同类已完成任务 ≥ 5 条 | 自己的账：`COUNT(*)` + `AVG(用时)` |
| `实测均值（样本少）` | 1 ≤ 样本 < 5 | 同上，但如实说样本少 |
| `基线估算` | 样本 = 0 | `计价表` 里的本机基线（写在源码里，标了「本机实测基线」） |
| `设计意图估算` | 类型不在 `计价表` 里 | 兜底的 5 秒/件 —— 明说这是拍的，不是量的 |

`计价表` 的积分单位是**账本自己的内部单位**，不是供应商报价：
`1 积分 ≈ 一枚 5080 跑 1 张 8 步 1024² 图的电费与机时`。
金额按 `整机瓦数（默认 600 W，可用 影匠_整机瓦数 覆盖）× 小时 × 电价（默认 0.56 元/度，可用 影匠_电价 覆盖）` 折算。

实测一条：

```
出片 × 2段：约 120.0 积分 / 520.0 秒墙钟 / 约 0.0485 元电费（600W × 0.14h × 0.56 元/度）。
来源：基线估算。账本里还没有「出片」的实测样本，用本机基线 260.0 秒/件 × 基线 60 积分/件。
```

有云端报价时用 `供应商报价=` 传进来，它会走真钱那条线，不再拿电费糊弄。

## 7. 命令行

```
python 账本.py 列表 [--状态 X] [--戏名 Y] [--类型 T] [--限 N] [--只未结算]
python 账本.py 新建 --类型 出图 [--戏名 Y] [--镜头 A] [--格号 1] [--估算成本 1] [--输入摘要 …]
python 账本.py 领取 <id>                      # 过并发闸门：排队 → 运行（尝试次数 +1）
python 账本.py 开始 <id> [--供应商任务号 P]    # 补登单号，状态不动；排队的账会被挡住
python 账本.py 完成 <id> [--输出 路径] [--实际成本 N]
python 账本.py 失败 <id> --错 "..."            # 明确失败（不确定成没成 → 用 未知）
python 账本.py 未知 <id> --因 "..." [--供应商任务号 P] [--不可能已计费]
python 账本.py 对账 [<id>] [--结果 成了 --产物 <路径> [--实际成本 N] | --结果 没成] [--备注 "..."]
python 账本.py 待人工 [--戏名 Y]                # 卡在「未知」态、等人工核对的账
python 账本.py 取消 <id> [--因 "..."]
python 账本.py 重试 <id> [--强开]              # 未知/可能已计费 → 拒绝，退出码 3
python 账本.py 恢复 <id> [--备注 "..."]        # 人工核对后：打回排队、清可能已计费
python 账本.py 未完成 [--戏名 Y]               # 断点表（排队+运行），另附未知提醒
python 账本.py 统计 [--戏名 Y]
python 账本.py 预估 <类型> <数量> [--模板 T] [--宽 W] [--高 H] [--帧数 F] [--步数 S]
python 账本.py 闸门 [--上限 N]
python 账本.py 自查                            # 36 项隔离自检
```

**退出码约定：**

| 码 | 含义 | 脚本该怎么处理 |
|---|---|---|
| 0 | 成功 | 继续 |
| 1 | 只有 `自查` 会返回：**自检有不过项** | 当成「账本本体坏了」，别继续跑活 |
| 2 | 用法/账本错误（含 `状态非法`、`找不到任务`） | 改命令或者改环境，重跑同一句是安全的 |
| **3** | **被铁律拒绝**：未知态或可能已计费的活不能自动重试 | **必须与 2 分开**：这不是命令写错了，是**钱的问题**，得有人去看供应商后台 |

`对账` 自己的码：没查就结（`--结果` 缺失或写了别的）→ 2；说「成了」没给 `--产物` → 2；
非「未知」态的账拿去对账 → 2；正常结掉 → 0。

常用旗标：`--库 <路径>` 换一个账本文件（默认 `作品/_账本/账本.db`，也可用环境变量 `影匠_账本`）。
**`--库` 放哪都行**（`账本.py 对账 --库 X <id>` 和 `账本.py 对账 <id> --库 X` 等价）——
位置参数是按「哪些选项会吃掉下一个值」算出来的，不会把库路径当成 id。

## 8. 接入方案（**产线接入还没做**；`引擎.py` 那一半已经做了）

> **2026-10-14 状态**：这一节原来写着「本文档不改任何现有文件」—— 已经不是事实了。
> `引擎.py` 已经改过：`派工()` 的超时/提交后失联现在抛 `提交未知`（见 §3.5），
> `账本.py` 新增了 `对账` 命令和 `未知因为()`。**但下面这三处「产线接入」一处都还没做**：
> `剧组.py` / `导演.py` 目前不调账本，账本现在只被 `面板.py`（命令行方式）用着。
> 所以「真出一个未知账」的演示是靠假对端做的，不是靠产线做的。

三处接入点，按「改动面从小到大」排。

### 8.1 接入点 A：`导演.开镜()` / `导演.让镜动()` 包一层账（推荐先做这个）

`导演.py` 是出图/出片的**唯一**出口，包住它就等于包住了整条产线，而 `剧组.py` 一行不用改。

```python
# 伪代码：建议放在 剧组.py 里（或单独一个 记账工.py），不去动 导演.py 的签名
import 账本, 引擎

def 记账开镜(戏名, 格号, 情节, **kw):
    r = 账本.预估("出图", 1, 宽=kw.get("宽", 1024), 高=kw.get("高", 1024))
    tid = 账本.新建("出图", 戏名=戏名, 格号=格号, 估算成本=r["积分"],
                    输入={"情节": 情节, **{k: v for k, v in kw.items() if k != "报"}})
    账本.领取(tid)                      # 过闸门；满了就在这里排队等
    try:
        果 = 导演.开镜(情节, **kw)       # ← 原调用，一字不改
    except 引擎.提交未知 as e:           # ← 钱可能已经花出去：唯一的「未知」入口
        账本.未知因为(tid, e)
        raise
    except Exception as e:
        v = 账本.分类异常(e)             # ← 传异常对象，不是 str(e)
        if v["动作"] == "未知":
            账本.未知因为(tid, e)
        else:
            账本.记失败(tid, 错=str(e)[:500])
        raise
    账本.记完成(tid, 输出路径=果.get("路", ""), 实际成本=r["积分"])
    return 果
```

**`except Exception` 里为什么也传对象**：`账本.分类异常(e)` 会**先看异常自带的属性**
（`可能已计费` / `供应商任务号` / `提示号`），再看文案；写成 `分类异常(str(e))` 就把这层信息丢了 ——
实测里同一个「提交后失联」，传对象得「未知」、传内层文本得「停（明确失败）」，后者会被自动重跑。
**接入时别写 `if 分类异常(str(e))["动作"] == "未知"`**。

**关于 `引擎.派工()` 的超时（这一条已经落地了）**：`引擎.py` 现在超时会抛
`提交未知`（带 `.提示号` / `.已等秒` / `.可能已计费=True`），`账本.py` 的分类器认这个对象、
落「未知」态。原来文中列的两条「二选一」办法（改 `引擎.py`，或往类别表里塞「等了 N 秒」的正则）
**已经按第一种做掉了**，不需要再做一遍。

### 8.2 接入点 B：`剧组.命令_出图/命令_出片` 的循环

现在循环里是 `try/except` + `记日志(目录,"出图",f"01_格{g['号']}",秒,"失败",str(e)[:80])`。
接入方式是**先落账、再写日志**：

| 现在 | 接入后 |
|---|---|
| `连败 += 1`，到 3 就 `break` 并提示去体检 | 先问 `账本.分类异常(e)`（**传对象，别 `str(e)`**）：`动作 == "停"` 才累加连败；`动作 == "退避后重试"` 就 `time.sleep(建议(错, 连败)["等待秒"])` 后重试 |
| 日志只有「失败」两个字 | 日志照旧写，但账本里多了「活交出去没有」「供应商任务号」「估算/实际成本」 |
| `命令_全部` 里的 `门()` 阶段门 | `门()` 之前加一道：`账本.待人工()` 非空就**不许往下走**（未知账没核完就开下一阶段，等于让未知账流失在流水线里） |

**`命令_全部` 的正确接法**：进循环前 `账本.未完成(戏名)` 拿断点，跳过已完成的格
（现在靠 `重做=False` + 文件存在与否来判断，不如账本精确：文件在但账没结，说明上次
写到一半；账结了但文件不在，说明产物被删了 —— 这两种现在都看不出来）。

### 8.3 接入点 C：`接口/契约.py` 的适配器层（云端真花钱时必做）

接入层已经有 `走一遍()` 这个演练器，它内部是「提交 → 拿 id → 轮询」三段拆开的，
正是账本要的形状。接法：

```
注册表.要("图生视频")
   ↓ 契约.走一遍(适配器, 请求)
   ├─ 提交阶段失败（拿到明确回包说没成） → 账本.记失败()
   ├─ 提交成功但拿不到 id / 轮询超时     → 账本.记未知()   ← 契约.归一() 已经会判「未知」
   └─ 轮询到终态                        → 账本.记完成() / 记失败()
```

**两个模块的状态名完全一致**（排队/运行/完成/失败/未知是同一套字面量），
所以 `契约.归一()` 的结果可以直接喂给账本的 `记失败/记未知`，不需要映射表。
唯一要守的一条：**重试与否由账本说了算**。适配器层可以建议「这个错看起来可以重试」，
但只要账本那边 `可能已计费` 是开的或状态是未知，账本就会拒绝并抛 `需人工核对` ——
这个否决权必须留在账本手里，因为只有账本知道「上一次到底交出去没有」。

### 8.4 接入顺序建议

1. **A**（包 `导演`）+ 只认「本地 ComfyUI」这一个供应商 —— 本机跑，没有真钱，风险最低，收益最大（出片不再瞎重试）。
2. **B**（`剧组` 循环 + 阶段门）—— 让 `命令_全部` 会在有未知账时停下来。
3. **C**（适配器层）—— 等真的接了云端付费供应商再做，那时候 `可能已计费` 才真的在保护钱。

## 9. 这个模块**不能自证**的东西

写清楚，免得把「测过了」当成「不会错」。

| # | 自证不了的事 | 为什么 | 怎么办 |
|---|---|---|---|
| 1 | **没在「真杀掉进程 / 真拔网线」的现场验过** | 端到端那条链是拿一个假 ComfyUI（本机 127.0.0.1 上的 stub）跑出来的：真提交、真提示号、真产物、真超时都测了，但「把真的 ComfyUI 杀了」「把网线拔了」没做 | 真接上之后的**第一个真实线上未知态必须人工核一次**，并把当时的错误原文补进 `_类别表` |
| 2 | 分类器对**除 `提交未知` 之外**的异常只认**文案** | `提交未知` 是按**对象**认的（属性优先，见 §3.5），其它异常仍靠字符串匹配。供应商换一种错误文案，分类就可能掉档 | 接入后拿真实异常喂一遍 `分类异常()` —— **传对象，别传 `str(e)`** —— 把对不上的补进表里 |
| 3 | **`os.replace` 那一瞬间被杀** | 需要精确到系统调用的注入钩子，本项目没有 | 只验了「每次正常收尾后无 `.tmp` 残留」；真出问题，`.bak` 是上一个完整版本，人工可回 |
| 4 | **掉电 = 数据库坏** | 强杀测试杀的是进程，不是电 | WAL + `synchronous=FULL` 是设计上对付它的，但**没实测**；本机没有 UPS |
| 5 | **跨进程闸门只压了 4 进程** | 没做几十进程的压测 | 产线实际并发就是 1~2 个进程，先按这个规模用 |
| 6 | 没测过跨机器（网络盘上的账本） | `.lck` 是本地文件锁，NFS/SMB 上的 `O_EXCL` 语义不保证 | **别把账本放在网络盘上** |
| 7 | 「可能已计费」只是**证据不足时的默认值** | 代码没法知道对面到底扣没扣钱 | 它的 `false` 只代表「没有证据表明送达」，**不代表没送达**。异常消息里明写了这句 |
| 8 | 时间/成本是**本机时钟与本机电价** | `time.time()`、瓦数、电价都是本机设定 | 换机器要重估基线；云端报价必须走 `供应商报价=` |
| 9 | **产线还没接账本** | `剧组.py` / `导演.py` 目前不调账本，账本只被 `面板.py` 以命令行方式用着。端到端实测是 `_复核/未知态端到端.py` 直调「引擎 + 账本」，不是一次真实出片 | 按 §8 接 A → B → C；接上之前，「未知」态由引擎那条链产生，不是由产线产生 |
