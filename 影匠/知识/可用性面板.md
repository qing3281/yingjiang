## 1. 它要回答什么问题

影匠原来最难受的不是「手艺不行」，是**算出来的东西没有出口**：

| 原来的痛点 | 面板给谁看 | 对应分区 |
|---|---|---|
| 跑一个命令要等 30 秒才知道结果，中间不知道在干嘛 | 引擎 / 在跑什么 | ① ③ |
| 中断了不知道哪些格子没跑完、能不能接着跑 | 断点（附「接着跑」的具体命令） | ⑤ |
| 不知道现在有没有别的活在跑（本机只有一张 5080，一次只能跑一个） | 在跑什么（账本闸门占用） | ③ |
| 不知道下一步要花多少时间 / 显存 | 钱和时间（积分 / 秒 / 电费 / 依据） | ⑥ |
| 不知道 ComfyUI 是不是还活着、关键模型下齐了没有 | 引擎 / 模型（含「下到一半」） | ① ② |

面板自己给自己定的四条设计原则（写在 `面板.py` 文件头）：

1. **一个数据源挂了不许拖垮整个面板**：每个分区单独 try/except，挂了就在那一行写
   `问不到：<原因>`，别的分区照常显示。
2. **拿不到就写「问不到」，绝不填假数字。**
3. **不碰重活**：只做轻量 HTTP 查询，不调 `文生图` / `让镜动` 之类的真跑活。
4. **只读，绝不写盘。**

## 2. 怎么用

```
python 面板.py              等价于 看
python 面板.py 看           打一次快照
python 面板.py 盯           每 3 秒刷新（Ctrl+C 退），屏幕清空重画
python 面板.py 看 --json    输出 JSON（给别的程序吃）
python 面板.py 看 --战情    只打「需要你动手的」那几行（待人工/失败/卡住）
python 面板.py 盯 --每 1    盯模式改成 1 秒一轮
```

跑的时候记得把编码钉死（否则 Windows 控制台会把中文和 ✓ 打成一团乱码）：

```powershell
$env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'
D:\Comfy-Desktop\ComfyUI-Installs\ComfyUI\ComfyUI\.venv\Scripts\python.exe -X utf8 面板.py 看
```

**退出码**（给脚本 / 定时任务吃）：

| 码 | 含义 | 什么时候 |
|---|---|---|
| `0` | 一切正常 | 没有要人管的事，也没有数据源问不到 |
| `2` | 有数据源问不到 | 某个分区自己抛了异常，那一行写了「问不到」 |
| `3` | 有「要人管的事」 | 未知态 / 失败 / 卡住的排队 —— **优先级比 2 高** |

`--战情 --json` 只吐「要人管的事 + 断点」两份精简 JSON，给闹钟 / 托盘程序吃。

零第三方依赖：只用 `os sys json time shutil glob argparse` + `importlib.util`（中文模块名兜底）。

## 3. 每个分区读哪个数据源

| # | 分区 | 数据源 | 具体接口 | 实测/设计 |
|---|---|---|---|---|
| ① | 引擎 | `引擎.py` | `引擎.在线()`、`引擎._请求("/queue", 超时=8)` | **【实测】** 谁被调过已用运行时装桩查过（见 §5） |
| ② | 模型 | 两个模型根 + `引擎.py` | `os.walk` 两个根；`引擎.有模型(名)` 问 ComfyUI 认不认 | **【实测】** |
| ③ | 在跑什么 | `账本.py` | `账本.闸门()`、`账本.列表(状态="运行")`、`账本.列表(状态="排队")` | **【实测】** |
| ④ | 要人管的事 | `账本.py` | `账本.待人工()`、`账本.列表(状态="失败")`、`账本.列表(状态="排队")` 里超时的 | **【实测】** |
| ⑤ | 断点 | `账本.py` + 作品目录 | `账本.未完成()`；再 glob 每部戏的产物文件推「该接着跑哪条命令」 | **【实测】** |
| ⑥ | 钱和时间 | `账本.py` | `账本.统计()`、`账本.预估(类型, 数量)` | **【实测】** |
| ⑦ | 每部戏的进度 | 文件系统 | 扫 `作品\<戏名>\` 的产物文件（不去 import 审片.py，见 §7） | **【实测】** |
| ⑧ | 磁盘 | 文件系统 | `shutil.disk_usage` 打 C:/D:/E: | **【实测】** |

### ① 引擎 —— 只打两个读接口

- `引擎.在线()` 问 `/system_stats`，回在线吗、版本、显卡、显存。这个函数自己吞异常，
  所以「ComfyUI 没开」是**正常返回值**，不是异常。
- 队列条数 `/queue` **不是 `引擎.py` 的公开函数**，面板借它的 `_请求()` 打
  （同一条口径、同一个超时 8 秒），只取 `queue_running` / `queue_pending` 的长度，
  顺手把正在跑的第一个节点的 `class_type` 抠出来当「正在跑什么」。
- **绝不提交工作流**。`文生图`、`让镜动` 这类重活一个都不碰。

ComfyUI 没开的时候，面板写的是人话，不是堆栈：

```
▶ 引擎
  ✗ ComfyUI 没开 —— 连不上 ComfyUI（http://127.0.0.1:59999）：[WinError 10061] 由于目标计算机积极拒…
    地址 http://127.0.0.1:59999（改地址：设环境变量 影匠_COMFY）
    启动提示：开 ComfyUI Desktop，或命令行 python main.py --listen 127.0.0.1 --port 8188
    没引擎就只能看账本和磁盘，出图/出片都跑不了。
```

> ⚠ **「引擎没开」不算「问不到」。** 引擎没开是一个**确定的事实**，
> 面板明确写「ComfyUI 没开」并给启动提示，此时退出码仍是 **0**（【实测】，见 §5）。
> 只有分区**自己抛异常**（拿不到、说不清）才计「问不到」→ 退出码 2。
> 这两件事混在一起会让「退出码 2」变得毫无信息量。

### ③ 在跑什么 —— 读账本闸门，不读 GPU

本机只有一张 RTX 5080，一次只能跑一个活，所以「有没有别的活在跑」这个问题由
**账本的并发闸门**回答，而不是由 `nvidia-smi` 回答：

```
▶ 在跑什么
  ○ 闸门 0/1 占用 · 还能开 1 · 排队 1
    ⚠ 并发上限是 1 —— 本机只有一张 5080，一次只能跑一个，别硬抬。
    正在跑：无
    排队中（1）：
      t9d21ef550278e5   出图 《试镜》 镜01 格3（2秒）
```

闸门上限是 1 的时候面板会顶一句「别硬抬」——这是刻意的，因为把上限抬到 2
是本机最容易犯的错，两个活抢一张卡只会两个都变慢。

### ④ 要人管的事 —— 最显眼的一区

这是面板**最重要**的分区。三段，顺序刻意这么排：

1. **未知态（`账本.待人工()`）排最上面**，用 `⚠⚠⚠ … ⚠⚠⚠` 框起来。
   铁律是「**钱可能已经花掉时绝不自动重试，必须人工核对**」，所以这一段的措辞是
   「钱可能已经花了」，并且明确写「绝不许自动重试」。每条给出：可能是多少、
   供应商任务号、`输出路径` 那个文件在不在（顺手 `os.path.exists` 一下）、
   当时的原因、去哪查、以及两条具体命令（`账本.py 恢复 <id>` / `账本.py 完成 <id> --输出 <路径>`）。
2. **失败** —— 只提示「看一眼再决定重不重跑」，附 `账本.py 重试 <id>`。
   失败是**已知的坏**，不像未知态那样是个钱的黑洞，所以排在未知态后面。
3. **卡住的排队** —— 排队超过 `卡住分钟` 分钟还没轮到（阈值在 `面板.py` 顶部改）。

```
▶ 要人管的事
  ⚠⚠⚠ 未知态 1 件 —— 钱可能已经花了，必须人工核对，绝不许自动重试 ⚠⚠⚠
    ▶ tc3718209b4151f   出片 《试镜》 镜02 格1
      可能已计费 是 · 供应商任务号 prompt-abc123
      当时的原因 提交后 90 秒没等到结果，供应商那边状态不明
      去哪查：ComfyUI（本机 5080 上的 http://127.0.0.1:8188，没有外部供应商计费）
      怎么办：python 账本.py 恢复 tc3718209b4151f   （或 python 账本.py 完成 <id> --输出 <路径>）
  ✗ 失败 1 件 —— 看一眼再决定重不重跑：
    ✗ t84bf0480751b69   出图 《试镜》 镜01 格4（11秒） ComfyUI 连接被拒（node 掉线）
      重试：python 账本.py 重试 t84bf0480751b69
```

`--战情` 就只打这一区（+ 断点），专治「扫一眼就想知道要不要动手」。

### ⑤ 断点 —— 不只列出来，还给出接着跑的命令

### ⑥ 钱和时间 —— 「依据」栏是这一区的良心

读 `账本.统计()` + 对 4 种活各问一次 `账本.预估(类型, 1)`，再算一部戏的量（9 张图 / 9 段片）。
每一条都必须带 **依据**，明确区分：

- `实测均值（样本少）` —— 账本里有真跑过的样本，用历史均值。
- `基线估算` —— 账本里没有这类样本，用的是本机实测基线常量。
- `设计意图估算` —— 连基线都还没有，纯粹按设计估的（**未实测**）。

```
▶ 钱和时间
  账本共 4 件 · 估算 0.322 元 · 实际 0.002 元 · 可能已计费 1 件
    按状态：失败 1 · 完成 1 · 排队 1 · 未知 1
    最久一件 t3318897e490814（配音）0秒 · 总机时 1秒
    下一步大概要多久（依据栏说清是实测均值还是基线）：
      活          数量  积分      墙钟      电费        依据
      出图        1     0.04      0秒       0.0元       实测均值（样本少）
      出图四宫格  1     1.0       4秒       0.0004元    基线估算
      出片        1     0.05      0秒       0.0元       实测均值（样本少）
      配音        1     0.05      0秒       0.0元       实测均值（样本少）
      一部戏（9张）：约 0.4 积分 / 2秒 / 0.0002 元电费  ← 实测均值（样本少）
      一部戏（9段）：约 0.41 积分 / 2秒 / 0.0002 元电费  ← 实测均值（样本少）
```

账本里一件都没有的时候，面板会**明说**，不会假装有数据：

```
  账本共 0 件 · 估算 0 元 · 实际 0 元 · 可能已计费 0 件
    按状态：还没有任何任务 —— 还没数据。
    ⚠ 还没有数据：下面的秒数/积分全是本机基线估算，不是实测均值。
```

> 上面那段「出图 0.04 积分 / 0秒」是**样本少**导致的，别当真：
> 4 件样本里出图只跑过 1 次失败、还有 1 次是同类型的排队，
> 均值被极短样本拉到了 0。样本多了自然会回到正轨。**面板不替账本擦屁股，只如实转述依据。**

## 4. 为什么这么设计

### 4.1 为什么「一个数据源挂了不许拖垮整个面板」

`收齐()` 拿一张 `分区表`（分区名 → 收函数 → 打函数）逐个跑，**每个分区一层 try/except**：

```python
for 名, 收, _打 in 分区表:
    try:
        果["分区"][名] = 收()
    except Exception as e:
        果["分区"][名] = {"问不到": f"{type(e).__name__}: {e}"}
        果["问不到"].append({"分区": 名, "原因": f"{type(e).__name__}: {e}"})
```

打印层再包一层：某一区**打**的时候自己崩了，也只写一行「问不到（打印这一块时自己崩了）」，
不往外抛。理由是：面板是「出问题时你最需要打开的那个东西」，
它绝对不能因为「某个东西坏了」而自己也打不开。

### 4.2 为什么「引擎没开」和「问不到」要分开

见 §3 ①。一句话：**确定的事实 ≠ 拿不到**。把两者混起来，退出码 2 就变成噪音，
「有数据源问不到」这条告警也就没人看了。

### 4.3 为什么退出码 3 压过 2

`3 if 要人管件数 else (2 if 问不到 else 0)`。

因为「有笔钱可能已经花了没人管」比「有个数据源读不到」**更要紧**：
前者在烧钱，后者只是看不全。脚本 / 定时任务只需要判 `if 码 == 3` 就能拉起人。

### 4.4 为什么宽要算「格数」不算 `len()`

中文和 `✓ ✗ ◐ ● ○ ⚠ ▶` 在终端里占 2 格，`len()` 数的是字符数。
`面板.py` 里自己写了 `格数()` / `排()` / `截()`，按东亚宽度算，**整个屏幕压在 100 格以内**。
不依赖 `wcwidth`，零第三方依赖。

### 4.5 为什么不 import `审片.py`

`审片.py` 是判片子好坏的，它要读图、要算分，**慢**。面板要的是「产物文件到哪一步了」，
看一眼文件在不在就够，所以 ⑦ 直接 glob 文件，不去 import 审片。
面板刷新一次 200 多毫秒，靠的就是「不碰重活」。

同理，面板也不 import `剧组.py`；只在 ⑤ 里**打印** `python 剧组.py …` 这条命令让用户自己敲。

### 4.6 中文模块名 import 的兜底

`import 账本` / `import 引擎` 在某些路径 / 编码环境下会失败。
`面板.py` 用了项目现成的兜底模式（`一致性.py` 里那份）：先 `__import__`，
不行就走 `importlib.util.spec_from_file_location` 按文件路径硬装。
模块级只装一次，装不上就留 `None`，后面每个分区各自报「问不到」，**不连坐**。

### 4.7 为什么只借 `引擎._请求()` 这个「私有」函数

`/queue` 不在 `引擎.py` 的公开接口里。面板没去改 `引擎.py`（那是别人的文件），
而是借它的 `_请求()`——好处是**同一套 base url、同一套超时口径、同一个连接复用**，
不会出现「面板看到的引擎和真干活的引擎不是一个地址」这种事。
风险是 `引擎.py` 改了这个私有函数的签名就会断，所以调用点包了 try/except，
断了也只影响「队列：跑 X · 排 Y」这一行。

## 6. 已知局限（不粉饰）

1. **`锁脸` 的「✗ 不认」有歧义**。文件名不在 ComfyUI 的 `object_info` 里，
   面板只能说「引擎不认」，**分不清**是「文件真的没有」还是「文件名写错」还是
   「引擎需要重启刷缓存」。面板把「文件在不在」（查两个根）和「引擎认不认」（问 object_info）
   分成两列，就是为了让人自己判断，但**面板不下结论**。
2. **`_请求` 是私有函数**。见 §4.7。它一改，队列那一行就会变成「队列问不到」。
3. **「卡住」的阈值是拍的**。`面板.py` 里写死 `卡住分钟 = 30`，
   排队超过 30 分钟还没轮到就算「卡住」。这个数没有实测依据（本机一次出图才几秒），
   就是「排队排太久了，大概不对」的经验值。要改就改 `面板.py:536` 那一行。
4. **⑦ 只看文件在不在，不看文件对不对**。一个 0 字节的 `01_格1.png` 在面板眼里
   和一张画好的图一样是「✓」。判好坏是 `审片.py` 的活，面板故意不越界。
5. **盯模式每轮都重新连账本 / 重问引擎**。一轮 200 多毫秒，可以接受；
   但如果以后分区变重，得改成「只重取变化的部分」。
6. **盯模式在 Windows 用 `os.system("cls")`**，靠的是终端；重定向到文件时
   会把 `cls` 的转义序列也写进去（本文 §5 的 7 轮就是数标题行数出来的，不是真屏幕）。
7. **没有历史曲线**。只能看「现在」，看不了「过去一小时」。要曲线得另做一个采样器。
8. **`--json` 里的 ⑥ 分区很啰嗦**（`账本.预估()` 的完整返回，含 `说明` 长句）。
   给程序吃没问题，人不该直接看。
9. **退出码 2 的场景是打桩造出来的**，不是自然发生的。也就是说
   「真有一个数据源在真实世界里挂掉」这个现场**没遇到过**——
   设计上是对的（§4.1 的 try/except 是真的），但**真实故障路径未实测**。
10. **`影匠_账本` 指向一个不存在的目录时，账本会静默开一个空库**，
    面板于是显示「0 件」而不是「问不到」。
    【实测】`影匠_账本=…\不存在的目录\账本.db` → 面板显示 0 件、退出码 0。
    这是账本那边的行为，面板照实转述，但用户会以为「账本是空的」而不是「路径写错了」。
    **这算是面板的一个盲点**，要修得在面板里额外探一次「这个路径存在吗」。
