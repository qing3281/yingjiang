# MiniMax H3（海螺 H3）提示词写作规范 v1.0

> 适用环境：ComfyUI 0.39.2 内置 `MiniMaxH3ReferenceToVideo` / `MiniMaxH3TextToVideo` 节点
> 调研日期：2026-08（所有结论标注来源 URL；查不到出处的明确标「未证实」）
> 结论先行：**你现在的 580 字符不是「不够长」，是「结构不对」。** 官方 55~80 词范例能出好片子，是因为它们是**纯文生视频、单镜头、无参考图**。你有参考图 / 要台词 / 要长镜头，就必须用 Context-IR 结构化长提示词。

## 0. 先纠正三个普遍误解

| 误解 | 事实 | 来源 |
|---|---|---|
| 「提示词越长越好，要写满 7000 字符」 | 官方上限 **7000 字符**，但**没有「必须写满」的要求**。官方举例中位数约 130 个中文字符，最长两例 657 / 858 字符。长度是结果，不是目标 | [video-generation.md](https://platform.minimax.io/docs/guides/video-generation.md)、[atlascloud 实测 45 条官方提示词](https://www.atlascloud.ai/zh/blog/tips/minimax-h3-prompt-guide) |
| 「一小段视频要 9000 字」 | **未证实**。中文互联网没有找到这句话的原始出处。最可能的来源是官方 API 文档里 `H3-Context-IR` 示例返回的 `usage.total_tokens: 9090` —— 那是**token 数**，不是字数，也不是输入上限 | [video-generation-v2-h3-context-ir.md](https://platform.minimax.io/docs/api-reference/video-generation-v2-h3-context-ir.md) |
| 「官方范例很短，所以短提示词最好」 | 官方范例短是因为它们**没有参考图、没有台词、只有 1 个镜头**。官方同时明确警告：**「提示词太短」是记录在案的失败模式**，无参考图时至少必须覆盖「主体外观 + 场景细节 + 动作 + 风格」四要素 | [video-generation.md](https://platform.minimax.io/docs/guides/video-generation.md)、[pixo 官方手册解读](https://pixo.video/zh/blog/minimax-h3-prompt-guide) |
| 「中文提示词效果差」 | 官方支持 11 种对白语言（含中文）。`H3-Base` 的文本编码器是 Qwen3-VL-32B（**中文母语模型**），中文理解没问题。**但**官方技能与 Context-IR 输出的「结构化字段名」是英文的——字段名和格式必须英文，正文和台词可以中文 | [README.zh-CN.md](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/README.zh-CN.md) |

## 1. H3 的三层架构 —— 理解这个才有「短 vs 长」的答案

官方仓库明确说明完整 H3 由三个模块组成（[README.zh-CN.md](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/README.zh-CN.md)）：

```
自由输入（一句话 / 参考图 / 参考视频 / 参考音频）
        ↓
① H3-Context-IR  ← 托管式预处理系统，把自由输入「解释并序列化」成结构化中间表示
        ↓
② H3-Base        ← 真正的生成模型，吃的是 ① 的输出。开源的是这个（FL2VA / Ref2VA）
        ↓
③ H3-Regenerate-2K ← 把 768p 结果 + 原始上下文送回 H3 重生成 2K
```

**官方原话（重点）**：

> 「H3-Context-IR 对最终输出质量至关重要，因此我们**强烈建议将其纳入你的生成流水线，或按照"提示词指导"构建自己的上下文处理系统**。」

这句话就是本规范的全部立足点。

### 关键推论：你的 ComfyUI 节点吃的是「②」，不是「①」

| 场景 | 官方短范例 | 你的场景 |
|---|---|---|
| 输入 | 一句话 | 一句话 + 9 张图 + 台词 + 运镜要求 |
| 谁负责「把自由输入翻译成结构化提示词」 | H3-Context-IR | **没有人**——本地 ComfyUI 只有 H3-Base |
| 所以 prompt 框里该放什么 | 用户话音刚落，Context-IR 自动扩写 | **你必须手写 Context-IR 的输出格式** |

**这就是「什么时候用短的、什么时候用长的」的答案**：

- ✅ **可以写短**：纯文生视频（T2VA）、只有一个镜头、没有台词、不要求跨镜头身份一致。此时短提示词 ≈ 官方范例，Context-IR 的活很少。
- ❌ **必须写长（结构化）**：用了参考图 `<Picture i>`、有多镜头/切镜、有台词或歌声、要求跨镜头锁脸、要求「一镜到底」、用了 `<Video k>`/`<Audio j>` 参考。此时短提示词 = 让 H3-Base 自己兼职做 Context-IR，效果必然崩。

> **一句话判据：只要提示词里出现了 `<Picture 1>` 这个标签，你就已经在扮演 Context-IR 了，请按第 3 节的完整结构写。**

## 2. 最常用的三条路：先选骨架

| 你的输入 | 模式名 | 骨架 |
|---|---|---|
| 纯文字 | T2VA | 三字段 |
| 一张图当首帧 / 首尾帧 | I2VA / FL2VA / L2VA | 首行对齐句 + 三字段 |
| 图/视频/音频当参考（最多 9+3+3） | Ref2VA | **六段式** |

### 2.1 T2VA / I2VA / FL2VA / L2VA：三字段骨架

来源：官方技能 `skills/h3-prompt-writing/references/base-en.txt`（[MiniMax-AI/MiniMax-H3](https://github.com/MiniMax-AI/MiniMax-H3)）

```text
<首行：仅 I2VA/FL2VA/L2VA 需要，见下> 
<空一行>
integrated_multimodal_description: [Shot 1] ...（主体 / 镜头 / 动作 / 对白 / 同期声）
[Shot 2] At 00:03.500, the camera cuts to ...
overall_soundscape: ...（环境音 + 物理动作音 + 非语言人声，1-4 句）
non_diegetic_music: ...（角色听不到、只有观众听到的配乐，1-3 句；没有就写 N/A）
```

**首行对齐句（一字不改抄，只替换时间与镜头号）：**

- **I2VA**（图当首帧）：
  `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`
- **FL2VA**（首尾帧）：
  `How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.`
- **L2VA**（图当尾帧）：
  `How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.`

其中 `N` = 实际最后一个镜头的编号，`S.SS` = 视频时长，**必须保留两位小数**（如 `8.00`、`6.00`）。

**三种关键帧模式的叙事骨架（这是官方给的，别自己发明）：**

| 模式 | 骨架 | 忌讳 |
|---|---|---|
| I2VA | 首帧锚定 → 动作起势 → 连续发展 → 结果/反应 | 开头不描述图里已有的东西，直接跳动作 |
| FL2VA | 首帧状态 → 可见的中间变化 → 差异逐步收窄 → 尾帧状态 | ① 把两张图的静态描述各抄一遍；② 默认多镜头（FL2VA **天然偏好单镜头**，要多镜头必须显式写） |
| L2VA | 合理的前置状态 → 明确的动作与过渡路径 → 末镜头逐步收敛 → 落到尾帧 | 让 `<Picture 1>` 出现在 Shot 1 |

### 2.2 Ref2VA：六段式骨架（**你真正需要的**）

来源：官方技能 `skills/h3-prompt-writing/references/ref-en.txt`

```text
subject_definitions:
<Subject 1> is ... from <Picture 1>. ...
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).

summary:
[reference generation + audio reference] ...

retention_analysis:
<Subject 1> (appears in [Shot 1], [Shot 3]): fully_preserved - ...
<Audio 1>: reference - ...

detailed_description:
<1~2 句全局风格 / 影调 / 制式>
[Shot 1] ...
[Shot 2] At 00:03.000, the shot cuts to ...

overall_soundscape:
...

non_diegetic_music:
...
```

**六段的职责分工：**

| 段 | 作用 | 写作要点 |
|---|---|---|
| `subject_definitions` | 把每个参考素材绑定成一个稳定实体 | 一行一个标签；写清「它是什么 + 来源 + 必须保持的特征」。**只用来定义身份/场景/风格、不作为具体帧锚点的图，不要单独起一行**，而要在对应的 `<Subject N>` 里引用它的出处 |
| `summary` | 一句话说清任务类型 + 目标视频 + 主要参考关系 | 以方括号任务类型开头；`+` 连接多个类型；**不得引入新标签** |
| `retention_analysis` | 逐条说明参考内容如何被保留/转移/复用 | 一行一个标签 + 固定关系标记（见下） |
| `detailed_description` | 主体：按播放顺序逐镜头写 | **生成类任务常规 350–500 英文词**；对白密集时优先「塞满台词时间轴」而不是凑字数 |
| `overall_soundscape` | 全片环境音/物理音 | 1–4 句一段；**不要重复** `detailed_description` 里的对白、歌声、同步音效 |
| `non_diegetic_music` | 只有观众能听到的配乐 | 1–3 句；写**配器 / 速度 / 节奏 / 力度变化**，不写「忧伤的氛围」这种抽象情绪词；没有就 `N/A` |

**`retention_analysis` 的固定关系标记（英文值，不能翻译）：**

- 视觉内容（`<Subject N>` / `<Picture N>` / `<Video N>`）：
  `fully_preserved`（完全保留） / `partially_preserved`（部分保留） / `attribute_transfer`（特征转移到另一个主体） / `weak_reference`（只保留风格/类别/构图上的宽泛相似）
- 音频（`<Audio N>`）：
  `fully_copy`（整轨 1:1 复用） / `partially_copy`（只复用部分时间轴或部分音层） / `reference`（不复用信号，只参考音色/节奏/风格/内容） / `weak_reference`

**`summary` 的任务类型标记：**

| 标记 | 何时用 |
|---|---|
| `keyframe completion` | 图作为首帧/尾帧/关键帧/编辑后关键帧 |
| `reference generation` | 图/视频/音频只提供**生成引导**（人物、场景、风格、动作、运镜、故事板） |
| `video editing` | 直接修改已有源视频 |
| `video continuation` | 从已有视频续写/延长/衔接 |
| `audio reuse` | 音频信号整体或部分被复用 |
| `audio reference` | 只参考音色/风格/内容/节拍，不复用信号 |

> ⚠️ **「有视频/音频文件」≠「自动是 video editing」**。如果参考视频只提供运镜和节奏，那是 `reference generation`。

## 3. 摄影机语法：这一节请重点看

### 3.1 H3 的正确语法不是方括号，而是「自然语言 + 三维度」

官方 H3 指南原文（`base-en.txt` §4.3）与社区验证的系统提示词（[HF Discussion #47](https://huggingface.co/MiniMaxAI/MiniMax-H3/discussions/47)）一致：

> **Camera Motion = 运动类型（Motion Type）+ 幅度（Amplitude）+ 速度（Speed）**，写成一个**自然英文动作，嵌在镜头描述里**，不要当成标签堆在句尾。

**完整运动类型清单（官方 13 项）：**

| 类型 | 含义 |
|---|---|
| `Zoom In / Zoom Out` | 机身不动，焦距变化 |
| `Push In / Pull Out` | 机身向前 / 向后移动 |
| `Pan Left / Pan Right` | 机位不动，镜头水平摇 |
| `Truck Left / Truck Right` | 机身水平平移 |
| `Tilt Up / Tilt Down` | 机位不动，镜头垂直摇 |
| `Pedestal Up / Pedestal Down` | 整机上升 / 下降 |
| `Arc Shot` | 绕主体弧线运动 |
| `Tracking Shot` | 跟随移动的主体 |
| `Static Shot` | 机位与镜头均不动 |
| `Shake Slightly / Shake Strongly` | 轻微 / 强烈抖动 |
| `POV` | 主体视角 |
| `Roll Clockwise / Roll Counterclockwise` | 绕镜头轴顺时针 / 逆时针旋转 |

**幅度**：`with small amplitude`（小幅度）/ `with large amplitude`（大幅度）
**速度**：`at slow speed`（慢）/ `at fast speed`（快）
→ **中等幅度、正常速度通常省略不写**（这是默认值）。

**正确写法（三例，官方原文）：**

```text
The camera pushes in with small amplitude at slow speed toward the folded letter in her hands.
The camera pans right with large amplitude at fast speed, revealing the open doorway.
The camera holds a static shot as the runner exits the frame.
```

**错误写法：**

```text
❌ 她打开信。运镜：慢推。
❌ [Push in] 她打开信。
```

### 3.2 方括号 `[pan]` `[zoom]` `[static]` 到底是什么

**结论：方括号运镜指令是 Hailuo 上一代模型（Video-01 / 02 / Director / Hailuo-03）的 API 语法，H3 官方指南已改用自然语言。方括号在 H3 上不是官方推荐语法。**

- 方括号指令在 H3 官方指南里**唯一合法且必须保留**的用法是**镜头标记 `[Shot N]`**（这是结构分隔符，不是运镜指令）。
- 官方备注（来自早期 API 文档，H3 指南未复述）：旧 Hailuo 端点支持 `[command]` 语法，**共 15 条**，且 **i2v 类端点最多一次组合 3 条**，逗号分隔、写在提示词开头：

```text
[Truck left, Pan right, Zoom in]   ← 旧 Hailuo 语法，最多 3 条
[Push in]
[Static shot]
[Zoom out]
[Tilt up] / [Tilt down]
[Pedestal up] / [Pedestal down]
[Pan left] / [Pan right]
[Truck left] / [Truck right]
[Tracking shot]
[Static shot]
```

  来源：[MiniMax i2v API 文档](https://platform.minimax.io/docs/api-reference/video-generation-i2v)（「camera movement can be controlled using `[command]` syntax. Supported **15** camera commands」）、[Replicate Video-01 Director](https://replicate.com/minimax/video-01-director)。

**实操建议（针对你的 ComfyUI 本地 H3）：**

1. **首选自然语言三维度写法** —— 这是官方 H3 指南的语法，也是训练分布内的。
2. 如果你已经有一套方括号提示词、且实测有效，**可以保留**（同一指令语义，模型有一定泛化），但**不要混用**（同一段里别既写 `[Push in]` 又写 `The camera pushes in`）。
3. **绝对不要组合超过 3 条**，那不适用于 H3。
4. 方括号写法**不与自然语言冲突的仲裁机制没有被官方文档定义 → 未证实**。若两者都写，行为不确定，请二选一。

### 3.3 三档写作强度（你现在第 1 档都没到）

| 档位 | 写法 | 风险 |
|---|---|---|
| ❌ 档 1（你现在的水平） | 不写运镜 → 模型自由发挥 | 场景漂移、无节奏 |
| ✅ 档 2（推荐） | 每个镜头写 1 个完整三维度运镜 | 稳定 |
| ⚠️ 档 3（你踩过的坑） | 同一镜头叠 2 个以上大幅度 / 快速运镜（`pans right with large amplitude at fast speed` + `trucks left` + `zooms in`） | **大幅度 + 快速度 + 多类型叠加 = 场景漂移**。这是你的坑的根因 |

**「运镜写猛了场景会漂移」的正确解法**（依据官方 `base-en.txt` §4.2 的镜头规则）：

- 一个镜头内**只写一个主运镜**；要换运镜就切 `[Shot N]`。
- 需要维持空间稳定时，明确写 `The camera holds a static shot` / `Static Shot`。
- 幅度、速度**只在有意义时写**；写 `with small amplitude at slow speed` 比写 `with large amplitude at fast speed` 稳得多。
- 官方原话：**「如果只需要改变景别或轻微角度，优先用运镜而不是切镜」**——反过来，运镜已经不足以表达时再用切镜，而不是继续堆运镜。

## 4. `H3-Context-IR` 是什么、本地能不能用

### 4.1 定义（官方原文）

> `H3-Context-IR` 深入解释跨文本、图像、音频、视频的多模态上下文，分析输入之间以及输入与目标输出之间的关系，进行复杂推理，并把这种理解转换为**具有更丰富语义细节的结构化表示**，同时尽可能保留用户原始意图。
> **该端点只返回增强后的提示词，不创建视频生成任务。**
> **H3-Context-IR 是一个复杂系统，其实现未开源。**

**输入 / 输出：**

| | 内容 |
|---|---|
| 输入 | `model: MiniMax-H3` + `content[]`（`text` 必填非空；可选 `image_url` 带 `role`）+ `duration` (4–15 整数) + `ratio` |
| `role` 取值 | `first_frame` / `last_frame` / `reference_image` / `reference_video` / `reference_audio`。**首尾帧模式与参考模式互斥**，不能混用 |
| 输出 | `task_id` → 查任务 → `content.prompt`（就是那句结构化增强提示词） |
| 端点 | `POST /v2/h3_context_ir` |

来源：[video-generation-v2-h3-context-ir.md](https://platform.minimax.io/docs/api-reference/video-generation-v2-h3-context-ir.md)

### 4.2 输入输出实例（这是「短 → 长」的实证）

**输入**（7 词，英文）：

```text
Epic space-opera theatrical teaser: a female captain stands alone before a massive observation window
as the last fleet gathers and jumps away in a blinding flash, the bridge shaking, leaving her behind.
```

**输出**（约 1,700 字符，三段式结构 + `[Shot 2] At 00:02.800` 切镜 + 强烈抖动）：

```text
integrated_multimodal_description: [Shot 1] Cinematic, wide shot with a slow push in on a female captain
standing center frame with her back to the camera. She has a slender build and short, swept-back silver
hair, wearing a crisp, dark navy-blue futuristic military uniform adorned with rigid silver epaulets.
Before her stretches a colossal, curved glass observation window dominating the dimly lit starship bridge.
... [Shot 2] At 00:02.800, the camera cuts to a medium close-up of the captain from Shot 1 in profile
facing right, while the camera shakes strongly. ...
overall_soundscape: Deep, resonant low-frequency thrumming of ship engines, overlaid with rhythmic,
high-pitched electronic beeps from the consoles, followed by a sudden, deafening sub-bass boom ...
non_diegetic_music: Symphonic orchestral score, beginning with a slow, rising brass and string crescendo
that abruptly cuts off, instantly transitioning into a single, sustained, low-register solo cello note
with no dynamic swell.
```

`usage: total_tokens 9090 / prompt_tokens 5664 / completion_tokens 3426` ← **「9000」的最可能来源**

来源：[video-generation-v2-h3-context-ir.md](https://platform.minimax.io/docs/api-reference/video-generation-v2-h3-context-ir.md)

### 4.3 本地能用吗？—— 不能，但可以手工模拟（官方允许）

- ❌ **本地不能调用** `H3-Context-IR`：模块未开源，`H3-Base` 的两个 checkpoint（FL2VA / Ref2VA）里**没有** Context-IR。
- ✅ **本地也真的不需要它**：你的 ComfyUI prompt 输入框本身接受的就是 `H3-Base` 的 conditioning 文本 —— 也就是说，**你在输入框里手写的，本来就应该是 Context-IR 的输出格式**。
- ✅ **可以用别的大模型手工模拟，且这是官方认可的路径**。官方原话：

  > 「我们提供了详细教程，开发者可以**按照"提示词指导"构建自己的预处理系统**。」
  > 「H3-Context-IR …… 我们提供 API 帮助用户复现官方工作流的行为。」

**手工模拟的正确做法（三步）：**

1. **准备中文字幕/剧本**（这一步用自然语言，怎么写都行）。
2. **复制官方技能里的一段提示词给任意大模型**：

   > 你是 MiniMax H3 的 H3-Context-IR 替代品。请把我给的中文创作意图，翻译成 H3-Base 能直接消费的结构化提示词，**逐字保留以下字段名和顺序**：
   > `integrated_multimodal_description:` / `overall_soundscape:` / `non_diegetic_music:`
   > 规则：① 正文写英文；对白、歌词、画面内文字保留原语言。② `[Shot 1]` 不带时间戳，后续镜头写 `[Shot N] At MM:SS.mmm, the camera cuts to ...`。③ 运镜写成自然英文动作，格式为「运动类型 + 幅度 + 速度」，中等幅度与常速省略。④ 说话人给稳定 ID `(S1)`/`(S2)`，同一个人跨镜头必须同一个 ID；首次出现时补足年龄、性别、是否在画面内、音高、音色、语速、口音。⑤ 对白写成 `<d>[Language] 原文</d>`，原文一字不改，不翻译、不改写。⑥ 旁白用 `says in an off-screen voiceover`，并在每个旁白 `<d>` 块后立刻说明对应角色的嘴唇保持闭合。⑦ `overall_soundscape` 1–4 句，不重复对白。⑧ `non_diegetic_music` 只写配器/速度/节奏/力度，没有写 `N/A`。⑨ 总时长与要求一致（4–15 秒）。
   > 只输出提示词正文，不要解释。

   （原始可复制版本见 [HF Discussion #47](https://huggingface.co/MiniMaxAI/MiniMax-H3/discussions/47) 与 [cushycrux/H3_LLM_Instructions](https://github.com/cushycrux/H3_LLM_Instructions/tree/main)，本地 LLM 用户已实测可用）
3. ⚠️ **诚实边界**：官方明确 `H3-Context-IR` 未开源。手工模拟的提示词**遵循同一公开格式，但不得声称等同于官方系统输出**。

## 5. 参考图 / 参考视频 / 参考音频：标签规则

### 5.1 两类标签，别混淆

| 类别 | 标签 | 语义 |
|---|---|---|
| **可复用内容** | `<Subject N>` | 从参考素材中抽象出来的、可在目标视频里复用或修改的**可见内容单元**（人、动物、物体、场景、服装、道具、界面、特效、风格、动作、表情、姿势） |
| **素材本身** | `<Picture N>` | 作为**具体目标帧**或**分镜锚点**的参考图 |
| | `<Video N>` | 提供**剪辑源 / 续写起点 / 整片时间结构**的参考视频 |
| | `<Audio N>` | 被复制或参考的音频信号 |

> **关键区别**：`<Subject N>` 是「内容」，`<Picture N>` 是「文件」。**如果一张图只用来定义人物/场景/服装/风格（不作为具体帧），不要给它单独起 `<Picture N>` 行**，而应在对应的 `<Subject N>` 定义里引用它的出处。

```text
✅ <Subject 1> is the young woman in <Picture 1>, with long dark hair, a blue cardigan, and a thin silver necklace.
❌ <Picture 1> is the young woman with long dark hair...   ← 只锁脸时不该这么写
```

**一个主体可以来自多个素材，一个素材也可以提供多个主体：**

```text
<Subject 1> is the woman whose appearance comes from <Picture 1> and whose walking motion comes from <Video 1>.
```

### 5.2 本地节点里的编号规则（务必按这个来）

你的节点源码 `comfy_extras/nodes_minimax_h3.py` 里写得很清楚（`MiniMaxH3ReferenceToVideo` 的 docstring）：

> References enter the presentation in fixed order: **images, then videos (each soundtrack's `<Audio j>` label right before its `<Video k>`)**, then standalone audio. **Ordinals are 1-based per type**, so the prompt refers to them as `<Picture i>` / `<Video k>` / `<Audio j>`.

也就是说：

- 编号**按类型各算各的、从 1 开始**：`ref_image_1` → `<Picture 1>`，`ref_video_1` → `<Video 1>`，`ref_audio_1` → `<Audio 1>`。
- **不是**按上传顺序混编。`<Video N>` 和 `<Audio N>` 各自独立编号——同一个参考视频可能是 `<Video 1>` + `<Audio 2>`，这**不表示它们不是同一个文件**。
- **`ref_video_audio_1`（某个参考视频的原声）会以 `<Audio j>` 标签排在对应 `<Video k>` 之前**——所以视频原声会占用一个 `<Audio>` 序号，请按此顺序数你的独立音频。
- 槽位上限：`ref_images` ≤ 9、`ref_videos` ≤ 3（各 2–15 秒，总时长 ≤ 15 秒）、`ref_video_audios` ≤ 3、`ref_audios` ≤ 3，**混合输入文件总数 ≤ 12**。
- 节点提示：`ref_image_size` 选 `max`（2048px 短边）对**身份保真最好，但会慢好几倍**（参考 token 会参与每一步采样）；选 `match` 更快。
- ⚠️ 不给 `vae` / `audio_vae` 时，参考图/视频/音频**只条件化文本编码器**，不进入 DiT——保真度会明显下降。

> 官方 API 里叫 `<Picture i>`；Hailuo/官方范例里也常写 `Image 1` / `图片1`。**本地 ComfyUI 节点必须用 `<Picture i>` 尖括号形式**（tokenizer 按这个标签匹配），`Image 1` 是网页端/API 端的自然语言写法。

### 5.3 一张参考图负责什么？9 张图怎么分工

官方"文件用途分类法"（[pixo 官方手册解读](https://pixo.video/zh/blog/minimax-h3-prompt-guide)，与官方范例一致）：**每个文件都必须有明确声明的用途，不声明用途 = 浪费掉的文件。**

| 用途 | 锁什么 |
|---|---|
| 人物参考 | 锁脸 / 形象 |
| 物体参考 | 锁产品或道具 |
| 场景参考 | 锁场景 |
| **关键帧** | 锁具体帧（必须写清是首帧还是尾帧） |
| 音色参考 | 锁音色 |
| 故事板 | 按分镜图生成镜头内容 |
| 风格参考 | 匹配风格 |
| 构图参考 | 匹配取景与排布 |
| 音频复用 | 音频整体/部分复用 |
| 动作参考 | 锁视频中的动作 |
| 运镜参考 | 锁运镜 |
| 视频编辑 | 要被修改的那段视频 |

**9 张图的分工建议（按「身份 / 空间 / 风格 / 帧锚点」四类分配，宁少勿滥）：**

| 张数 | 推荐分配 |
|---|---|
| 1 张 | 人物参考（锁脸）——最常用 |
| 2 张 | 人物参考 + 场景参考 |
| 3 张 | 人物参考（全身造型）+ 人物参考（面部多角度）+ 物体/道具参考 |
| 4 张 | 上者 + 风格/影调参考（官方品牌片范例就是 Image1 影调 + Image2 人物 + Image3 产品 + Image4 logo） |
| 5–6 张 | 加：首帧关键帧（或故事板） |
| 7–9 张 | 加：配角人物参考、尾帧关键帧、构图参考 |

**官方范例（三张图三个明确分工，提示词里完全不描述模特的脸和眼镜）：**

```text
9:16 high-fashion eyewear commercial on a minimal white cyc.
Image 1: two full-body female models. Image 2: facial details.
Image 3: eyewear design — wrap-around curves, sharp cat-eye/goggle hybrid silhouettes,
mirror reflections, streamlined temples. Keep the runway attitude and cool demeanor.
```

**铁律：**

1. **能靠参考图锁住的，就不要用文字描述**（脸、服装细节、产品纹理）——文字描述脸反而会和参考图打架。
2. **不能让参考图锁的，才用文字写**（动作、情绪、节奏、视线方向、台词、物理交互）。
3. **每张图必须有一句 `@图片N 是 XX 参考（锁什么）`**。上传了却不说用途，是「参考被忽略的头号原因」。
4. 想让画面里出现文字 → **逐字写出原文**（见 §6.3）。

## 6. 对白 / 音频怎么写（这是 H3 最强也最容易翻车的部分）

H3 输出 **32 kHz 立体声**、支持 **11 种稳定对白语言**（阿拉伯语、中文、英语、法语、德语、意大利语、日语、韩语、葡萄牙语、俄语、西班牙语）。来源：[README.zh-CN.md](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/README.zh-CN.md)

### 6.1 对白格式：说话人标注必须在 `<d>` 外面，台词必须在里面

```text
The young woman with a quiet, breathy voice (S1) says: <d>[English] I get off at the next station.</d>
The two children (S1,S2) shout together, <d>[English] Wait for us!</d>
```

**硬性规则：**

| 规则 | 说明 |
|---|---|
| ID 格式 | `(S1)` `(S2)`…；**同一说话人跨镜头必须用同一 ID**；从不出声的角色**不给 ID** |
| 多人齐声 | 复合 ID：`(S1,S2)` |
| ID 位置 | 说话人的「辨识短语 + (Sx) + 动作 + 说话方式」放在 `<d>` **外面** |
| `<d>` 内部 | **只放语言标签 + 用户提供的台词原文** |
| 原文保真 | **一字、一个标点都不能改**，不翻译、不改写 |
| 首次出现 | 必须补足：角色类型 / 年龄 / 性别 / 是否在画面内 / 音高 / 音色 / 语速 / **口音** |
| 旁白 | 用固定短语 `says in an off-screen voiceover`，且每个旁白 `<d>` 块后**立刻声明对应角色嘴唇保持闭合** |
| 跨切镜台词 | 在两个连接点写 `<scenetrans>`，并明确说明音频跨切镜延续（`continues seamlessly across the cut` 等） |
| 被结尾截断 | 写 `<cutoff>` |
| 听不懂 | 写 `[unclear]`，**不要猜、不要转述** |
| 标点 | 只保留 `, . ? !`；删掉重复波浪号、emoji、项目符号、装饰性标点 |
| 只参考音色时 | **不要把参考音频里的原始台词写进目标视频** |

### 6.2 语言 / 口音 / 语速 / 音色 / 情绪怎么标注

官方格式是：**在 `<d>` 外面的那句里，用自然英文把「语言 + 口音 + 语速 + 音色 + 当前情绪」一次说清**，然后台词本身放 `<d>` 里。

```text
✅ 标准写法（官方范例）
<Subject 4> (S2) says in a casual young male voice with a playful tone and an easy conversational pace,
<d>[English] He just likes cookies more than me.</d>

✅ 中文 + 口音 + 语速 + 音色 + 情绪（社区实践，[worked-example.md](https://github.com/yajnignez/minimax-h3-prompts)）
洛桑（用带藏族口音、温和缓慢、低沉平稳的普通话说）：“你在和树打架吗？要不要帮忙？”
扎西（用带藏族口音、略快、少年音色、带一点逞强的普通话说）：“不用，我自己能弄开。”
```

**中文场景推荐标注顺序（写成一句英文放在 `<d>` 前）：**

```text
The middle-aged man with a warm, slightly hoarse voice and a gentle Sichuan accent (S1) says at a
measured pace in Mandarin Chinese, <d>[Chinese] 你来了，剑等你好久了。</d>
```

**逐镜头的对白连续性（这是最容易翻车的地方）**——社区实例给出的教训：

```text
❌ Bad（第二句在拒绝一个从未被提出的帮助）
洛桑：“你在和树打架吗？”
扎西：“我自己能弄开。”

✅ Good（每句都直接回应前一句）
洛桑：“你在和树打架吗？要不要帮忙？”
扎西：“不用，我自己能弄开。”
```

**规则：每次生成新片段，都要把完整的「说话方式说明」重写一遍，不能简写成「洛桑说」「扎西回答」。**

### 6.3 画面内文字（招牌 / 标题 / UI / 字幕）

**必须逐字写出原文**，放在英文双引号里，不翻译：

```text
A red neon sign reading "营业中" glows above the doorway.
手机屏幕上显示标题："AI Video Creation"，按钮文字为："Start Now"。
```

想让画面里出现「THE STARS WERE LISTENING」这种大标题，就把这句话原样写进去，并补上字体描述（极窄、厚重、全大写、暗红铁锈色、颗粒与雾化边缘）。

### 6.4 用 `<Audio N>` 做音色参考

```text
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).
<Audio 2>: reference - the target speaker follows <Audio 2>'s voice timbre and measured delivery
without copying the original signal.
```

**注意：`<Audio N>` 绑定到某个目标说话人时，必须复用该说话人的全局 `(Sx)` ID，不能自己重新编号。`(Sx)` 只在 `detailed_description` 里写，`retention_analysis` 里不写。**

**音频不能作为唯一输入**——官方规定音频必须与图像或视频输入一起使用。

## 7. 负面约束怎么写（含你的两个具体坑）

H3 **没有**独立的 negative prompt 输入框。负面约束只能**写在正文里**或**用官方约定的字段**。

### 7.1 坑 1：模型把提示词里的中文当台词念出来 —— 根因是「中文台词没有容器」

**根因**：你把中文句子裸露在正文里，H3 无法区分「这是给模型的描述」还是「这是台词」。官方为台词设计了专用容器 `<d>`，**不带容器的自然语言句子会被模型当作可朗读内容**。

**正确解法（三件事一起做）：**

1. **正文一律用英文写**。官方技能的 `Output Rules` 原文：**「Write rewrite sections in English; preserve dialogue, lyrics, and visible scene text in their original language.」** 也就是说：**字段名、描述文字 = 英文；台词、歌词、画面内文字 = 原语言并放进专用容器。**
2. **所有中文台词放进 `<d>[Chinese] ...</d>`**，前面必须紧跟说话人说明：

   ```text
   ✅ 安全
   The young woman with a clear, gentle voice (S1) says: <d>[Chinese] 你来了。</d>

   ❌ 危险（裸中文 = 会被念出来 / 会被当描写）
   年轻女人说：你来了。
   ```
3. **显式排除**（写在 `detailed_description` 末尾或 `overall_soundscape` 之前，用英文）：

   ```text
   No narration of the prompt text. No text overlay other than the on-screen text explicitly
   specified above. Characters do not speak any line that is not enclosed in <d>...</d>.
   ```

4. **如果全片不该有人说话**：`overall_soundscape` 不写人声，`non_diegetic_music` 按时写内容或 `N/A`，并在正文末尾加：

   ```text
   No dialogue, no singing, no voice-over. All characters remain silent throughout; lips stay closed.
   ```

### 7.2 坑 2：运镜写猛了场景漂移 —— 根因是「同一镜头堆叠多个大幅度快速度运镜」

**正确解法**（回看 §3.3）：

1. **一个镜头一个主运镜**。幅度、速度只在有意义时写；需要精确控制时用 `with small amplitude at slow speed`。
2. **想固定空间**：写 `Static Shot` / `The camera holds a static shot throughout the entire duration`。
3. **想「一镜到底」必须显式禁止切镜**（否则 H3 默认会切镜）：
   ```text
   ... 自然衔接，不要切镜。 / Keep a single continuous take. Do not cut.
   ```
   官方首尾帧模式范例：`让她从持剑起势到舞剑完毕，自然衔接，不要切镜。`
4. **不要在镜头中途换运镜**：要换运镜 → 切 `[Shot N]` → 新镜头写新运镜。
5. **场景锚点要复述**：「地板潮湿反光」「她站在画面右侧」这类空间锚点在每个镜头都要提一次。

### 7.3 禁 BGM（官方指定写法）

```text
non_diegetic_music: N/A
```

官方举例：不要 BGM，就在提示词末尾写 `non_diegetic_music: N/A`。
**⚠️ 绝对不能自相矛盾**——一句话要配乐、另一句话禁 BGM，是官方手册点名的失败模式。

### 7.4 官方点名的六大错误（照抄自查表）

来源：[pixo 官方手册解读](https://pixo.video/zh/blog/minimax-h3-prompt-guide)（与官方 `video-generation.md` 一致）

| # | 错误 | 修法 |
|---|---|---|
| 1 | 把所有东西糊成一段无结构的话 | 按三字段 / 六段式拆开 |
| 2 | 上传了素材却没写用途 | 每个文件补一句「`<Picture 1>` 是 XX 参考（锁什么）」 |
| 3 | 一边要配乐一边禁 BGM | 删掉其中一个，或分场景各说各的 |
| 4 | 想要一镜到底却写了 `镜头1 / 镜头2` | 保持一段连续情节描述，删掉分镜结构 |
| 5 | 想要脸部一致却没传参考图 | 上传一张并标注「人物参考（锁脸）」 |
| 6 | 没传文件时提示词太短 | 至少覆盖：主体外观 + 场景细节 + 动作 + 风格 |

## 8. 两个完整长提示词范例

> 以下两例都是**可直接粘进 ComfyUI 输入框**的完整结构，均超过 2000 字符（实测：范例 A 约 3,900 字符，范例 B 约 7,900 字符）。
> 用法：范例 A 对应「纯文生视频 / 多镜头 / 有台词」；范例 B 对应「9 张参考图 / 一镜到底 / 有对白」。
>
> ⚠️ **长度提示**：官方 API 的 `text` 项上限是 **7000 字符**，范例 B 略微超出——**本地 ComfyUI 走的是节点内的 tokenizer，没有这个 7000 字符闸门，可正常使用**；但如果你要把同一段提示词拿到 Hailuo 网页端或官方 API 复现，请把 `subject_definitions` 与 `retention_analysis` 压到各 3–4 行。**日常生产建议区间：1500–4000 字符**。

### 范例 A：T2VA 三字段结构（约 2,400 字符，16:9，10 秒，3 个镜头，含中文台词）

```text
integrated_multimodal_description: [Shot 1] Live-action, cinematic, a slow-burning nocturnal neo-noir. An
extreme wide shot frames a narrow rain-slicked alley in an old Cantonese city block at 02:40 at night. Wet
grey brick walls rise on both sides, glazed with a thin film of water that mirrors the red and cyan neon of
a noodle shop sign at the far end. A single overhead bulb swings almost imperceptibly on a rusted wire,
casting an unstable pool of warm amber light on the cracked concrete floor. Puddles hold trembling
reflections of the sign. The camera pushes in with small amplitude at slow speed down the centerline of
the alley, and the graffiti on the left wall slides past the frame edge. Halfway through the shot, a woman
in a soaked dark-green trench coat walks into the frame from the right edge, one hand holding a folded
envelope pressed against her chest to keep it dry. Her shoulders are raised against the cold, her steps
are quick and uneven on the wet stone, and her wet hair is plastered flat to her temples. She stops
directly beneath the swinging bulb and looks up at it. The bulb's light flares across her face and reveals
that her eyes are red-rimmed. She breathes out once, visible as a thin white cloud, and the camera settles
into a static shot. The young woman with a low, breathy voice and a faint Cantonese accent (S1) says at a
slow, unsteady pace: <d>[Chinese] 我等了很久。</d> Her jaw stays slightly open after the last syllable, and
she does not blink.

[Shot 2] At 00:04.200, the shot cuts to an extreme close-up of her two hands from Shot 1 tightening on the
folded envelope, the knuckles going pale, raindrops running down the back of her hand and pooling in the
crease of her wrist. The camera tilts up with small amplitude at slow speed along her forearm to her jaw,
where a single drop travels from her chin to her collar. The wet envelope paper has gone translucent at the
corners; a red ink stamp is faintly visible through the fibre. Her thumb presses and releases the fold twice,
and her breathing quickens enough to fog the frame edge.

[Shot 3] At 00:07.400, the shot cuts back to a medium shot from the same angle as Shot 1, but the alley is
now noticeably darker because the swinging bulb has gone out and only the distant noodle-shop neon remains.
The woman from Shot 1 is still standing in the same position in the same frame coordinates, holding the same
envelope. The camera holds a static shot. She lowers the envelope from her chest to her side, turns her head
slowly toward the neon light at the end of the alley, and takes one step forward. The red neon light lands on
```

## 9. 常见坑清单（照着自查）

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | **裸中文台词** | 模型把提示词正文当台词念出来 | 正文全英文；台词进 `<d>[Chinese] ...</d>`；加「只朗读 `<d>` 内内容」的排除句（§7.1） |
| 2 | **一镜里堆多个大幅度快运镜** | 场景漂移、主体形变 | 一镜一主运镜；用 `small amplitude at slow speed`；切镜换运镜（§7.2） |
| 3 | **想要一镜到底却没写「不要切镜」** | 中途自己切镜 | 显式写 `不要切镜` / `Do not cut`（§7.2） |
| 4 | **上传参考图却不写用途** | 参考被完全忽略 | 每个文件一句「`<Picture 1>` 是人物参考（锁脸）」 |
| 5 | **用文字描述参考图已经锁住的东西** | 脸/服装和参考图打架 | 图能锁的一律不写文字（§5.3） |
| 6 | **说话人 ID 跨镜头变了** | 音色不一致 | 同一说话人全程同一个 `(Sx)`；首次出现必须补足年龄/性别/音高/音色/语速/口音 |
| 7 | **台词前不写说话方式** | 语气随机 | 每句台词前独立写一份完整「语言 + 口音 + 语速 + 音色 + 情绪」 |
| 8 | **对白不承接上一句** | 对话逻辑断裂 | 每句必须直接回答/承接/拒绝前一句 |
| 9 | **`[Shot 1]` 也写了时间戳** | 结构异常 | `[Shot 1]` 不带时间戳；后续镜头写 `At MM:SS.mmm, the camera cuts to` **严格递增**且在时长内 |
| 10 | **`overall_soundscape` 里重复对白** | 声音重复/串音 | 对白/歌声/同步音效只写在 `detailed_description` |
| 11 | **`non_diegetic_music` 写抽象情绪词** | 音乐随机 | 只写配器 / 速度 / 节奏 / 力度变化 |
| 12 | **同时要配乐又禁 BGM** | 结果矛盾 | 二选一；不要 BGM 就 `non_diegetic_music: N/A` |
| 13 | **画面内文字不逐字写** | 出现乱码/错字 | 逐字写出原文，放英文双引号（§6.3） |
| 14 | **长片写超时长** | 动作被截断 | 描述的时间轴总和必须等于请求时长（4–15 秒）；被结尾截断处写 `<cutoff>` |
| 15 | **本地节点不给 `vae` / `audio_vae`** | 参考图/音频保真度骤降 | 接上 VAE；要身份保真就把 `ref_image_size` 设为 `max`（慢） |
| 16 | **`<Video N>` / `<Audio N>` 编号混算** | 标签指向错文件 | 各类型独立 1-based 编号；视频原声占一个 `<Audio>` 号且排在对应 `<Video>` 之前（§5.2） |
| 17 | **零参考图时提示词过短** | 官方记录在案的失败模式 | 至少覆盖：主体外观 + 场景细节 + 动作 + 风格 |
| 18 | **首尾帧模式里写多镜头** | 插值断裂 | FL2VA 天然偏好单镜头，要多镜头必须显式指定；尾帧必须由最后一个 `[Shot N]` 在片尾到达 |
| 19 | **L2VA 让尾帧图出现在 Shot 1** | 逻辑倒错 | `<Picture 1>` 属于最后一个 `[Shot N]`，前面写「合理的前置状态」 |
| 20 | **参考视频只给运镜却标成 `video editing`** | 任务类型错 | 只提供运镜/节奏 → `reference generation` |

## 10. 一页速查卡（贴在 ComfyUI 旁边）

```text
【选骨架】
  纯文生视频 / 单镜头 / 无台词        → 三字段，可以短
  有 <Picture i> / 多镜头 / 台词 / 锁身份 → 六段式（或三字段 + 完整镜头时间轴）

【三字段】
  integrated_multimodal_description: [Shot 1] 风格, 景别, 主体, 场景, 动作, 运镜, 台词 <d>[Chinese]..</d>
  overall_soundscape: 环境音 + 物理音 + 非语言人声（1-4 句，不重复对白）
  non_diegetic_music: 配器 + 速度 + 节奏 + 力度（1-3 句，没有写 N/A）

【六段式】
  subject_definitions: → summary: → retention_analysis: → detailed_description: → overall_soundscape: → non_diegetic_music:

【运镜（自然语言！不是方括号）】
  运动类型 + with small/large amplitude + at slow/fast speed
  一个镜头一个主运镜；中等幅度和常速省略

【台词】
  说话人说明 (S1) 放 <d> 外，台词原文放 <d>[Chinese] ...</d> 内，一字不改
  旁白：says in an off-screen voiceover + 声明嘴唇闭合

【参考图】
  <Picture i> / <Video k> / <Audio j>，各类型 1-based 独立编号
  每张图都要有一句「是 XX 参考（锁什么）」；图能锁的不写成文字

【负面约束】
  全片无声：No dialogue, no singing, no voice-over.
  不要 BGM：non_diegetic_music: N/A
  不要切镜：不要切镜 / Do not cut.
  只读台词：Characters do not speak any line that is not enclosed in <d>...</d>.

【数字】
  时长 4–15 秒整数｜分辨率 768p 或 2K｜帧率 24 fps｜音频 32 kHz 立体声
  提示词上限 7000 字符｜参考：图 ≤9，视频 ≤3（各 2–15s，总 ≤15s），音频 ≤3（总 ≤15s），混合 ≤12 个文件
```
