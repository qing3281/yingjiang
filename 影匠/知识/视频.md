### 1.8 提交 / 轮询 / 失败语义

- 提交 `POST /api/video/generate`（headers `x-feicai-video-operation-id`、`x-feicai-video-semantic-claim`，
  body 是 JSON 字符串，`redirect:"manual"`）；状态 `POST /api/video/generate/status`。
- 超时逐字：`let a = e.includes('-zm-feicai"')||e.includes('-mgdb-15s-feicai"') ? 21e5 : 12e5;`（**210s / 120s**）。
- 轮询逐字：`if(Date.now()-r>3e6) throw …("视频任务超时（50 分钟未完成），任务结果暂时无法确认")`、
  `await new Promise(e=>setTimeout(e,5e3))`（5 秒一次）、
  `signal: AbortSignal.timeout(e.provider==="plugin" ? 33e4 : 3e4)`（**330s / 30s**）、
  连续失败 `a>d.aV` 才抛、`o.kind==="retry"` 时继续、文案 `` `视频任务状态查询连续失败 ${a} 次：${msg}` `` errorKind:"network"。
- **核心经验：超时 ≠ 失败。** 活已经交出去了，钱可能已经花了。影匠 `引擎.提交未知` 同此语义。
- 批量并发逐字：`Math.min(8, e.length)`；状态账本 localStorage `feicai-video-states`；
  参考图 dataURL 序列化**过滤 `idb:` 前缀**（`refImages.filter(e=>!e.url?.startsWith("idb:"))`）。
- 错误码（`KB` 逐字）：积分不足 `(ret=5000)`、内容被过滤 `(fail_code=2038)`、
  权限拒绝 `(ret=3018)`=**即梦 Cookie 过期**、人脸检测 `(ret=4010)`、请求被拒绝 `(ret=1000)`=参数错误、
  `浏览器连接失败`、`未获取到记录ID`。
- **架构真相**：飞彩用 **Playwright 驱动已登录浏览器**打即梦网页接口，不是直调字节 API。

### 2.3 关键设计决策与理由

- **首尾帧走 H3 原生双槽，不重造模型。** 任务书说「用现成的，别重造」。
  本机 `MiniMaxH3ImageToVideo` 原生有 `first_frame` / `last_frame` 两个可选 `IMAGE` 槽，
  不需要外挂 FLF2V。本机也确实有 `loras\minimax_h3_flf2v_lora_v1.safetensors`（147.9 MB），但**不需要它**。
  Wan 侧另有一条 `WanFirstLastFrameToVideo`（`start_image` + `end_image`），作为 fallback 通道保留。
- **不拼 mp4（原判断）→ 已修订：剪辑层走本机 ffmpeg。** 当初的结论是「ComfyUI 所在环境没有 ffmpeg」，
  这是对的（`D:\Comfy-Desktop\ComfyUI-Installs\ComfyUI\ComfyUI` 全树无 ffmpeg）。
  但**影匠自己带了 `D:\DSHworkspace\影匠\_bin\ffmpeg.exe`（6.1.1）** —— 转场是剪辑层的事，不该占显卡，
  所以镜间转场改成 `接片` 走 ffmpeg `xfade`，跟 ComfyUI 彻底解耦。
  ComfyUI 那条 `接龙`（上镜末帧 = 下镜首帧）仍保留：它管的是「生成时就接上」，`接片` 管「已有素材怎么剪」。
- **不写 `模板\*.json`。** 那目录是跨 agent 共享区，写它等于跟别人抢文件。
- **工作流拼装照官方模板接线，一处不改。** 依据
  `……\templates\video_minimax_h3_i2v.json` 的 `definitions.subgraphs[0]`：
  `UNETLoader → LoraLoaderModelOnly(minimax_h3_fl2v_turbo_8step) → BasicScheduler(simple, steps) + BasicGuider(model)
   → SamplerCustomAdvanced(noise/sampler/sigmas/latent) → VAEDecode + VAEDecodeAudio → CreateVideo(fps 24) → SaveVideo`。
- **模型文件名用本机实际名。** 官方模板写的是 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`，
  **本机没有这个文件**；本机是 `minimax_h3_fl2va_pruned_w6a8.safetensors`（15,243.3 MB）。
  视频.py 写的是本机实际名，这是**刻意的偏离**，不是抄错。

### 2.4 规格化的硬事实（都是问出来的，不是猜的）

- H3 尺寸：`width`/`height` 步进 **32**，节点默认 1344×768；`length` 步进 **17**，
  在 **24 fps** 下对齐 **17k+5** 网格（节点 tooltip 逐字：
  `Frame count at 24 fps, snapped up to the model's 17k+5 grid (124 = ~5s; trained range is ~124-362, longer is untested)`）。
  **`min` 是 5，不是 124** —— 124 只是训练区间下限。所以 2 秒 = 56 帧是合法的，
  只是会落在训练区间外（代码发警告，不硬顶用户意图）。
- **length 官方公式逐字**（`video_minimax_h3_i2v.json` 节点 107 的 `ComfyMathExpression`）：

  ```
  max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17
  ```

  验算：2 秒 → `round(48)=48`，`48%17=14`，`(5-14)%17=8` → **56**；
  5 秒 → `120%17=1`，`(5-1)%17=4` → **124**（跟 tooltip 完全一致）。
- Wan 尺寸步进 16 / 帧数步进 4（`4k+1`）；5 秒 @16fps → **81 帧**。
- 尺寸选取规则（`选尺寸()`）：先按长边算理想宽高 → 若超预算（H3 原生画布 1344×768）
  就**等比压进预算**，不是硬丢候选。实测结果：
  16:9 → 1344×768、9:16 → 736×1376、1:1 → 960×960、4:3 → 1024×768、21:9 → 1344×576、
  16:9@1080P → 1920×1088（**恰好整除，不许落成 1888×1056**）。
- 飞彩的 1–30 秒钳制（`Math.max(1, Math.min(30, Math.trunc(e)))`）照搬进 `规整时长()`；
  1080P 上限 11 秒也照搬。

**归一化必做，理由逐字**（`视频.py` 的 `归一视频()` 注释）：
> `xfade` 硬要求同尺寸同帧率，`acrossfade` 硬要求两边都有音轨；不先归一，只会在 `filter_complex` 里炸得莫名其妙。

实现：等比缩放 + 居中补黑边（**不裁内容**，`force_original_aspect_ratio=decrease` + `pad`），没音轨的补 `anullsrc` 静音：

```
ffmpeg -i 入.mp4 [-f lavfi -i anullsrc=channel_layout=stereo:sample_rate=48000 -map 0:v:0 -map 1:a:0 -shortest] \
  -vf "scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2:color=black,setsar=1,fps=FPS" \
  -c:v libx264 -preset veryfast -crf Q -pix_fmt yuv420p -c:a aac -b:a 192k -ar 48000 -ac 2 出.mp4
```

**合成命令形状**（`接片()` 拼出来的，逐字）：

```
ffmpeg -i n00.mp4 -i n01.mp4 \
  -filter_complex "[0:v][1:v]xfade=transition=fade:duration=0.500:offset=4.560[v1];[0:a][1:a]acrossfade=d=0.500:c1=tri:c2=tri[a1];" \
  -map "[v1]" -map "[a1]" -c:a aac -b:a 192k -ar 48000 -ac 2 出.mp4
```

`offset = 前面各段之和 − 前面已扣掉的转场时长之和`；三段以上会链式接
（`[v1][2:v]xfade…[v2]`），音频同理 `acrossfade` 链。**硬切段**用 `concat=n=2:v=1:a=0` / `concat=n=2:v=0:a=1` 插进同一条链。

**踩过的两个 `filter_complex` 坑（都真炸过，逐字留着）**：

| 坑 | 报错 | 根因 |
|---|---|---|
| 1 | `No such filter: ''` / `Failed to set value '[v1][a1]' for option 'filter_complex'` | 把「已搭好的链」和「链末端标签」**当成同一个变量**，循环里 `v链, a链 = v出, a出` 把链本身覆盖成了末端标签，最后 `fc` 只剩两个裸标签 `[v1][a1]`，成了空滤镜名 |
| 2 | `More input link labels specified for filter 'xfade' than it has inputs: 3 > 2` | `v图` 和 `v尾` **都初始化成 `[0:v]`**，第一次迭代拼出 `[0:v][0:v][1:v]xfade=…` —— 输入标签给了三个 |

修法：拆成 `v图/a图`（已搭好的链，初值空串）与 `v尾/a尾`（末端标签，初值 `[0:v]`/`[0:a]`），
每轮 `v图 += f"{v尾}[{i}:v]xfade=…{v出};"`、结束后 `v尾 = v出`。
**教训：`filter_complex` 的「累加串」和「游标标签」必须是两个变量。**
