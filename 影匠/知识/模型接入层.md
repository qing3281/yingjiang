# 模型接入层

> 目录：`接口/`　　入口：`接口/注册表.py`
> 一句话：**把「调哪个模型」从业务代码里剥出来**。导演.py / 剧组.py 只说要什么活，不关心这活是谁干的、怎么干的、跑在哪。

---

## 1. 为什么要有这一层

在这之前，「调模型」这件事是散在业务代码里的：`引擎.文生图(...)` 写死在导演流程里，
想换成云端的豆包，得去改导演的代码。

现在多了一层：

```
导演.py ──> 注册表.挑("文生图") ──> 适配器.元数据()/校验()/buildCreate() ...
                     │
                     ├─ 本地ComfyUI（免费、离线、慢、吃显存）
                     └─ 火山方舟（花钱、要联网、不占本机显卡）
```

业务代码只写**它要什么**（能力 + 提示词 + 参数），接入层负责回答**谁最合适**。
换供应商 = 换一个适配器文件，业务代码一个字不用动。

### 文件

| 文件 | 行数 | 干什么 |
|---|---|---|
| `接口/契约.py` | 715 | 规矩本身。**零依赖**，只用标准库。不含任何供应商 |
| `接口/本地ComfyUI.py` | 860 | 把 `引擎.py` 包成适配器。**只 import 不改它** |
| `接口/火山方舟.py` | 508 | 云端骨架：豆包/Seedream/Seedance 的通用 HTTP 契约 |
| `接口/注册表.py` | 415 | 汇总注册 + 查询 + 自查。**业务代码只该 import 这一个** |

`契约.py` 一行网络代码都没有，`本地ComfyUI.py` 一行 HTTP 都不自己写（全走 `引擎.py`），
这个是刻意的：**越往下越不懂业务，越往上越不懂网络。**

## 2. 契约：一个适配器必须长什么样

### 2.1 必须实现的纯函数

```python
元数据()                 -> dict    # 我是谁、会什么、多少钱（见 2.2）
校验(请求)               -> list[str]   # 有毛病就列出来，**不抛异常**
buildCreate(请求)        -> dict    # 请求 → 提交体（纯拼包，不发送）
parseCreate(响应)        -> str     # 提交响应 → 任务id（同步能力：→ 产物标识）
parseResult(轮询响应)     -> dict    # 轮询响应 → {状态, 产物, 错误, 成本}
```

前四个是**同步能力**的最低要求；能力要是异步的，再加 `parseResult`。
`契约.缺什么函数(适配器)` 会告诉你缺哪个。

### 2.2 元数据

```python
{
  "名称": "本地ComfyUI",              # 必须跟注册名一致
  "能力": ["文生图", "图生视频"],       # 只能从 契约.能力全集 里挑
  "模型": ["wan22_i2v", "zimage_turbo"],  # 支持的模型 id
  "费率": {"zimage_turbo": {"单价": 0.0, "单位": "次", "币种": "CNY", "说明": "..."}},
  "需要联网": False,
  "是否本地": True,
  "异步能力": ["文生图", "图生视频"],   # 可选。列了就必须有 parseResult
  "未验证": ["..."],                  # 可选。自己承认哪些没验过
}
```

`能力全集`（12 个，写死在 `契约.py:193`）：
`文生图 / 图生图 / 图生视频 / 文生视频 / 首尾帧视频 / 配音 / 配乐 / 超分 / 补帧 / 抠像 / 理解 / 翻译`

**`费率.单价` 允许是 `None`** —— 那是「不知道多少钱」的正经表达。
但填 `None` 就**必须**用 `说明` 写清为什么不知道。
逼适配器填数字的话，它只好编一个 —— 编出来的价格比 `None` 危险得多。

### 2.3 可选钩子

有就用，没有就跳过（`契约.py:453`）：

| 钩子 | 签名 | 干什么 |
|---|---|---|
| `预备` | `(请求) -> 请求` | **唯一允许有副作用**的钩子：上传本地图、建会话 |
| `认证` | `() -> dict` | 请求头。密钥只许在这一个函数里出现 |
| `凭证检查` | `() -> {就绪, 缺, 提示}` | 给 `注册表.可用性()` 用。**没配好也不许崩** |
| `解析错误` | `(响应) -> str` | 把供应商的报错翻译成人话 |
| `轮询端点` | `(任务id) -> [提交体]` | 告诉驱动器该 GET 谁 |
| `取回` | `(产物, 存到) -> 本地路径` | 把远端产物落到本机 |
| `成本` | `(响应) -> dict` | 从回包里抠出这次花了多少 |

### 2.4 注册机制

```python
契约.注册(适配器, 覆盖=False)   # 名字重复会拦，除非 覆盖=True
契约.取(名称) / 契约.要(名称)    # 要() 取不到会抛
契约.全部() / 契约.找能力(能力名) / 契约.有(名称) / 契约.名字们() / 契约.清空()
```

### 2.5 path 字段的红线

**凡是键名以 `path` 或 `路径` 结尾的字段，值必须是 `/` 开头、且不是 `//` 开头的相对路径。**

```
/作品/试镜/沈砚_正面.png      ✅
/素材/角色/沈砚/正面.png       ✅
D:\影匠\作品\a.png            ❌ 本机绝对路径
C:/x/a.png                    ❌
\\服务器\共享\a.png            ❌ UNC
//服务器/a.png                ❌ 网络路径
file:///D:/a.png              ❌ 伪装的绝对路径
作品/a.png                    ❌ 没有前导斜杠
/作品/../../秘密.txt           ❌ 上跳目录
https://x.com/a.png           ❌ URL
/作品/a:b.png                 ❌ Windows 非法字符
```

为什么这么严：**绝对路径写进请求体，就等于把「这台机器长什么样」漏给了云端**，
而且换个工作目录就全废了。转换（相对 → 绝对）只发生在最后落地那一下，由适配器自己干。

两道闸：

- `契约.检查路径(请求)` —— 按字段名查，管住「请求」
- `契约.扫描绝对路径(体)` —— 无差别递归整个提交体，管住「任何地方漏进来的盘符」

第二道闸是防呆的：适配器可能把绝对路径塞进一个不叫 `path` 的字段里。
`契约.走一遍()` 和 `注册表.自查()` 都会跑这两道。

## 3. 三段式：异步任务为什么拆成三个函数

一个云端视频任务是这样走的：

```
buildCreate(请求) ──提交──> parseCreate(响应) ──轮询 N 次──> parseResult(轮询响应)
     拼包                     拿任务id                        看好了没
```

拆成三段，不是为了好看，是因为这三段的**失败方式完全不同**：

| 段 | 干的事 | 失败了意味着什么 | 能不能重试 |
|---|---|---|---|
| `buildCreate` | 拼请求体 | **肯定没花钱**。本地拼错了而已 | 随便重试，改完再拼 |
| `parseCreate` | 认任务号 | **可能已经花钱了**。请求可能送达了，只是我没认出回包 | 重试前先去控制台查 |
| `parseResult` | 认结果 | 前两种都可能。要看状态 | 看状态说话 |

如果三段揉成一个 `调用()` 函数，调用方就**分不清**「我拼包错了」和「云端已经扣费了但回包没认出来」——
而这两件事一个可以无脑重试，另一个重试就是白烧钱。

拆开之后，`buildCreate` 是**纯函数**：给它同一个请求，永远拼出同一个提交体，
不发网络、不读时钟、不写文件。所以它可以离线测、可以 diff、可以缓存。
**本次交付的 92 项自测里，绝大部分就是靠这一点离线跑完的。**

还有一条约束：`buildCreate` 不许有副作用，那「上传本地图拿一个 URL」放哪？
放在**可选钩子 `预备(请求) -> 请求`** 里，它是唯一允许有副作用的钩子，
而且它在 `buildCreate` 之前跑 —— 它上传完，把拿到的名字塞进请求，`buildCreate` 再照着拼。

> `本地ComfyUI.py` 就是这么干的：`预备()` 调 `引擎.上传图()`，把 ComfyUI 给的文件名
> 放进请求的 `_图名`，`buildCreate()` 只管把这个名字写进工作流的 `LoadImage` 节点。
> 这样「上传」这件事能被单测 stub 掉，拼包逻辑依然纯净。

## 4. 状态映射表

本项目的状态只有五个：`排队 / 运行 / 完成 / 失败 / 未知`。
`契约.归一(供应商的原始状态)` 负责翻译，认不出来的一律 → **未知**。

公共别名表（`契约.py` 内置，各供应商还能给自己的私有表）：

| 供应商原始状态 | 本项目 | 备注 |
|---|---|---|
| `queued` `pending` `排队中` `in_queue` `waiting` | **排队** | |
| `running` `processing` `执行中` `generating` `in_progress` | **运行** | |
| `succeeded` `success` `completed` `done` `完成` | **完成** | |
| `failed` `error` `cancelled` `canceled` `失败` | **失败** | |
| `timeout` `超时` `connection reset` `502` `503` `bad_gateway` | **未知** | 请求**可能已送达** |
| `task not found` `not_found` `查不到` `expired` `结果过期` | **未知** | 活可能干过、钱可能扣了 |
| `""` `None` `供应商发明的新状态` | **未知** | 认不出就别乱猜 |

### 「未知」的定义（这块是重点）

> **请求可能已送达，但结果无法确认 —— 必须映射成「未知」，而不是「失败」。**

为什么这条值得单列：

- 判**失败** → 上层逻辑会**重跑** → 重跑 = 再扣一次钱 / 再烧一次显卡
- 判**未知** → 上层逻辑去**查** → 查一下不要钱

「超时」「502」「task not found」「expired」全都是这一类：
你以为失败了，其实云端那一单可能正在跑，或者已经跑完了、链接过期了而已。

所以：

- `契约.是终态(未知) == False` —— 未知**不是**终态，它要求人去查，不是收工
- `契约.可疑未知(原始状态)` 单独暴露出来，让上层能问「这个状态是不是那种『说不清』的」
- 空状态 / `None` 也算可疑未知

### 供应商私有表怎么加

```python
状态表 = {
    "queued": 契约.排队, "running": 契约.运行,
    "succeeded": 契约.完成, "failed": 契约.失败,
    # 这三个是重点：东西可能已经生成过，只是这条回包证明不了 → 未知，不是失败
    "expired": 契约.未知, "timeout": 契约.未知, "not_found": 契约.未知,
}
翻 = 契约.归一(原始状态, 状态表)   # 私有表 → 公共表 → 子串兜底 → 未知
```

### 「完成了个寂寞」怎么办

供应商说 `succeeded`，但回包里一个产物都没有。这时**判未知，不判失败**：
活多半已经干完、钱也扣了，只是这条回包的字段名跟文档不一样。
错误话术里会明确写「**别急着重跑（重跑 = 再扣一次），先去控制台按任务id 查一眼**」。

反过来，本地 ComfyUI 报 `status_str == "success"` 但 `outputs` 是空的 —— 这个**判失败**。
区别在于：本地跑不花钱、重跑没有代价，而且「跑完了没产物」在本机是**真·配置错误**
（SaveImage 没接对）。**同样是「说成功但没东西」，云端算未知、本机算失败，因为重跑的代价不一样。**

### 第 2 步：想清楚它是同步还是异步

- 异步（交任务 → 轮询）→ 要 `parseResult`，且 `异步能力` 里要列上
- 同步（一次请求一次回包）→ 不用 `parseResult`，
  这时 **`parseCreate` 返回的是产物标识**（一个 URL / 一个文件名），非空即视为完成

### 第 3 步：三个函数

```python
def buildCreate(请求):

        raise ValueError("请求不合格：" + "；".join(问题))
    return {
        "端点": "/v1/video/tasks",       # 必须 / 开头（不许写完整网址）
        "方法": "POST",
        "体": {"model": 请求.get("模型id"), "prompt": 请求["提示词"]},

    """认任务号。**认不出来必须返回空串**，不许抛 —— 抛出去上层就不知道该不该重试了。"""
    if isinstance(响应, dict):
        return str(响应.get("task_id") or "")
    return ""

def parseResult(轮询响应):
    """一律返回四件套，且**这个函数不许抛异常**。"""
    ...  # 见下一段
```

`parseResult` 的返回永远是这四样：

```python
{"状态": 契约.完成 | 契约.失败 | 契约.未知 | 契约.排队 | 契约.运行,
 "产物": [{"类型": "视频", "路径": "https://...", "临时链接": True}],
 "错误": "给人看的一句话",
 "成本": {"金额": 1.35, "币种": "CNY"}}
```

判断顺序建议照抄火山方舟（`接口/火山方舟.py:379`）：

1. **先看产物**：解析出东西了就是完成，不管 `status` 字段写没写（各家写法不一致）
2. **没有 status 也没有产物** → 未知（认不出这个任务怎么了）
3. **归一成失败** → 失败，带上人话
4. **归一成未知** → 未知，话术里写明「别急着重跑」
5. **归一成完成但没产物** → 未知（完成了个寂寞）

## 6. 业务代码怎么用

```python
import 注册表
注册表.装载()

# 我要一次图生视频，谁便宜谁上，本机优先
```

## 8. 无法自证的点（如实列，别当已验证）

这一节是**这个交付里最该看的一节**。下面每一条都是「看起来能用」，但**没有证据**：

### 火山方舟：一次真实调用都没跑过

本机没有 `ARK_API_KEY`，也不许拿真 key 去试。所以：

- **真实鉴权头对不对** —— 按官方文档推的 `Authorization: Bearer $ARK_API_KEY`，没跟真实回包比对过
- **返回体字段名对不对** —— `content.video_url` / `data[].url` / `usage.generated_images` 全是照文档抄的
- **状态表的 `expired` / `not_found` 映射** —— 是按「可能已扣费」的逻辑推的，不是线上事故复现的

也就是说：**「未知」这条语义，验的是映射逻辑（伪造响应），不是真实故障场景。**
它现在证明的是「如果供应商这么说，我们会这么判」，不是「线上真出这事时我们判对了」。

### 火山方舟：图生图 / 图生视频的图片入参是断的

方舟要公网可访问的图片 URL，本机没有上传通道。`buildCreate` 会把 `image` 留空并写警告 ——
**这是「明确地断着」，不是「能用」。** 要接上，得先有对象存储或者图床。

### 火山方舟：费率一律 `None`

没去查价，不敢编数字。`注册表.报价()` 对云端会老实返回「不能确定」。

### 本地ComfyUI：`qwen_edit.json` 没接入

`模板/qwen_edit.json` 是**图生图**（`QwenImageEditPlus`），本次没接。
所以 `元数据()["未接入的模板"]` 里会看到它。能力列表里没有「图生图」。

### 真跑只覆盖了文生图

图生视频（Wan 2.2 5B）耗时长、当时显存只剩 3.3GB，本次未真跑。
**它的拼包逻辑验过（伪造响应），「ComfyUI 真能收下这个提交体」没验过。**

### 未接入的：`配音` / `超分` / `补帧` 等能力

`能力全集` 里列了 12 个能力，实际只有 3 个有适配器认领（文生图 / 图生视频 / 图生图-云端未通）。
`配音.py`（IndexTTS）**还没有包成适配器**，这是个明显的下一步。

### 没有的东西

- 没有重试策略、没有退避、没有超时预算 —— 这一层只负责「翻译」，不负责「调度」
- 没有并发控制、没有队列 —— 本机 ComfyUI 一次只该跑一个
- 没有成本累计 / 预算熔断 —— `成本` 字段抠出来了，但没人拿它做判断
- 没有真实的多供应商回退：`注册表.挑()` 只是「本机优先」，本机挂了**不会**自动切云端
