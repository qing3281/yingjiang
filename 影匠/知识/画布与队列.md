## 0. 一句话

飞彩的画布是一张**有类型的管线图**：节点有入/出端口，端口带 `dataType`，**连线只有在「上游出端口类型 == 下游入端口类型」时才合法**——连错了根本连不上，不用等跑起来才发现。影匠原来只有一条写死的流水线（导演 → 引擎 → 剧组），画布把这条线变成**数据**。

飞彩的队列解决的是另一件事：**浏览器刷新、断网、模型挂掉、限流之后，那些「钱可能已经花出去」的调用怎么办**。它的答案是四层账（内存 → IndexedDB → 业务账本 → 服务端）+ 一条铁律：**终态未知绝不自动重试**。

## 2. 画布 · 飞彩原样

### 2.1 节点对象（逐字）

```js
{ id, type:"module", position:{x,y},
  data:{ moduleId, moduleName, category, color,
         status:"idle"|"queued"|"running"|"success"|"error",
         params:{...},
         inputs:[{id,label,dataType,direction:"input"}],
         outputs:[{id,label,dataType,direction:"output"}] } }
```

组节点是 `type:"group"`，另带 `width`/`height`/`zIndex:0`，`data.moduleId:"builtin:group"`，`data.moduleName:"新建组"`，`params:{_groupId,_groupColor,_groupName}`。组 id 形如 `` `group-container-${Date.now()}-${rand4}` ``，成员靠 `params._groupId`/`params._groupColor` 认亲。组的存在感仅限视觉——见 2.2。

**节点状态枚举（两处独立证据）**：

- `8703...js @357180`：`ek="queued"===t.status||"running"===t.status`（这两个状态下节点被禁用）
- `7528...js @88397`：`f="running"===t.status, g="success"===t.status, v="error"===t.status`
- 新建节点带 `status:"idle"`

→ 取值集合 = `{idle, queued, running, success, error}`。`idle` = 从没跑过，`queued` = 已入队没开跑。

### 2.2 拓扑分层（逐字，`8703...js` 的 `n(e,t)`）

```js
function n(e,t){
  let a=new Set(e.filter(e=>"group"!==e.type).map(e=>e.id)), r={}, n={};
  for(let e of a) r[e]=0, n[e]=[];
  for(let e of t) if(a.has(e.source)&&a.has(e.target)) r[e.target]=(r[e.target]||0)+1, n[e.source].push(e.target);
  let s=[], o=Object.keys(r).filter(e=>0===r[e]);
  for(;o.length>0;){ s.push([...o]); let e=[];
    for(let t of o) for(let a of n[t]||[]) { r[a]--; if(0===r[a]) e.push(a); }
    o=e; }
  if(s.reduce((e,t)=>e+t.length,0)<a.size) throw Error("工作流中存在循环依赖，无法执行");
  return {layers:s, totalSteps:a.size};
}
```

五条语义，影匠一条不改地照抄：

1. **`type === "group"` 的节点不参与图**（组只是画框）。
2. 入度加在 `target` 上，邻接表是 `source → target`。
3. 结果是**分层**的（`layers` 是数组的数组）——同一层可以并发。
4. **孤立节点入度 0，自己成第一层**，永远不会被丢掉。
5. 环检测 = 「吐出来的节点数 < 总节点数」，抛的字符串逐字是 `工作流中存在循环依赖，无法执行`。

### 2.3 边形状 + 数据键解析（逐字）

边是 `{id, source, target, sourceHandle, targetHandle, data?:{sourcePort?, targetPort?}}`。`data.targetPort`/`data.sourcePort` **优先于** handle（React Flow 的 handle 是渲染层，`data.*Port` 是语义层）。

```js
// 端口解析 n_(e,t,a) = 边, 本节点 inputs, 兜底 dataType
let r = "string"==typeof e.data?.targetPort && e.data.targetPort ? e.data.targetPort : e.targetHandle,
    n = t.find(e=>e.id===r) ?? (a ? s(a,t) : void 0);
return {port:n, dataKey:n?.id || r || "input"};

// 取值 qg(e) = 节点 data

    || ("builtin:text-input"===e.moduleId ? e.params?.prompt : "") || "";

// 建上游数据 N5(e,t,a) = 入边, id→节点, 本节点 inputs
function d(e,t,a){ let n={};
  for(let s of e){ let e=t.get(s.source); if(!e) continue;
    let o=i(e.data); if(!o) continue;
    let d=e.data.outputs[0]?.dataType||"any", c=l(s,a,d), u=c.port??r(d,a);
    n[c.port ? c.dataKey : (u?.id||c.dataKey)] = o; }
  return n; }

// 合并 hY(e,t,a,r,n)：先算新 key 集合，然后**新值覆盖、旧 key 删除**
// cT(e,t) 浅比较：key 数量一样且每个 key 严格相等 → 才认为没变（省一次写回/重渲染）
// l0(e,t,a)：找**别的**节点上是否已经有同一个产物（判据 result.outputUrl===t || params.file===t）
```

要点：值被写进 `node.data.upstreamData[dataKey]`；`dataKey` 默认取解析出来的目标端口 id，兜底字面量 `"input"`。`hY` 的**删除**语义是动态端口（每镜一根线）能用的关键——下游端口没了，旧数据必须跟着消失，否则会拿上一镜的图去跑这一镜。

第二现场（`@166927`）补一条：源端口若在 `outputsByHandle` 里（或节点有动态 `out-n<i>-*` 端口），值取自 `outputsByHandle[handle]`，**空值直接 `continue` 跳过**；否则 `text` 类型的入端口优先吃 `outputText`，非 text 优先吃 `outputUrl`。

### 2.4 连线校验器（逐字，`7528...js @197281`）

```js
function r5(e,t,r){                     // e=节点表, t=源{nodeId,portId}, r=目标{nodeId,portId}
  let a=e.find(e=>e.nodeId===t.nodeId), n=e.find(e=>e.nodeId===r.nodeId);
  if(!a||!n||a.nodeId===n.nodeId
     ||!Object.hasOwn(r2,a.moduleId)||!Object.hasOwn(r2,n.moduleId))return!1;
  let i=r2[a.moduleId].outputs, s=r2[n.moduleId].inputs,
      o=i[t.portId], l=s[r.portId];
  return "string"==typeof o && o===l
}
```

四条规则：

1. 两端节点都得在。
2. **不许自环**（`a.nodeId===n.nodeId`）。
3. **两端模块都必须在 `r2` 里**——不在契约表里的模块，连线一律拒绝。
4. 合法性 = **`outputs[portId] === inputs[portId]` 严格字符串相等**。这条闸门里**没有 `any` 兜底**（宽松的类型匹配在渲染路径 `PP`/`r()` 里，不在闸门里）。

端口契约表 `r2`（`Object.freeze`，**只有 4 个 id**）：

```js
"builtin:text-input":     {inputs:{"in-text":"text","in-image":"image","in-video":"video"},                      outputs:{"out-text":"text"}},
"builtin:smart-image":    {inputs:{"in-image":"image","in-ref":"image","in-text":"text"},                        outputs:{"out-image":"image"}},
"builtin:smart-video":    {inputs:{"in-text":"text","in-image":"image","in-image-last":"image","in-video":"video"}, outputs:{"out-video":"video"}},
"builtin:seedance-video": {inputs:{"in-text":"text","in-image":"image","in-video":"video","in-audio":"audio"}, outputs:{"out-video":"video"}}
```

`r1 = new Set(["builtin:text-input","builtin:smart-image","builtin:smart-video","builtin:seedance-video"])` —— 正好是 `r2` 的 4 个键。
端口类型词表：`text | image | video | audio | any`。

> 旁证：打包进来的 `@xyflow/react`（`1a258343-2e0bb13192d21ed5.js`）默认 `isValidConnection` 返回 `true`（没给校验器时一律放行），该 chunk 里 `concurren|maxConcurrent|并发` **零命中** —— **React Flow 本身没有并发概念**，闸门是飞彩自己加的。

### 2.6 改动审批契约（逐字，`7528...js @214034-218958`）

提案一律带 `{schemaVersion:1, costCents, approvalRequired, runNodes, evidence, mutation}`，且 `approvalRequired === true`、`costCents` 是 `[0,800]` 的安全整数；`evidence` 要 `canvasRevision`(`/^[0-9a-f]{64}$/`)、`evidenceDigest`、`selectionInstanceId`、`selectionVersion`、`node`/`nodes`。

`mutation.kind ∈ {set_params, connect, auto_layout, create_reference_extractors}`，**四种全都要求 `costCents === 0 && runNodes === false`**——**改画布永远不花钱**。

- `connect`：当场过 `r5`，且 `[source.nodeId, target.nodeId].sort()` 必须等于 `evidence` 里节点的顺序。
- `auto_layout`：`nodeIds` 与 `positions`（`{nodeId,x,y}` 有限数）1:1，长度 2..64。
- `create_reference_extractors`：每个 `sourceNodeIds` 必须是 `builtin:text-input`，`estimatedCents === (runAfterCreate ? a : 0)`，`runNodes === mutation.runAfterCreate`，`costCents === mutation.estimatedCents`。
- 提示词改写变体的摘要逐字：`修改当前选中的一个画布节点提示词，零费用，等待用户批准`，要求 `costCents===0`、`runNodes===false`、prompt 2..20000 字节。

### 3.2 影匠自创的部分（**明确标出来**）

这些飞彩**没有**，是影匠自己加的，用 `工程.定义()` / `python 画布.py 定义 <id>` 能当场列出来：

4. **`定义()` 差异清单本身** —— 飞彩没有这个自省能力。
5. **`收产物()` 落素材库** —— 飞彩走 `syncAssetToLibrary()` + `/api/workspace-file`（HTTP）；影匠直接调 `一致性.建()` / `一致性.绑定()`（同进程）。
6. **`_跑_直通()` 的如实报错** —— 18 个模块影匠只有定义没有执行器，调用一律抛一句人话（「报错好过假装跑通」）。飞彩这些模块是真能跑的（定义在服务端/别的 bundle 里）。

## 4. 队列 · 飞彩原样

### 4.1 飞彩真的任务队列（`5209...js` webpack 模块 `9223`，源码在 `_work\rh任务队列.js`）

- IndexedDB 库名 `"feicai-rh-task-queue"`，**版本 2**；store `"rh-tasks"`；`createObjectStore(n,{keyPath:"taskId"})` —— **主键是 `taskId`**。
- 两个非唯一索引：`createIndex("state","state",{unique:!1})`、`createIndex("canvasId","canvasId",{unique:!1})`。
- 导出：`UT`=put/upsert、`lC`=按 taskId 打补丁（get → `{...e,...t}` → put）、`be`=取待办（`getAll(IDBKeyRange.only("queued"))` + `only("running")` 拼起来；索引不在时退回全量 `getAll()` 再用 `"queued"===e.state||"running"===e.state` 过滤）、`JG`=启动 GC。
- **状态枚举逐字：`"queued"`, `"running"`, `"success"`, `"failed"`, `"cancelled"`**；GC 的终态集正好是 `success|failed|cancelled`。
- **记录字段逐字：`taskId`, `state`, `canvasId`, `projectId`, `submittedAt`, `finishedAt`**。列表过滤 `t.projectId===e||void 0===t.projectId` —— **没有 projectId 的任务对所有项目可见**。
- **保留/GC 逐字**：`c(e=7)` 删掉 `r.finishedAt||r.submittedAt||0` 早于 `Date.now()-24*e*36e5` 的终态任务（默认 **7 天**，`openCursor()` 游标删）；`p(e=6048e5)` 每次页面加载只跑一次（模块级 `d`/`f` 把关），失败时 `console.warn("[rh-task-queue] startup GC 失败，下次启动重试:", e)` 并返回 `0`（下次启动重试）。
- 降级契约：`s()` = `!!window.indexedDB`；每个入口在 IndexedDB 不可用时**静默返回**（`return;` / `return []` / `return 0`）；`i()` 缓存打开的 promise，`onversionchange`/`onclose`/`onerror` 时重置，错误路径 `reject(new Error("IndexedDB not available"))`。

### 4.2 每身份并发闸门（`2703-90569494d1040531.js @~86908` 逐字）

- Map 的键 = **trim 过的队列身份字符串**；上限写死 **30**；`waiters` FIFO。

### 4.5 失败分类 / 重试策略（飞彩的铁律）

核心判据是**区分「确定失败」和「终态未知」**：

| 情形 | 飞彩处置 | 原话 |
|---|---|---|
| 参数错误 / 明确 4xx | **不发请求、不重试** | 「本次没有发出任何请求，不会产生费用」 |
| 明确失败（上游 200 带错误体 / 明确 5xx） | 可重试 | 27 处「自动重试」 |
| **终态未知（超时 / 网络断 / 响应不是合法 JSON）** | **绝不自动重试** | 「该次请求可能已计费，已停止自动重试，请手动重试」 |
| 校验失败 | 不重试 | — |
| 实例级失败 | 换实例，不原地重试 | 「本次未自动重试，请手动更换模型后再试」 |
| 旧版断点 | 标悬空，不迁移不重试 | 「检测到旧版自动化断点（schema N），已标记为悬空」 |

承载「终态未知」的错误类是 `class d extends Error { this.indeterminate = true; this.chargedUnknown = true }`。
超时兜底原话：「视频任务超时（50 分钟未完成），任务结果暂时无法确认」——**50 分钟是实测硬阈值**。
成本预告原话：「本次确定新增 LLM 调用 N 次，执行并发上限为 3；账本查询与任务续查不会新调用模型。」
降级原话（12 处）：`图片保存失败，使用 data URL 降级`、`视觉分析跳过（降级）`。

### 5.2 两道闸的分工（**自创说法，机制是实测的**）

飞彩是浏览器单进程、库在 IndexedDB 里，**没有跨进程问题**。影匠是 CLI + MCP + 多进程，所以必须自创这一层：

| | 全局闸门 | 每身份闸门 |
|---|---|---|
| 谁 | `账本.领取()/释放()` | `队列.进程闸()` |
| 单位 | 整个账本（默认上限 1，可配） | 一个**身份**（默认 30，飞彩原值） |
| 落在哪 | SQLite（跨进程真闸） | 进程内 `Map`（同进程排队） |
| 满了怎么办 | 抛 `闸门满`，任务**留在「排队」** | 进 FIFO 等待 |

两者都在 `跑一条()` 里过一遍；`闸门守`（`with` 上下文管理器）是影匠自创的糖，保证**出块就放、异常也放**（实测：块里抛异常也不漏槽）。

### 5.3 队列自创的部分（**明确标出来**）

1. **每身份闸门的上限可配** —— 飞彩写死 `30`，影匠 `进程闸(上限=30)` 可传。
2. **`闸门守` 同步上下文管理器** —— 飞彩是 `Promise` + 释放闭包。
3. **次数上限那层** —— 账本原话「只给建议，不给次数上限」，调用方决定；`队列.策略()` 默认 6 次。
4. **`指定实例` 前置校验** —— 飞彩只在 `project` 作用域查「实例在不在清单里」，legacy 作用域不查；影匠把这条**提到作用域判断之前**统一查，理由是那两句原话的用意就是「在供应商请求前停止」。
5. **`跑一条()` 的收尾流程** —— 飞彩的四层账（内存 → IndexedDB → 业务账本 → 服务端）在同进程里被压成一条：成本预告 → 落账 → 双闸 → 派活 → 分类 → 重试/换实例/未知 → 收尾。
6. **`换实例/重试` 要换一条新账** —— 账本的 `重试()` 是**开新任务**（重试链留着），不是把旧账拨回「排队」。所以循环必须换 id，否则下一次「领取」会撞在 `任务 X 现在是「失败」，只有「排队」的才能领取。` 上。这条是修 bug 时定的，飞彩那边对应的是 `[id]/submissions`（一条操作可多次提交）。

### 5.4 队列**没落**的部分（诚实清单）

| 飞彩有 | 影匠状态 | 为什么 |
|---|---|---|
| 四层账（内存/IndexedDB/业务账本/服务端） | **单层**（SQLite 账本） | 影匠没有浏览器、没有服务端。飞彩「L2 丢了能靠 L3 重建」的能力在影匠这里没有对应物。 |
| 启动 GC（7 天保留，失败下次重试） | **没落** | 账本的保留策略由人决定，不做自动删（删账比留账危险）。 |
| `[RhKeyPool]` 真 Key 槽（退休/强制回收） | **只有实例轮转** | 影匠没有 RunningHub 账号池；`轮转()` 转的是**实例 id**，不是 key。 |
| 租约心跳（`owner-liveness`） | **没落** | 影匠没有长驻 worker 需要心跳。 |
| `withdraw`/`submissions` 多次提交语义 | **没落** | 对应 `账本.重试()` 的新任务链，但没实现「同一操作多次提交」的显式 API。 |

## 7. 这个模块**不能自证**的东西（诚实清单）

1. **画布没跑过一次真的出图/出片**。`自查` 全是干跑（`干跑=True` 不发任何网络请求）和打桩执行器。真跑要 ComfyUI 在线，而本机 `http://127.0.0.1:8188` 现在**连不上**（`_查现场.py` 实测 `[WinError 10061] 由于目标计算机积极拒绝`）。
2. **18 个节点模块只有定义没有执行器** —— 调用会如实报错，不会假装跑通。这是**设计选择**，不是遗漏：飞彩那些模块的定义在服务端/别的 bundle 里，影匠没有对应的上游。
3. **`自动布局` 的位置算法是影匠编的**。飞彩的布局算法没挖到（`auto_layout` 只接受现成坐标）。
4. **`能连吗()` 对 20 个非 `r2` 模块放宽了**（端口存在 + 类型相等）。飞彩的闸门只认 4 个模块，一律拒绝其余。**这是偏离，不是照抄**。
5. **画布「代次」乐观锁没在拦人** —— 字段、盐、正则都在，但没有服务端去比对，所以迟到结果目前只靠 `_该写回()` 这个桩。
6. **队列的跨进程闸门只压过 4 个进程**（账本自查里），**没测网络盘**。
7. **`[RhKeyPool]` 的真 Key 槽没有实现** —— 影匠只有实例轮转，没有账号池。
8. **成本预告的数字来自账本的实测均值/基线**，不是供应商报价。`接口\火山方舟.py` 的费率一律 `None`（没查价，不敢编数字），所以影匠的「元」是**电费口径**（600W × 时长 × 0.56 元/度），不是账单口径。
9. **飞彩的 `.next\static\chunks\9876543210-*.js` 没动**（加密包，红线）。
10. **`画布.py` 里的 `_work` 自测会往 `作品\_画布` 写工程文件**；`队列.py 自测` 用 `tempfile` 建临时账本，**不碰真账本**。

## 8. 一页速查

```
画布 = 有类型的管线图
  节点 {id,type,position,data:{moduleId,status,params,inputs,outputs}}
  状态 idle | queued | running | success | error
  边   {source,target,sourceHandle,targetHandle,data:{targetPort?}}
  连线合法 ⇔ 上游 outputs[口] === 下游 inputs[口]（严格相等，无 any 兜底）
           且 两端模块都在契约表里，且 不是自环
  执行顺序 = 拓扑分层（group 不参与；孤立节点自成一层；有环抛「工作流中存在循环依赖，无法执行」）
  并发 1-30（原话「画布执行并发必须是 1-30 的整数」）
  改画布永远零费用（costCents===0 && runNodes===false）
  上游失败 → 下游「上游 XXXXXX 失败,已跳过：<错前80字>…」

队列 = 双闸 + 分类 + 有限重试 + 换实例 + 降级
  全局闸  账本.领取()/释放()     单位=整个账本，默认 1，跨进程，满了抛「闸门满」且任务留在「排队」
  每身份闸 队列.进程闸()          单位=身份，默认 30（飞彩原值），FIFO，释放幂等，归零删
  实例     轮转 = 30 槽 t % 实例数；故障转移 = 实例级失败换一台，不原地重试
  分类     转发账本；认不出的错 = 最保守（未知，不自动重试）
  铁律     终态未知 → 绝不自动重试（可能已经计费）；明确失败才退避重试
  收尾     成本预告 → 落账 → 双闸 → 派活 → 分类 → 重试/换实例/未知 → 收尾（不留半路状态）
```

**影匠自创清单（一句话）**：自动布局的算法、`能连吗()` 对非 `r2` 模块的放宽、同步执行、`定义()` 自省、落素材库走同进程、18 个模块的如实报错、每身份闸门上限可配、`闸门守` 糖、次数上限那层、`指定实例` 前置校验、`跑一条()` 的单层收尾、`换实例/重试` 换新账。其余字段名、枚举、原话、公式、契约表**全部照抄**。
