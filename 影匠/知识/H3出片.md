# H3 出片 —— 治「像看图片」和「动作不连贯」的那把刀

> 2026-10-14 落地。用户抱怨的两件事：
> **「怎么像看图片一样」**、**「动作不连贯」**。
> 根因是同一个：**`wan2.2_ti2v_5B_fp16` 是个 5B 的小模型**，它只会把首帧往前推
> 一点点 —— 所以看着像静帧。换成 MiniMax-H3（原生 AV 大模型）之后，
> 头真的会转、嘴真的会动、雨真的在下。

## 三、★ 三条硬约束（都是踩过报错的）

### 1. 宽高必须能被 32 整除

```
ValueError: MiniMax H3 width and height must be divisible by 32
```

`720` **不是** 32 的倍数 → 报错；`704` 是 → 通过。
所以《觉醒》用 **1280×704**（不是 1280×720）。

### 2. 帧数必须在 17n+5 网格上

节点 tooltip 原文：`"24fps; snapped up to the 17n+5 H3 grid"`，`step` 是 **17**。

合法值：5, 22, 39, 56, 73, 90, **107**, **124**, 141 …

**★ 109 不在网格上** —— 它会被**悄悄吸附到 124**（5.1667 秒），
日志不报错、节点不报警，**只有拿 ffmpeg 量成片时长才发现**。
74 格会从 4:53 变成 5:46。

用 **107**（= 17×6+5 → 107/24 = **4.4583 秒**）。

### 3. 必须 8 步，不能降到 4 步提速

```
ValueError: profile 'turbo_standard8' requires 8 steps, got 4
```

`MiniMaxH3AVSigmaSameNFERedistributionT8Advanced` 的 `profile` 只接受：
`turbo_standard8` / `turbo_ema8` / `turbo_fl2v8` / `stock20` / `custom_strict`
—— 名字里带 8 的就得 8 步。

## 四、工作流怎么写的（`_出H3.py` 的 `建图`）

14 个节点的 API 格式工作流。关键节点与签名：

### `MiniMaxH3AudioConditioningT8`

**必填**：`clip` / `video_vae` / `audio_vae` / `prompt` /
`width`（step 32，default 1344）/ `height`（step 32，default 768）/
`length`（step 17，default 124）/ `task_type` / `audio_mode` /
`audio_denoise_strength` / `add_source_as_reference` /
`prompt_primary_audio_ordinal` / `strict_prompt_tags` /
`ref_image_size` / `reference_video_policy`

**可选（★ 这才是本事所在）**：
- **`first_frame` + `last_frame`** → **镜头衔接**（flf2v）的工具
- `ref_images`（最多 **9** 张）、`ref_videos`（最多 3）、`ref_audios`（最多 3）
- `drive_audio` / `final_audio` / `semantic_bridge`

`task_type` 取值：`auto` / `T2VA` / `I2VA` / `FL2VA` / `L2VA` / `Ref2VA` / `Hybrid`
`audio_mode` 取值：`lock_source` / `remix_source` / `reference_only` / `native`

### `MiniMaxH3DualClockSamplerT8`

**必填**：`model` / `av_latent` / `steps`（default 4）/ `shift_video`（default 12.0）/ `shift_audio`（default 3.0）
**可选**：`sampler_name`（默认 `dual_clock_euler`）/ `scheduler`（默认 `native_flow`）

## 八、为什么没让远端分担（算过账）

远端 `100.127.224.106` 一台上一个 H3 模型都没有（只有 wan2.2 和 z_image_turbo）。

- H3 最小集 ≈ **65 GB**；全 15 个文件 **228.89 GB**
- **`scp` 实测 2.7 MB/s** → 65 GB 要 **6.8 小时**，全传 **24.1 小时**
- Tailscale 已经是 **direct**（`direct [2409:...]:41641`），不是中转
  —— **2.7 MB/s 就是线路真实上限，改配置没用**
- **传 6.8 h vs 本机自己跑完 3.3 h** → 不搬

唯一快法：拿 U 盘拷过去。规矩仍是「远端只出算力，模板/提示词/种子/模型全由本机定」。
