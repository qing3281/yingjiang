#### 3.3.1 ★★【实测·已修】「按名字点音色」曾经根本点不准 —— 两个叠在一起的 bug

这是本次最值钱的一个发现：**两个 bug 各自都不报错，合起来让「角色→音色」这条链路完全不可用。**

**Bug ① · 名字被 `-` 截断（`音色库.py:112 _人名()`）**

原写法是「按第一个 `-` 切开取左边，长度 ≤12 就用」：

```python
for 分 in ("-", "—", "_", "–"):
    if 分 in s:
        左 = s.split(分, 1)[0].strip()
        if 0 < len(左) <= 12:
            return 左      # ← 就是这里
```

于是实测出来：

| 文件名 | 旧 `名字` | 后果 |
|---|---|---|
| `女-常规-清冷无情-2-1.wav` | **`女`** | 唯一有用的「清冷无情」被丢掉 |
| `男-常规-清冷无情-3-1.wav` | **`男`** | 与上面只差一个字 |
| `人物——叶修.WAV` | **`人物`** | 真名「叶修」被丢掉 |
| `01.wav`（一堆） | `01` | 完全无意义 |

**中文音色文件名里的 `-` 是结构分隔符，不是「名字-描述」的分界** —— 不能按它切。
修法（保守，只在明显无意义时才改写）：优先「占位符——真名」取右边；有料就整段当名字（**长名字也比重名强**）；纯序号才借父文件夹名。

**Bug ② · 兜底匹配把「每字都出现」也算命中（`配音.py:230`）**

```python
elif all(字 in 干 for 字 in 词):   # 最弱的一级，但排序时和真命中混在一起
```

查 `女-常规-清冷无情-2-1` 时，`男-常规-清冷无情-3-1` 的**每个字都出现过**，于是被算作命中；
而这一级和前面几级**合并后统一按时长降序**，7.84 秒的男声就排到了 4.77 秒的女声**前面**。

→ **查女声返回男声。** 这比报错危险得多：结果看起来完全合理，不核对就用了。
修法：改成**严格四级**（名字完全等于 → 名字/文件名包含 → 路径/标签包含 → 每字出现），
`甲+乙+丙+丁` 拼接后再各自按时长排序 —— **兜底那级永远排在真命中后面**。
同一处逻辑在 `音色库.py --查` 里也一样改成四级。

**Bug ③（连带发现）· 无法「指名道姓」点一条音色**

模糊匹配再准也只是「比较像」。剧本里写「凌霜 → A 组第 1 个」，库一更新就漂移。
→ 新增 `配音.py: 按路找音色(相对)`：按**相对路径精确匹配**（路径在库内唯一，`指纹` 就是它的 md5），
`参考音频()` 现在**先试路径精确匹配，命中就用它**，再拼模糊结果做候选；查不到才抛 `KeyError`。

### 3.4 【实测】「名字唯一」这件事修了三层才真修好

修完 `_人名()` 之后重编，`统计` 里多了两个字段：`名字消歧` 和 `仍有重名`。
**第一轮 `仍有重名 = True`** —— 也就是说「按名字点音色」还是不可靠。挖下去发现**三种重名，一层比一层隐蔽**：

| 层 | 现象（实测） | 为什么漏 | 修法 |
|---|---|---|---|
| 1 | `没有想要的人物角色…\` 下每个子文件夹都有 `01.wav`，全被叫成父文件夹名 | 规则 ④ 只借了一层父目录名 | 补「（子文件夹）」→ 消歧 **96** 条 |
| 2 | `英语人物音色\其他\男声\1.wav … 18.wav` → **18 条全叫 `男声`** | 它们的父目录**就是同一个** `男声\`，补上去等于没补（原判据 `若 != 名字` 会跳过） | 两轮扫描 + 改成「父目录名已包含在名字里才跳过」→ 消歧 **130** 条 |
| 2 | `王也.MP3` 与 `王也.WAV`；`云小馨.wav` 与 `云小馨（影视模式）.wav`；`男-…柔和.wav` 与 `男-…柔和 (2).wav` | 规则 ① 把括号内容剥掉了，**不同文件撞成同名** | 同上 |
| 3 | 真正同名又无法拆分的（如那 18 个 `男声`） | 没有更多语义信息可用 | 挂 `指纹` 前 4 位 → `男声·9b3f`（指纹=相对路径 md5，库内唯一且稳定，**选出来永远是同一条**） |

**最终实测**：
```
总数= 1415   名字消歧= 130   仍有重名= False
实际重名名字数= 0   涉及条数= 0
```
抽查那 18 条现在叫 `男声·fa63` / `男声·97e5` / … **互不相同**。

> ★ **不变量（能自检的断言）**：`音色库.json` 的 `统计.仍有重名` **必须是 `False`**。
> 一旦变 `True`，「按名字点音色」就又不可靠了 —— 这是一条**跑一次编目就能验**的检查，
> 别把它当普通统计数字看。`配音.py 自测` 里没有这条断言，**手工跑 `音色库.py` 时看这一行**。

**教训**：我第一版 `_去重名()` 写完就以为修好了，**是 `仍有重名=True` 这个我自己加的字段把我拦住的**。
如果只写了「消歧了 96 条」这种好看的数字，就会带着 36 条重名继续往下做。
→ **修完一件事要留下一个能判对错的不变量，而不是一个好看的数字。**


**坑 1 · 落地路径 ≠ 仓内路径（最容易自己骗自己）**
`w2v-bert-2.0/model.safetensors` 的**落地**路径带一层目录，但它在 `facebook/w2v-bert-2.0` 仓里是**仓根**文件。

看起来完全像「镜像没有这个文件」，其实是自己拼错。**落地路径和仓内路径必须分开记。**

**坑 2 · `--speed-limit` / `--speed-time` 套在小文件上会假报 404**
实测同一个 `bigvgan/config.json`：
- 单独跑（`-o NUL`）：`HTTP=200 size_download=1405 exit=0`
- 套上 `--speed-limit 10240 --speed-time 90`：curl 判定「太慢」中止，返回 **exit 22**

这两个开关是为「几个 GB 的大文件静默卡死」设计的（掉到 10 KB/s 以下持续 90 秒就自杀），
但 1.4 KB 的配置文件在 8 路分片抢带宽时同样会 90 秒内传不完 —— 于是**把正常文件误判成 404**。
→ 小文件**不带**速度保护，只留一个宽松的 `--max-time 300`。小文件本来就是毫秒级，不需要保护。

**坑 3 · `_下模型.py` 的清单缺 `--fail`，会把 404 的占位响应当成文件存下来**
主仓对 `bigvgan/*`、`w2v-bert-2.0/*` 返回 404 但 **curl 不加 `--fail` 也算成功**，
落盘的就是那 15 字节的 `Entry not found`。而 `下一条()` 里 `预期` 写 0 时靠
`if 码 == 0 and not 预期: return True` 收尾 —— 于是一次**看起来成功、实际什么都没下到**。
→ 补全脚本一律带 `--fail`，并在落地后**校验字节数**，不符就删掉重来。

**坑 4 · `_并行下.py` 的 CLI 是 `<url> <目标文件> [份数]`，不是 `<目标文件> [份数]`**
传错参数时 curl 报的是
`curl: (3) URL rejected: Port number was not a decimal number between 0 and 65535`，
然后 `--retry 10 --retry-delay 5` 老老实实退避重试 —— 表面现象正是
「**进程活着、CPU 不动、一个字节不进**」，极易被误判成「镜像卡死」或 xet 又发作了。
→ 大文件直接调 `_并行下.拉(url, 目标, 份数=8, 预期=字节)`，不要拼命令行。

### 4.6.2b ★★【实测】「文件存在」≠「文件对」：远端 6 个 `.safetensors` 里 2 个残缺

**【Lead 在远端的实测（不是推测）】** 用同一套算法扫远端模型库，6 个 `.safetensors` 里 **2 个是残缺的**：
```
z_image_turbo_int8_convrot.safetensors      969,932,800 / 6,201,001,296 = 15.6%
umt5_xxl_fp8_e4m3fn_scaled.safetensors    3,853,414,400 / 6,735,906,897 = 57.2%
```
这两个文件 **`exists()` 为真、大小非零、ComfyUI 照列不误**，但一加载就：
```
Tensor 'layers.11.attention.out.weight' extends past the end of the file
```
补完这两个、重扫报 `好 6 / 坏 0` 之后，**远端那条线一次就出图成功**（24 秒 / 1066 KB）——
说明版本、路径、参数全是先前猜错的方向，**唯一的病根就是文件内容不全**。

**【影匠的判据：不问 `exists()`，问文件自己】**

`.safetensors` 是**自描述**格式：文件头里写着每块张量的 `data_offsets`，
所以「本该多大」可以**算出来**，不必信任何外部清单 —— 这才是真判据。

算法（落成 `补模型.py: 头校验(p)`）：
```
前 8 字节 = 小端 uint64 头长 L
→ 读 L 字节 JSON 张量表
→ 应 = max(8 + L + data_offsets[1])     # 跳过 __metadata__
→ 应 == 实际字节数 才算完好
```
**只读头（几 KB），不把 5 GB 读进内存** —— 比 `exists()` 强，比 `torch.load()` 快得多。

**【实测：它真的抓得住】**
```
A. 真件 D:\Comfy-Desktop\ComfyUI-Shared\models\embeddings\minimaxh3_art_is_explosion.safetensors
        512,120 字节
   → 头校验 ✓ 512,120 字节

B. 故意截到 40% → 204,848 字节
   → 头校验 ✗ 残缺：实际 204,848 / 应 512,120（只到 40.0%，缺 307,272 字节）
   → 对照 exists() = True      ← exists 说是，但它是坏的

C. `python 补模型.py 状态` 新增「校验」列；✓完整 的行也会再验一次头
   下完的瞬间就验（`下()` 里逐件调 `头校验`），不过就把这件记进失败清单
```
**报错比 `extends past the end of the file` 早一步、也更准**：它会告诉你「只到百分之几、缺多少字节」。

**【三层静默叠加，是它能一直藏住的原因】**
1. curl **没带 `--fail`** → HTTP 404 也算「成功」（返回体是 15 字节的 `Entry not found`）
2. 落了 15 字节 → `file.exists()` 为真
3. `下一条()` 里 `预期` 传 0 时靠 `if 码 == 0 and not 预期: return True` 报「✓完成」

→ **「文件存在」不等于「文件对」—— 这是本轮最贵的一课。**

### 4.7 ★【设计意图 → 已实测修正】「节点没加载」是个误判

| **第 4 关** 依赖关 | 节点自带的 `requirements.txt` 里 28 个包装了没 | `importlib.metadata.version(分发名)` | **不 import**，所以秒级、不会因副作用炸；能拿到版本号是要点 |

实测结果（两关全过，exit 0）：`共 28 个包：28 装了，0 没装` / `共 40 项：40 通过，0 缺`。

**第 4 关能工作的关键细节**：`requirements.txt` 里写的是**分发名**（PyPI 名），
代码里 `import` 的是**导入名**，两者不一致的必须有一张映射表，否则会把「装了」误判成「没装」：
```python

    "openai-whisper": "whisper",          "descript-audiotools": "audiotools",
    "pyyaml": "yaml",                     "g2p-en": "g2p_en",
    "docstring-parser": "docstring_parser", "absl-py": "absl",
    "flatten-dict": "flatten_dict",       "unidic-lite": "unidic_lite",
    "huggingface-hub": "huggingface_hub", "scikit-learn": "sklearn",
}
```
另外两处必须处理的：① `requirements.txt` 里有**平台标记**行
（`pynini==2.1.6; platform_system!="Windows"`、`WeTextProcessing>=1.0.3; platform_system!="Windows"`）
→ Windows 上**本来就不该装**，不跳过就会报两个永远修不好的「缺失」；
② `git+https://github.com/descriptinc/audiotools@0.7.4#egg=descript-audiotools` 这种行要走 `egg=` 提取名字。

#### 4.10.3 ★ 第 5 关踩的坑：`import whisper` 会去联网下载语料，10 分钟不回来

第一版第 5 关「所有模块都真 import 一遍」，结果**卡死**：
`import whisper` → `nltk.download('cmudict')` → 连 `raw.githubusercontent.com` → 连不上 → 重试到跑不完。
实测 10 分钟没返回（不是死锁，是它在等超时重试）。

1. **`断网()` 环境变量**：`NLTK_DATA` 指向一个空目录 + `HF_HUB_OFFLINE=1` + `TRANSFORMERS_OFFLINE=1`
   → 不追求真断网，只要求「**连不上就立刻报错，别重试**」。副作用只在本进程内。
2. **`只查在不在` 名单**：`torch / torchaudio / transformers / matplotlib / whisper / g2p_en /
   numba / nltk / scipy / librosa` 这批只做 `find_spec`（毫秒级、绝不联网、绝不 JIT）；
   其余轻模块才真 import。输出里会标 `只查在不在` / `真 import ✓` —— **「没测」和「过了」必须能分辨**。

#### 4.10.4 两个包值得单独记：它们不在节点源码的任何 `import` 语句里

- **`contractions`** —— 节点源码里搜不到这个字面量，它是 `wetext/utils.py:21 import contractions` 进来的。
  → **教训：依赖不只藏在「你的代码 import 谁」，还藏在「你的依赖 import 谁」。**
  `requirements.txt` 只写 `wetext`，但 `wetext` 自己还要 `contractions` + `kaldifst`。
- **`kaldifst`** —— `wetext` 的 FST 后端。**Windows 上有 wheel**（实测
  `kaldifst-1.8.1-cp313-cp313-win_amd64.whl` 1.1 MB，清华镜像直接下到），
  所以节点 `requirements.txt` 里那两个 `platform_system!="Windows"` 的 `pynini` / `WeTextProcessing`
  确实不需要 —— **但要装 `kaldifst` 顶上**。
- **`descript-audiotools`** —— 它其实**写在** `requirements.txt` 最后一行
  （`descript-audiotools==0.7.2  # DAC 依赖（PyPI 版即可）`），
  我早先因为「会拉 torch/numpy/transformers 老版本」而跳过了它，**那一步是错的**。
  正确做法是 **`--no-deps` 装上本体，再逐个补它缺的子依赖**（见 4.10.5）。

#### 4.10.5 装依赖的唯一安全姿势：全程 `--no-deps`，装一件复核一次版本

这个 venv 里 **`torch 2.12.1+cu130` / `numpy 2.5.2` / `transformers 5.16.1`** 是 ComfyUI 自己在用的版本。

实行的办法：**每装一批就在同一个命令里复核一次版本**，三个数一个字都不能变：

```powershell
$py -X utf8 -c "import torch,numpy,transformers;print(torch.__version__,numpy.__version__,transformers.__version__)"
```
`audiotools` 实际要补的子依赖（本次逐个试出来的）：
`flatten-dict` · `importlib-resources` · `julius` · `tensorboard` · `argbind` · `randomname` ·
`markdown2` · `rich` · `pyloudnorm` · `pystoi` · **`absl-py`**。
（`ffmpy` / `librosa` / `matplotlib` / `numpy` / `scipy` / `soundfile` / `torch` / `torchaudio` 之前就有。）

**★ `absl` 是这一串里最容易漏的**：`import torch.utils.tensorboard` 本身**不报缺**，
但 `from torch.utils.tensorboard import SummaryWriter` 会炸 —— 因为 `absl` 在更深一层才被 import。
**「导了外层没报错」不等于「这条链是通的」。**

#### 4.10.6 教训（「判据撒谎」的第五、六族）

| 族 | 症状 | 真因 |
|---|---|---|
| 一 | 模型加载器说「齐了」 | 它只查 8 件，另 3 件（§〇）不查 |
| 二 | `file.exists()` 为真 | 内容截断了（`头校验` 才能发现） |
| 三 | `Get-ChildItem` 报 0 字节 | 它在量一个**正在被写**的文件 |
| 四 | `validate()` 说齐 / 构造参数传了「名字」 | 字符串看着对，但它是名字/根目录，不是路径（§4.6.3） |

| **六** | **`import torch.utils.tensorboard` 成功** | **`absl` 在更深一层才 import；外层成功不代表链通** |

第五族的通用形态：**「我的检查器检查的东西」≠「我声称它保证的东西」。**

### 4.11 ★★【实测】后缀名是声明，不是事实 —— 产物叫 `.wav`，字节流是 FLAC

#### 4.11.1 现场：`wave.open()` 炸，但文件明明「是 wav」

Lead 用 Python 标准库读产物，逐字报：
```
wave.Error: file does not start with RIFF id
```
ffmpeg 一看：`Audio: flac, 22050 Hz, mono, s16`。**文件名叫 `.wav`，内容是 FLAC。**

#### 4.11.2 根因在 ComfyUI，不在调用方

`D:\Comfy-Desktop\ComfyUI-Installs\ComfyUI\ComfyUI\comfy_extras\nodes_audio.py:159-185`：
```python
class SaveAudio(IO.ComfyNode):
    node_id="SaveAudio",
    display_name="Save Audio (FLAC) (DEPRECATED)",
    is_deprecated=True,
    def execute(cls, audio, filename_prefix="ComfyUI", format="flac") -> IO.NodeOutput:
```
再查 `SaveAudioAdvanced` 的格式选项 —— `comfy_api\latest\_ui.py:259`：
```python
_FORMATS = {"flac", "mp3", "opus"}
```
**没有 `wav`。这个 ComfyUI 根本存不出真 WAV。** 默认节点固定 FLAC，`format` 参数只是给
`AudioSaveHelper` 选编码器用的，它**不决定扩展名** —— 扩展名由 ComfyUI 的
`folder_paths` 那套按编码器自己拼（所以服务器上是 `配音_00008.flac`）。
而调用方（我）把「我要的文件名」写成了 `.wav`，于是**声明与事实分叉**。

#### 4.11.3 为什么这个坑很贵：它骗过所有按后缀分支的人

| 谁被骗 | 表现 |
|---|---|
| `wave.open()` | `file does not start with RIFF id` |
| `ffmpeg` 包装脚本 | 多数能靠探测自救，但 `-f wav` 之类的强制参数会炸 |
| `剪映.py` / 剪辑软件 | 按扩展名选解码器 → 拿到 FLAC 却按 WAV 解 |
| 人的直觉 | 「我去读音频时长」→ 直接信后缀 |

★ **它和「文件存在≠文件对」是同一族，但更阴**：那个还能靠比对大小抓出来，
**这个连大小都对**（FLAC 是合法文件、字节数正常、`exists()` 为真、能播）。

#### 4.11.4 修法：读魔数 → 后缀与内容一致 → 需要 WAV 就真转

`配音.py` 新增两个函数：
```python
def 认音频(身: bytes) -> tuple[str, str]:      # → (真实后缀, 格式名)
def 转真WAV(路: Path) -> tuple[bool, str]:     # → (是否成了, 说明)
```
`认音频()` 看的头（`m4a` 的 `ftyp` 在第 4 字节起，单独判）：

| 魔数 | 后缀 | 格式 |
|---|---|---|
| `RIFF` | `.wav` | WAV |
| `fLaC` | `.flac` | FLAC |
| `OggS` | `.ogg` | OGG |
| `ID3` / `\xff\xfb` / `\xff\xf3` / `\xff\xf2` | `.mp3` | MP3 |
| 第 4 字节起 `ftyp` | `.m4a` | M4A |
| `\x30\x26\xb2\x75` | `.wma` | WMA |
| 都不匹配 | `""` | 报「认不出来（头 16 字节 …）」+ 原样落盘，**不猜** |

`_取音频()` 新流程：
1. 取回字节 → `认音频()`
2. **已经是 WAV 或认不出来** → 原样落盘（认不出来时打一行字，不硬改后缀）
3. **不是 WAV** → 先落**真后缀**（`.flac`），**名字与内容立刻一致**
4. 调用方点名要 `.wav`（`要真WAV=True`）→ `soundfile` 读 → 写**临时文件** → `replace()` 换名
   - ★ 先写临时再换名：中途炸了**不会毁掉原文件**
   - 转 `PCM_16`（`subtype="PCM_16"`, `format="WAV"`）
5. **转失败** → 保留 `.flac` 并打印说明 —— **绝不留下「名叫 .wav 的 FLAC」**

`合成()` / `批量()` 新增 `要真WAV: bool = True`（拿 FLAC 省一次转码可传 `False`）。

**实测（三方交叉验证）**：修后 4 份产物 `魔数=RIFF` / `wave.open()` 全通 /
`soundfile` 报 `WAV PCM_16 22050Hz 1ch` / 触顶样本 0 个。
`认音频()` 另用三个真文件单独验过：真 WAV→`.wav`、旧的 FLAC-顶着-`.wav`→`.flac`、参考音色源→`.wav`。

#### 4.11.5 通用规矩（写进 §六 未验清单）

1. **判定音频格式一律读魔数，不看扩展名。** 凡是「有一环按后缀走分支」，就一定会分叉。
2. **产物命名要由内容决定，不由愿望决定。** 「我想要 wav」是愿望；「字节流是 RIFF」才是事实。
3. 需要某种格式时**真转一次**，别靠改后缀 —— 改后缀只是换个方式骗人。
4. 转码**先写临时文件再替换**，别在原路径上原地写。

### 4.12 ★【实测】我自己代码里的一个静默 bug：净化文件名把中文和路径分隔符一起删光

#### 4.12.1 现象：四个空目录

用 `配音.批量()` 连配 4 句，音色词写的是**带子目录的相对路径**
`男女——情绪分类\女-常规-清冷无情-2-1.wav`。跑完 exit 0、四句都报成功，但产物是：
```
四句连配_lead\001_\21wa.wav
四句连配_lead\002_\21wa.wav     ← 001_ 是一个【目录】，不是一个文件
四句连配_lead\003_\21wa.wav
四句连配_lead\004_\21wa.wav
```
**不报错，不崩溃，四句时长都正常** —— 只有文件名变成了「四个空目录」。

#### 4.12.2 根因：两个错叠在一行里

```python
目标 = 夹 / f"{int(序):03d}_{re.sub(r'[^\\w\\u4e00-\\u9fa5]', '', str(音))[:12]}.wav"
```
1. **Python 的 `re` 里，字符类中的 `\\u4e00` 不是「汉字区间」** ——
   `r'[^\\w\\u4e00-\\u9fa5]'` 这个原始字符串进到 re 引擎，`\\` 是**字面的反斜杠**，
   于是这类被理解成「非（反斜杠 | w | u | 4 | e | 0 | 5 | a | 9 | 范围 `-`）」，
   **中文全部命中「非」而被删掉**。
2. `\` 和 `.` 也一并被删 → 剩下 `21wa`（来自 `-2-1.wav`）。
3. 序列号前缀 `001_` + 空名字 → 拼出来 `001_`，**成了目录**，音频落进了它里面。

#### 4.12.3 修法

新增 `净名(词, 上限=24) -> str`：
```python
s = s.replace("\\", "_").replace("/", "_")             # 路径分隔符先变可见字符
s = Path(s).stem if ("." in s.rsplit("_", 1)[-1]) else s  # 再去扩展名
s = re.sub(r"[^\w\u4e00-\u9fff]", "", s, flags=re.UNICODE)  # ★ 用普通字符串，不用原始字符串
s = s.strip("_") or "音色"                                  # 空了给兜底
```
实测：`男女——情绪分类\女-常规-清冷无情-2-1.wav` → `男女情绪分类_女常规清冷无情21`；
`冰山女王` → `冰山女王`；`''` → `音色`。

另加两道防线：
- `_取音频()` 里：**落点若指向一个已存在的目录，直接抛错**，别让 `write_bytes` 造出目录。
- 新增 `_独前缀()`：给 ComfyUI 的 `filename_prefix` 带 6 位随机后缀，
  让服务器上的文件与「哪一次调用」一一对应（原来固定 `影匠配音/配音`，
  服务器自己加序号堆出 `配音_00001.flac`…，排查时分不清哪次是哪次）。

修后文件名：`001_男女情绪分类_女常规清冷无情21.wav`。

#### 4.12.4 教训

- **原始字符串 `r'…'` 只在「正则里真的要一个字面反斜杠」时才用。**
  想让 `\u4e00` 当 Unicode 转义，就得用**普通字符串**（或者写 `\u4e00` 不带双斜杠）。
  ★ 这类错**单测很容易漏**：只要测试用的名字是纯 ASCII，它就一直不发作。
- **「净化成空字符串」必须当成一种失败**，而不是一种结果。净化后为空 → 要么兜底名，
  要么报错；**绝不能拿空字符串去拼路径** —— 那样拼出来的东西有时是合法路径（`001_`），
  于是错误被掩盖。**「产出物看起来合法」不等于「产出物是对的」。**
- 这是**静默错误**的第 N 次发作。共同特征：**运行成功、退出码 0、人眼不细看发现不了。**
  防它的唯一办法是给每个交付物都定一个**能判对错的不变量**
  （这里的做法：文件名主干不能为空；产物必须 `wave.open()` 能打开）。

**★ 踩到的坑：正斜杠 vs 反斜杠，同一个文件被判「不存在」。**
`音色库.json` 里 `相对` 存的是**正斜杠**（`男女——情绪分类/女-常规-清冷无情-2-1.wav`，
因为它是 `Path` 的 `as_posix` 风格），而人手写映射表时习惯**反斜杠**。第一版 `归一()` 只做了
「去空格 + 转小写」，于是一上来就报 `✗ 音色库里没有这条！` —— 而这正是**同一个坑的第二次发作**
（第一次是「文件存在 ≠ 文件对」）。修法：`归一()` 里加
`(名 or "").strip().lower().replace("\\", "/")` 并把重复斜杠折叠。
→ **通用教训：只要有两处各自拼路径，就一定会在分隔符上分叉；归一化函数必须同时管「大小写/空白」和「分隔符」。**

**★ 另一个设计决定：解析顺序不能反。** 先当**角色名**查映射表，命中就用映射的音色；否则才当音色名。
理由：角色名和音色名可能撞（某个角色可能就叫「御姐」），而**映射表是人明确指定过的，比模糊匹配可信**。

### 5.3 G6 · SRT 用真实音频时长 —— 【实测】已经做到了，之前我判错了

早先我按自测输出判「SRT 是按 `估时长()` 排的」，**这个判断是错的**。逐行走代码（`配音.py`）：

```python
953:  出.append({..., "秒": 秒, ...})
```

`写SRT()` 里 `896: 长 = float(段.get("时长") or 估时长(文))` —— 只有**没给时长**时才退回估算。

自测里之所以看到 `估时长 4.15 秒` 而 SRT 写 `0→2.400 + 2.400→5.400`，

**不是 bug，是我把「降级路径」当成了「主路径」。** 教训：判断「某功能有没有实现」必须读主路径，
不能拿一个**已知失败场景**的输出当证据。

→ 对飞彩的差距因此**不存在**：飞彩的原则「根据**已合成对白**的时长生成 SRT」（逐字）
