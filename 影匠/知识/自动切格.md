## 1. 结论：纯几何切分

飞彩的切格入口是一个浏览器端 Canvas 函数，打包后的名字是 `uT`，原始签名（从调用点与字符串常量还原）：

```js
cropImageGrid(imageUrl, cols, rows, maxCellSize = 1024, explicitRect = null)
  → Promise<{ dataUrl, blob, width, height, x, y }[]>
```

它有三种走法：

| # | 触发条件 | 行为 |
|---|---|---|
| 1 | 传了 `explicitRect = {x, y, width, height}` | 只裁这一块，不走网格 |
| 2 | 传了 `cols/rows` | 平均分成 `cols × rows` 块 |
| 3 | 都没有 | 判为「自动」，按 3×3 切 |

**没有用到任何检测模型、边缘分析、连通域、模板匹配。** 也就是说：切出来的格是否正好落在画面上，完全取决于**你导入的那张合成图本身排得正不正**。这一点对影匠很关键——切格不是智能的，它是「你按 3×3 出图，我就按 3×3 切回来」的对称操作。

## 2. 三条路径的细节

### 2.1 显式矩形（单块裁剪）

```
校验：x >= 0、y >= 0、width >= 1、height >= 1、不越界、块数 <= 81
```

`<= 81` 这个上限说明飞彩把「自定义宫格」的规模上限定在 81 格（9×9），超过就拒绝。

### 2.2 平均网格（主路径）

```
单块宽 = floor(图宽 / cols)
单块高 = floor(图高 / rows)
第 (i, j) 块（i 行、j 列）：
    x = j * 单块宽
    y = i * 单块高
    w = 单块宽
    h = 单块高
```

注意两个设计点：

1. **向下取整（floor）**，余数像素被丢掉，不做「最后一块吃掉余数」的补偿。所以一张 1025px 宽的图切 3 列，会丢 2px，右侧最后一块比其他块窄 2px——但代码仍按统一 `单块宽` 取，等于切出来右边有 2px 永远拿不到。这个行为是**有意的对称性优先**：宁可丢边角，也让每格尺寸完全一致（后续合成、编号、超分都按固定尺寸走）。
2. **循环顺序是先列后行还是先行后列**由编号决定：`@1` 是左上角，然后**从左到右、从上到下**（行优先）。这与影匠 `模板\九宫格.md` 的分镜阅读顺序一致。

### 2.3 每块的处理管线

对每个矩形：

1. `drawImage` 到离屏 Canvas（`createElement("canvas")`）
2. **`maxCellSize = 1024` 的等比缩放**：如果块宽或高 > 1024，就按长边缩到 1024；否则**原样输出，不放大**
3. `canvas.toBlob(...)` → 拿 `Blob`；同时 `toDataURL()` → 拿 `dataUrl`
4. 若 `Blob` 创建失败，则走 **一次重试**（有重试逻辑，说明这条路径在真实浏览器里踩过坑）
5. 返回数组里每项带 `{dataUrl, blob, width, height, x, y}` —— `x/y` 是**原图坐标**，不是块内坐标。这两个字段是给「在整图上高亮/定位当前格」用的 UI 信息。

### 2.4 1px 内缩（去接缝）

切出来的块在**每边内缩 1px** 再输出。目的：AI 生成的九宫格在格与格之间常有一条 1~3px 的浅色/深色接缝（模型自己画的分隔线或压缩伪影），不内缩的话这圈脏边会被当成「画面内容」带进下一轮生图，逐轮放大成明显的边框。**这一条是影匠一定要照抄的经验。**

### 2.5 切完之后的落盘

- 单格图存 `outputs/grid-images/`（按格 key 命名，刷新自动恢复）
- 相关的 API 路由名（空壳文件名暴露）：`app\api\grid-image`、`app\api\grid-image-info`、`app\api\grid-expand`
- `grid-expand` 的存在说明还有「扩展宫格」动作：把已有格扩成更多格
- 有一处校验文案原文：`Flow 扩展的 @参考图持久化数量异常，已停止入队`，判断条件形如 `t.length !== t.strictReferenceCount || r.some(e => !e.url)` —— 也就是**切格 + 扩格时，每格挂的参考图数量必须与 `strictReferenceCount` 严格相等，且每张都必须有 url 才能入队**。这是防止「扩格后参考图静默丢失」的护栏。

## 3. 影匠的实现建议（★ 当时写的「不抄代码」已作废，能搬就搬）

影匠的 `拼图.py` 是反向操作（把 N 张拼成一张）。切格是它的逆运算，建议**放在 `拼图.py` 旁边新开一个函数**（或在 `一致性.py` 里做 `切格()` 辅助），要点：

```python
def 切格(合成图路径, 列=3, 行=3, 内缩=1, 最长边=1024, 输出目录=None):
    """
    按比例把一张合成图平均切成 行×列 张，行优先编号（左上=@1）。
    - 内缩: 每边裁掉多少 px，用来去掉 AI 出图在格与格之间的接缝（默认 1）
    - 最长边: 单格超过这个像素就等比缩小，不超过则不动（默认 1024，照飞彩）
    返回 [{"序": 1, "路径": ..., "宽": w, "高": h, "原图坐标": (x, y)}]
    """
```

实现注意（都是从飞彩那边验证过的坑）：

1. **floor 取整 + 不补偿余数**，保证每格严格等宽等高。
2. **内缩 1px**，去接缝。
3. **单格超 1024 才缩，不放大** —— 放大是 `超分` 的活（见下）。
4. **返回原图坐标 `(x, y)`**，方便在整图上画高亮框、或者在 `知识\一致性系统.md` 里做「点哪格改哪格」。
5. **不要试图自动判断是 4 格还是 9 格**。飞彩是让用户选（四宫格 / 九宫格按钮），因为从一张图反推布局不可靠。影匠照做：让用户说「切 9 格」或「切 4 格」，别猜。

### 3.1 切格的编号必须与「参考图编号」对齐

这是**最容易出一致性事故的地方**，飞彩用 `strictReferenceCount` 那条校验挡的就是它。影匠的做法：

- 切格产出的每张单格图 → 立即写入该格的 `参考图` 字段
- 每格入队生图前，断言 `len(图数组) == 该格声明的参考图张数`
- 不相等就**拒绝入队并明确报错**，绝不静默丢图（飞彩原文就是「已停止入队」）
