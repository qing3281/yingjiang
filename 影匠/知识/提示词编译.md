## 0. 一句话总览

飞彩的提示词编译是**两级结构**：

```
第一级：把「一致性资产 + 风格参数」编译成一段结构化中文清单  →  塞进 LLM 系统提示词（buildStylePrompt）
第二级：LLM 按固定六段公式吐出「每格英文提示词」           →  生图时再拼上参考图数组（buildReferenceImages）
```

风格不是写死在模板里的，而是**以「字段清单」的形式注入 LLM**，让模型自己在写每一格时落地。
影匠照做的话：**风格系统 = 一张 23 行的词表 + 一段逐字段输出的编译器**，不需要 23 个模板。

## 1. 影匠规格 A：风格参数清单（照 `buildStylePrompt` 复刻）

### 1.1 证据

- 文件：`.next\static\chunks\9490-a7bad63d9cae38d9.js`，模块 **70308**
- 搜索关键词：`buildStylePrompt`（出现在 `console.warn("[buildStylePrompt] stylePrompt JSON 解析失败…")` 里，因此可确认函数名）
- 函数在产物里的压缩名是 `ec`，签名 `function ec(e,t)`，`e` = 一致性上下文对象，`t` = 自定义风格预设列表

### 1.2 输出顺序（**这个顺序就是规格，照抄即可**）

编译器用 `r.push(...)` 顺序累积，最后 `r.join("\n")`。逐行顺序如下：

| # | 输出行（原文前缀） | 条件 | 取值来源 |
|---|---|---|---|
| 1 | `【角色一致性要求 - 所有画面中同一角色外观必须严格保持一致】` | `characters.length > 0` | 固定表头 |
| 2 | `- {name}(#{id})：{description}` | 每个角色 | `description` **超过 150 字会被截断**并补 `…` |
| 3 | `\n【场景一致性要求】`（前面带空行） | `scenes.length > 0` | 固定表头 |
| 4 | `- {name}(#{id})：{description}` | 每个场景，**且 `subType !== "scene-view"` 时跳过** | 同上，150 字截断 |
| 5 | `\n【道具一致性要求】` | `props.length > 0` | 固定表头 |
| 6 | `- {name}(#{id})：{description}` | 每个道具 | 同上 |
| 7 | `\n【整体风格要求】` | 恒有 | 固定表头 |
| 8 | `- 画幅：{aspectRatio}` | 恒有 | 直接取字符串 |
| 9 | `- Render type: {label} — {keywords}` | `renderType` 存在且 `id !== "auto"` 且 `keywords` 非空 | 渲染类型表 |
| 10 | `- 画质：{label} ({resolution})` | 恒有 | 画质档位表（缺省 `"4K"`） |
| 11 | `- 画质要求：{keywords}` | `keywords` 非空 | 画质档位表 |
| 12 | `- 视觉风格：{label} — {keywords}` | `visualStyle` 存在 | 视觉风格表 |
| 13 | `- 光影氛围：{label} — {keywords}` | `lightingMood` 存在且 `keywords` 非空 | 光影氛围表（`auto` 的 `keywords` 是空串，所以自动模式**不输出这一行**） |
| 14 | `- 镜头效果：{中文标签列表} — {keywords}` | `lensEffects` 非空且能拼出关键词 | 中文标签用 `、` 拼；关键词用 `, ` 拼 |
| 15a | `- Style preset: {label} — {keywords}` | `stylePreset` 命中 | **23 风格表的英文词** |
| 15b | `- 预设风格：{label} — {prompt}` | 同上（**紧跟在 15a 后面**） | **23 风格表的中文描述** |
| 15c | `- 参考图画风：{artStyle}` / `- 参考图色调：{colorPalette}` / `- 参考图关键词：{styleKeywords}` / `- 参考图氛围：{mood}` | 无 `stylePreset` 但有 `stylePrompt`，且能 `JSON.parse` | 参考图识别结果（只推存在的字段） |
| 15d | `- AI识别风格：{stylePrompt}` | `stylePrompt` 不是合法 JSON | `console.warn("[buildStylePrompt] stylePrompt JSON 解析失败，作为纯文本处理:", …)` |
| 15e | `- 画风：{artStyle}` / `- 色调：{colorPalette}` | 既无 `stylePreset` 也无 `stylePrompt`，但有手填字段 | 手工填写 |
| 16 | `- 时代/世界观背景：{timeSetting}` | `timeSetting` 存在 | 手工填写 |
| 17 | `- 补充：{additionalNotes}` | `additionalNotes` 存在 | 手工填写 |

### 1.3 三条优先级规则（影匠必须复刻）

1. **自定义预设优先**：`stylePreset` 的解析函数先把**用户自定义预设列表**过一遍，没命中才回落到内置 23 种。
   证据：同模块 `p(e.style.stylePreset, t || [])`，`t` 是调用方传进来的自定义列表。
2. **预设 ≫ 参考图 ≫ 手填**：`stylePreset` 命中时**完全不走** `stylePrompt` / `artStyle` / `colorPalette` 分支（是 `else if` 链）。
3. **描述截断 150 字**：`i = e => e.length > 150 ? e.slice(0,150) + "…" : e`，只作用于角色/场景/道具的 `description`，
   **不作用于风格字段**。

### 1.4 影匠落地建议（本站设计，非飞彩原文）

```python
def build_style_prompt(ctx) -> str:
    # 直接照 1.2 的 17 行顺序生成；风格表从 风格提示词.json 读
    ...
```

## 2. 影匠规格 B：参考图数组的排序（照 `buildReferenceImages` 复刻）

### 2.1 证据

- 同文件模块 70308，压缩名 `eu(e,t)`，`e` = 一致性上下文，`t` = 当前镜头（含 `sceneType`）
- 搜索关键词：`feicai-scene-outfit-match`

### 2.2 顺序（**生图模型靠位置理解谁是「第一张参考图」，所以顺序即语义**）

```
1. 风格参考图        style.styleImage（若通过 startsWith 校验）
2. 每个角色一张       outfits[?].coverImage ?? referenceImage
3. 每个场景一张       scene.referenceImage
4. 每个道具一张       prop.referenceImage
```

### 2.3 隐藏机制：按「场景类型」自动换装

- 开关：`localStorage["feicai-scene-outfit-match"] === "true"`，并且当前镜头**必须**有 `sceneType`，否则退化为「永远取 `outfits[0]`」。
- 匹配算法（函数体可直读）：
  1. 在 `outfits` 里找 `sceneTagsApplicable` **精确等于** `sceneType`（两边都 `toLowerCase().trim()`）的那一套 → 命中即用；
  2. 否则找 `sceneTagsApplicable` 包含 `"*"`（通配）的那一套 → 命中即用；
  3. 否则回落 `outfits[0]`。
- 取到的 outfit 用它的 `coverImage`，拿不到再回落角色的 `referenceImage`。

> 影匠吸收点：这等于把「同一角色在不同场景换衣服」做成了**每条 outfit 打场景标签**，而不是靠一次性的角色描述。

## 4. 影匠规格 D：单格提示词的六段公式（**最重要的可照做规格**）

### 4.1 证据

- `D:\DSHworkspace\素材\网盘\_飞彩解包\Win\9宫格分镜Gem.txt`、`4宫格分镜Gem.txt`、`25宫格分镜Gem.txt`
- 搜索关键词（挖取时）：`组合公式`、`纯视觉原则`、`字数锁`

### 4.2 公式（三份文件完全一致，原文）

```text
[景别] + [主体与动作] + [环境] + [时间/光照关键词] + [风格标签] + [排除词]
```

### 4.3 六段各自的规定

| 段 | 规定 | 证据 |
|---|---|---|
| 景别 | 用英文标准景别词开头：`Extreme Wide Shot` / `Wide Shot` / `Medium Shot` / `Medium Close-up` / `Close-up` / `Close Shot` / `Two-shot` / `Over-the-shoulder Shot` / `Dynamic Low Angle` / `Bird's Eye View` / `Long Shot` / `Extreme Close-up` | 示例 JSON 里的 `prompt_text` 首词 |
| 主体与动作 | 主语 + 动词 + 核心环境词；**只描述画面内容** | 生成流程「步骤4」 |
| 环境 | 场景/陈设/道具 | 同上 |
| 时间/光照 | 英文，**每个分镜独立推断**（`dawn soft light` / `sunset golden hour` / `midnight blue moonlight` / `blue hour` …） | 约束 `C8` |
| 风格标签 | **从参考图提取 3-4 个最具代表性的风格单词**，追加在提示词后部 | `:风格` 段；例：`Anime style, 3D render, 8k, Volumetric lighting` |
| 排除词 | 见 4.5（这是全项目最容易踩坑的地方） | 约束 `C5`/`C6` |

### 4.4 语言约定（**双语分工**）

| 字段 | 语言 | 长度 | 用途 |
|---|---|---|---|
| `description` | **中文** | 九宫格 30-50 字；四宫格/25 宫格 10-20 字 | 在分镜面板显示给用户 |
| `time_setting` | **英文** | 短语 | 时间/光照，且必须**同时融入** `prompt_text` |
| `prompt_text` | **英文** | 25 词左右（±5 词）；九宫格另有硬约束 ≤40 词 | 真正送给生图模型 |

### 4.5 反向原则：**排除词不是「加负向词」，而是「禁止写元指令」**

这是飞彩最反直觉、也最值得影匠直接吸收的一条：

- 传统做法：在提示词尾部加 `no subtitles, no watermark`。
- 飞彩的结论（原文 `C5`）：**这些元指令会被图像模型渲染成画面里的可见文字**，所以：
  - `C5`：`prompt_text` 内**严禁**出现 `no timecode`、`no subtitles`、`分镜X in corner`、`Shot X in top-left` 等指令性文字；
  - `C6`：**严禁**添加任何分镜编号、角落标记、序号标注（`分镜5 in the top-left corner`、`S1:`、`Frame 3`）；
  - `prompt_text` **只写纯视觉描述**。
- 同时：`H1` 严禁在画面中添加任何文字、序号、时间码、字幕。

> ⚠️ 产物内部对此**存在自相矛盾**：`9宫格分镜Gem.txt` / `4宫格分镜Gem.txt` / `25宫格分镜Gem.txt` 的**示例 JSON** 里
> 仍然写着 `no timecode, no subtitles.`，而 `25宫格分镜Gem.txt` 的 `C5` 明令禁止。
> 这是飞彩新旧两版提示词叠在一起没清理干净。**影匠应按 `C5`/`C6` 执行（不加任何元指令），不要照抄示例。**
> 另有 `global_watermark { position: "bottom_center", size: "extremely small" }` 这个字段——
> 它属于**后期合成阶段**的水印参数，**不是**要写进 `prompt_text` 的文字。

### 4.6 全流程（原文「生成流程」六步）

```text
步骤1 提取参考图风格标签 (Style Tags)
步骤2 将剧本切分为 N 个关键动作（N = 4 / 9 / 25）
步骤3 时间推断：逐分镜推断时间段与光照（允许各格不同，忠实剧本）
步骤4 编写精简 Prompt：景别、主语、动词、核心环境词 + 时间/光照关键词
步骤5 检查字数：确保每个 Prompt 在 25 词左右
步骤6 封装 JSON
```

### 4.7 输出 JSON 结构（原文）

```json
{
  "image_generation_model": "NanoBananaPro",
  "grid_layout": "3x3",
  "grid_aspect_ratio": "16:9",
  "global_watermark": { "position": "bottom_center", "size": "extremely small" },
  "shots": [
    {
      "shot_number": "分镜1",
      "description": "中文叙事描述（30-50字）",
      "time_setting": "dawn, soft golden light, morning mist",
      "prompt_text": "Extreme Wide Shot, mountain village in glowing canyon, dawn soft golden light, ..."
    }
  ]
}
```

`grid_layout` 取值：`2x2` / `3x3` / `5x5`；`shots` 数组长度必须严格等于 4 / 9 / 25。

## 5. 影匠规格 E：宫格与一致性

### 5.1 宫格规范（`Gemini生图专用Gem.txt`「宫格规范」段）

| 宫格 | 布局 | 用途 | 节奏设计 | 景别要求 |
|---|---|---|---|---|
| 九宫格 | 3行×3列 | **Beat Board 节拍板** —— 一段剧情（约1集/1章节）的 9 个关键瞬间 | 开场建立(1-2) → 冲突升级(3-5) → 高潮爆发(6-7) → 余韵收束(8-9) | 至少 1 远景 + 3 中景 + 2 特写 + 3 自由 |
| 四宫格 | 2行×2列 | **Sequence Board 序列板** —— 九宫格中某一格的 4 格展开 | 引入(1) → 发展(2) → 转折/高潮(3) → 余韵(4) | 必须至少两种不同景别 |
| 25 宫格 | 5行×5列 | 完整细致分镜 —— 一段长剧情的 25 个关键画面 | 起承转合的**多次循环** | 追求最大化景别多样性 |

通用规则（原文）：每格一个独立镜头，不拼接/不重叠；统一画幅比 **16:9**；不得在画面内添加文字、序号、水印；
格与格之间要有叙事逻辑连贯性；角色在不同格中需保持外貌一致。

### 5.2 一致性系统（`Gemini生图专用Gem.txt`）

- **角色档案**字段：中文名/英文名/别名、年龄/性别/体型、发型发色、面部特征（脸型/眼型/标志性特征如伤疤胎记）、
  标志性服装（本场）、主色调、气质关键词（阴郁/阳光/冷漠/高傲）。
- **场景档案**字段：场景名称/类型、空间规模（室内/室外/开阔/狭窄）、核心道具/陈设、光源类型与方向、
  色彩基调、氛围关键词。
- **跨格一致性策略**（原文 4 条）：
  1. 生成第一格时确立角色与场景的视觉基准；
  2. 后续每格的提示词中**显式引用角色档案关键特征**；
  3. 同一场景内**光源方向保持一致**；
  4. 有参考图时，**每格提示词中都要描述参考图中需保留的元素**。
- **风格一致性**（同文件另一段）：色彩范围与饱和度保持、线条粗细/清晰度不变、光影体系统一（光源方向与质感不变）、
  **仅在剧情需要时（闪回/梦境/情绪转变）才允许风格微调**。

### 5.3 影匠落地建议

`5.2` 的「角色档案 / 场景档案」正好是 `第 1.2 节` 里 `【角色一致性要求】` 那几行的数据源。
影匠应把「档案字段」与「编译器输出行」一一对应，做到**改档案即可改提示词**，不需要手改模板。

## 6. 影匠规格 F：约束与自检（可直接当验收清单）

### 6.1 硬约束（原文标「违反则生成失败」）

| 编号 | 内容 |
|---|---|
| H1 | 严禁在画面中添加任何文字、序号、时间码、字幕。 |
| H2 | 严禁使用 `A scene showing...` / `There is a...` 等无意义句式。 |
| H3 | 叙事段落必须具体——禁止「戏剧性的场景」「美丽的画面」等空洞描述。 |
| H4 | JSON 模式下只输出 JSON，不附加任何解释文字。 |
| H5 | 每格画面必须有且仅有一个视觉焦点。 |
| H6 | 严禁在一个画面中描述超过 3 个运动元素。 |
| H7 | 如有参考图，风格标签必须**从参考图中提取，不得臆造**。 |
| H8 | 中文 `description` 不超过 30 字（九宫格版为 30-50 字，见 4.4）。 |
| H9 | 英文 `prompt_text` 不超过 40 词。 |
| H10 | 生成图像时不得包含 NSFW 内容。 |

### 6.2 约束模块 C1-C8（宫格分镜提示词）

| 编号 | 内容 |
|---|---|
| C1 | 格式：标准 JSON，无 Markdown 废话。 |
| C2 | 数量：`shots` 数组必须为 4 / 9 / 25 个。 |
| C3 | **字数锁**：每个 `prompt_text` 限制在 25 词左右（±5 词）。 |
| C4 | 句式：严禁长难句，严禁 `A scene showing...` / `There is a...`。 |
| C5 | **纯视觉原则**：`prompt_text` 内严禁出现任何非画面内容的指令性文字。 |
| C6 | **去水印**：严禁分镜编号、角落标记、序号标注；只写纯视觉描述。 |
| C7 | `description` 必须为中文，简明扼要，用于分镜面板显示。 |
| C8 | `time_setting` 必须为英文，逐分镜推断时间/光照，并融入 `prompt_text`。 |

### 6.3 内部自检清单 QC1-QC10（原文标「不输出给用户」）

```text
QC1  叙事连贯性：9/4/25 格是否讲述了一个完整的故事弧？
QC2  景别多样性：是否避免了连续 3 个以上相同景别？
```
