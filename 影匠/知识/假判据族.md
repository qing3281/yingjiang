# 假判据族 —— 那些「说 OK 但什么都没量」的检查

> 这份文件是一份**故障模式手册**，不是教程。
> 每一条都是在这个项目里真踩过的，附现场证据和修法。
> 共同点：**它们都不报错。** 报错的检查只是烦；不报错的检查会让人把「通过」当成事实，
> 然后基于一个假事实做破坏性动作 —— 删文件、杀进程、重下 20 GB。

---

## 零、为什么单开一份文件

这个项目里「判据说谎」已经发生了 **八次**，分五个族（族三在 2026-10-14 加了第 3.3 条）。它们散落在各个脚本里，
每次都是重新踩一遍才想起来。所以集中记一份。

判据的两种坏法，坏的方向相反，但后果一样：

| | 表现 | 后果 |
|---|---|---|
| **太松** | 恒真、作用域没覆盖到、量的是别的东西 | 放过了真的坏东西 |
| **太严** | 把正常状态判成故障 | 天天误报，人开始无视它 —— **比没有判据更坏** |

`dub` 的原话值得抄在这里：
> 「报错 ≠ 有问题。判据说『过』要问作用域覆盖到哪；判据说『不过』要先问这在不设计要的行为里。
> 一个分不清这两者的自测，会让人开始无视它 —— 那比没有自测更坏。」

## 一、族一：判据读的**地方**不对

### 1.1 `Test-Path 'C:\pagefile.sys'` 返回假 False

**现场**（2026-10-14，查远端虚拟内存）：
```
PS> Test-Path 'C:\pagefile.sys'
False
```
差点据此判定「远端页文件 72 GB 配置了但文件没建出来」——那会导致去重建一个
**已经存在且正在被系统使用**的页文件。

**真相**：`cmd /c dir /a C:\` 看得到
```
2026/10/13  21:48    77,309,411,328 pagefile.sys
```
注册表也对：`PagingFiles = c:\pagefile.sys 73728 98304`、
`ExistingPageFiles = \??\C:\pagefile.sys`。

**机制**：页文件被内核独占打开着，某些经过 Win32 属性层的查询路径会静默返回
「没有」而不是报错。

**规矩**：**被进程独占持有的文件，至少用两种无关的机制各问一次**
（`dir /a` + 注册表 + `Get-CimInstance Win32_PageFileUsage`），
三个里有两个说在，就是在。

## 二、族二：判据读的**编码**不对

### 2.1 `Get-Content` 默认 GBK 读 UTF-8 → 一个文件被读成另一个文件

**现场**（2026-10-14，回验网盘归档清单 698 条）：
```
PS> $行 = Get-Content 'D:\DSHworkspace\影匠\作品\_网盘归档\归档清单.txt'
PS> ... 逐条回验 ...
共 464 条：在 0　不在 464
```
**「698 条一条都不在盘上」** —— 按这个结果下一步就是重新下载 20 GB。

**真相**：文件是 UTF-8，PowerShell 默认按 GBK 读，
`D:\DSHworkspace\素材\网盘` 被读成 `D:\DSHworkspace\缃戠洏`，路径自然全不匹配。
**加 `-Encoding UTF8` 就是 698/698 全在。**

### 2.2 同一个坑的另外三次发作

| 日期 | 文件 | 读出来的样子 | 真相 |
|---|---|---|---|
| 10-14 | `作品\_网盘归档\归档清单.txt` | 698 条全「不在」 | UTF-8 被按 GBK 读 |
| 10-14 | `影匠\视频.py` | `def 鎺ョ墖(...)`，签名看不懂 | 同上；换 `read` 工具就对 |
| 10-14 | `影匠\配音.py` 的中文正则 | `\u4e00` 被当字面反斜杠，中文全被删 | 源码字符串转义层 |

**规矩**：
- **看文件用 `read` 工具，不用 `Get-Content`。** 这条已经写进项目惯例。
- PowerShell 里读文本一律显式 `-Encoding UTF8`。
- 反向：**写 `.cmd` 给 cmd.exe 用，必须写成 GBK（936）**，因为 cmd 按 OEM 代码页读；
  而 **`.ps1` 传远端必须带 UTF-8 BOM**，否则 PowerShell 5.1 按 GBK 读中文 → `ParserError`。

### 2.3 中文 Python 别用 PowerShell here-string 喂

**现场**：
```
PS> & $py -X utf8 -c @"
... f"凌霜，{角['外貌']}"
"@
SyntaxError: invalid character '，' (U+FF0C)
```
**真相**：here-string 里的双引号被 PowerShell 先剥掉，`f"..."` 变成 `f...`。
后来又复现一次：`r"作品\磨刀\02-九宫格.md"` 变成 `r作品\磨刀\...` →
`SyntaxError: unexpected character after line continuation character`。

**规矩**：**带中文或引号的 Python，一律写成 `.py` 文件跑。**

## 三、族三：判据**太弱**（恒真）

### 3.1 `_烧字幕.py` 的 `探时长()` —— 一个永远说 OK 的检查

**原代码**：
```python
ff = os.path.join(处处, "_bin", "ffmpeg.exe")
ffprobe = ff.replace("ffmpeg", "ffprobe")
```
**`_bin\` 下只有 `ffmpeg.exe`，没有 `ffprobe.exe`。**
抛异常 → 被 `except` 吞掉 → 返回 `0.0` → 两个 `0.0` 相减 = 0 →
「时长差 > 0.5 就报错」**恒不成立**。

第一次跑打印 `0.00 秒 → 0.00 秒`，看着像通过，其实什么都没量。

**修法**：用 `ffmpeg -i` 解析 stderr 的
`Duration:\s*(\d+):(\d{2}):(\d{2})\.(\d{1,3})`。
修完复跑：**183.25 秒 → 183.25 秒** ✓

**规矩**：**「量到了 0」和「没量到」必须能区分。** 一个函数返回 0 的时候，
调用方没法知道是真 0 还是失败 —— 所以量不到就抛，别返回 0。

### 3.2 抽样哈希会骗人 —— 三对「看起来一样」的 30 GB 文件

**现场**（2026-10-14，网盘去重）：三对大文件（31.70 GB / 19.53 GB / 12.63 GB）
**前 8 MB + 1/3 + 2/3 + 尾 8 MB 的抽样哈希全部相同**，
按抽样判就是「重复」→ 会误删 **~63 GB**。

**全量 SHA-256 一算**：
| 组 | 差异字节数 | 第一处不同 |
|---|---|---|
| `minimax_h3_fl2va_int8_convrot` 31.70 GB | 2,071,866 | 偏移 10,676,600,832 |
| `minimax_h3_fl2va_pruned…` 19.53 GB | 342,933 | 偏移 9,730,785,280 |
| `Comfyui-WF-2026.8.8.7z` 12.63 GB | 5,167,861 | 偏移 11,022,630,912 |

safetensors / 7z 的**头完全一致**，尾部有零散差异 —— 像一次中断的拷贝留下的残缺副本。

**规矩**：**要动 30 GB 的东西，就花 511 秒把 283 GB 全算一遍。**
抽样是为了快，但快出来的结论如果是错的，省下的时间要加倍还回去。

### 3.3 「音轨在」不等于「音轨里有声音」—— 整条音轨被静默砍断

**现场**（2026-10-14，《觉醒》拼片）：每格 H3 段片都自带环境音
（`格1_本机.mp4` mean_volume **-40.9 dB**），拼出来的片子：

```
Duration: 00:00:24.29                        ← 时长对
Stream #0:1: Audio: aac (LC), 48000 Hz…      ← 音轨在
（volume 一量）mean_volume: -91.0 dB          ← 整条是数字静音
```

`ffprobe` 全绿、退出码 0、滤镜图没有一条 warning。

**机制**：ffmpeg 的 `amix` 和 `sidechaincompress` 都是**「谁短跟谁」**：

- `amix=inputs=N:duration=first` → 输出长度 = **第 1 条输入**的长度
- `sidechaincompress` → 输出长度 = main 与 sidechain 里**短的那条**

而人声是**有限长**的（最后一句台词说完就没了）。于是
「原声 + 人声（侧链压低）」这条链里，第一句台词开始才有声音，
**最后一句说完整条音轨就断掉**。实测最后一句在 23.0 秒结束，
23.5 秒处新旧两套链都是 **-91 dB**，而输入在同一点是 **-40.1 dB**。

**修法**：进 `amix` / `sidechaincompress` 之前，**每一条流都先 `apad` 铺满整片**：

```ffmpeg
[人声]asplit=2[人声出0][人声键0];
[人声出0]apad=whole_dur=31.290[人声出];    ← 两条分支都要补
[人声键0]apad=whole_dur=31.290[人声键];
```

`anoisesrc` 产棕噪也要写 `duration={总+5}`；兜底链要把无限长的那条放第 1 位
（`[风][人声]amix=duration=first`，不是 `[人声][风]`）。

**判据**（`D:\DSHworkspace\影匠\_验混音_觉醒.py`）：同一条片子两套链、同一批窗口对比 ——

```
窗口                   旧链(丢原声)     新链(留原声)      差
4.0s　没人说话           -51.8 dB       -44.9 dB     +6.9
6.6s　人声在说           -16.5 dB       -16.5 dB      0.0   ← 该一样就得一样
10.5s 没人说话          -52.0 dB       -39.0 dB    +13.0
23.5s 没人说话          -52.1 dB       -36.5 dB    +15.6   ← 修好后不再静音
```

**规矩**：**「流存在 / 时长对 / 退出码 0」三样加起来，仍然什么都说明不了。**
要判「这段有没有声音」，只有一条路：**在具体时间点上量 `volumedetect`**。
两条判据缺一不可 —— 只看「空窗更响了」会漏掉「人声被环境盖住」，
只看「人声够响」会漏掉「环境音全丢了」。
**而「该打平的窗口必须打平（0.0 dB）」这一条，专治「改了 A 顺手把 B 也改了」。**

详见 [`音轨截断.md`](音轨截断.md)。

### 3.4 数白像素判字幕 —— 量的是画面，不是字幕

**现场**（2026-10-14，《觉醒》成片质检）。想验「64 条字幕是不是都在对的时刻烧上去了」，
写了个探针：抽某一时刻的帧，把底部 20% 裁出来，**数接近纯白（>=235）的像素个数**，
多就判「有字幕」。

**结果一眼就不对**：
```
第10条 「今年不是你。」  句中 3180  句前 4178     ← 句前的白像素比句中还多
第15条 「四十年。」      句中 1529  句前 5139
第24条 「一年一道。」    句中 1457  句前 5242
```
64 条里 22 条判成「没字幕」，而这 22 条全是**画面本身发白**的镜头
（霜地、白衣、白墙、亮天）。

**根因**：白像素的个数由**画面内容**决定，跟字幕没有因果关系。
字幕只占底部那几行，而画面一白，整个底部都白。
**这就是「判据和要证明的事之间没有因果链」的教科书形状** ——
数是量了，量得还挺认真（都精确到个位），但它量的是另一件事。

**修法**：字幕是**后来烧上去的一层**。同一个镜头里，
「有字幕的那一帧」和「没字幕的那一帧」**差的正好是那几行字**。
所以直接做**帧差**（裁同一条字幕带、逐像素取绝对差、求平均）：
画面内容被减掉，剩下的就是字幕本身。
判据变成「句中差 >= 2.0 且明显大过句前差」。

**修完复跑**（抽 12 条铺开全片）：
```
  1 青云山下，没人记得他的名字   句中 74.99  句前 0.00   ✓
 36 它还在跳。               句中 68.71  句前 16.95  ✓
 56 那是我划的。引荐帖我没送。     句中 71.28  句前 14.38  ✓
```
12 条里 10 条直接过；剩下 2 条（第 11、26 条）是**参照帧选错了** ——
那两句前面正好卡了一个镜头切换，「句前差」被切换本身抬高（24.5 / 21.2），
不是字幕没上来。这两条的「句后差」是 54.92 / 54.82（句中 → 句后变化极大），
正好证明字幕句中在、句后没了。**12/12 通过。**

**规矩**：**判「某样东西在不在画面上」，要做帧差，不要数颜色。**
颜色是画面的属性，帧差才是「多出来的那一层」的属性。
另外：**参照帧必须和被测帧在同一个镜头里** —— 跨切的参照帧会把切换本身算进来。

### 3.5 用「相邻两句之间的缝」量环境音 —— 缝正好卡在压缩器的恢复期

**现场**（2026-10-14，《觉醒》混音）。要判「台词有没有被 H3 的原生环境声埋掉」，
第一版探针取「上一句字幕结束 → 下一句字幕开始」的中点，量那里的响度当环境音电平。
结论是「台词只比环境高 **2.9 dB**，被埋了」。

**这个数不可信**。配音排轴改成「一句都不许往回挪」之后，
相邻两句之间**只剩 0.20 秒**，而这个缝正好落在侧链压缩的
`release=450`（毫秒）里面 —— 量到的 -29 dB 是**环境音还没放回来**的读数。

**修法**：留白窗必须**离任何一句字幕都 >= 0.6 秒**才采（侧链早已放开、环境音回到满值），
两边都取**中位数**而不是平均。重跑：
```
  台词窗 64 个  中位 -15.9 dB
  真空窗 71 个  中位 -34.9 dB
  → 分离度 +19.0 dB  ✓
```

**规矩**：**取样点要避开被测机制的过渡期。** 动态处理（压缩、限幅、淡入淡出）
都有恢复时间，落在恢复期里的读数既不是「压着」也不是「放开」，两头都不算。

## 四、族四：判据**太严**（把正常判成故障）

### 4.1 `规范化()` 逐字符比 ComfyUI 的回执 → L2 永远红

**现场**：本机发 `"fps": 16`（int），ComfyUI 收到后按节点声明折算，
`/history` 里存回来是 `"fps": 16.0`（float）。逐字符比永远差这一处。

**修法**：`_归一值(v)` —— 数值统一成 float 规范写法（整数写成 int）、
字符串去首尾空白；bool 先拦（它是 int 子类）。

**注释里写死的理由**：
> 判据太严会跟判据太松一样没用：太松放过真改动，太严天天误报，人就学会无视它。

### 4.2 `配音.py 自查()` 把**故意留空**的测试夹具判成故障

**现场**：改陈旧文案时断言写宽了，`配音.py 自测` 当场 `exit=1`。

**修法**：区分「有词却失败」和「空句报错」——
空句是夹具，**本来就该报错**，那是在测「空输入被挡住了」。

**规矩**：**测「坏输入被拦」的用例，会让「有失败」变成正确状态。**
断言必须知道自己在测哪一种。

### 4.3 我自己犯的：把「正常在跑」判成「卡死」

**现场**（2026-10-14 11:47，本机出《雪线》格4）：
看到 ComfyUI 日志停在 `75%|██▌ | 15/20`、GPU 却 100% 353 W，
判「采样卡死」，**杀了两个出片任务、重启了 ComfyUI**。

**真相**：我拿日志时间戳去比一个**我从来没核对过的「现在」**。
我以为过了 20 分钟，其实只过了 4 分钟。格4 单独重跑 **149.5 秒**就出了 —— 完全正常。

**规矩**：**凡是要说「卡住了」，先打一次 `Get-Date`。**
判「没进展」需要一个**可信的现在**，而「现在」是这一次判据里最容易漏掉的那一项。

## 五、族五：**作用域**没覆盖到，但报「过」

### 5.1 `补模型.py 验` 三关全过 → 一跑就炸

**现场**：
```
第 1 关 过   第 2 关 过   第 3 关 过   退出码 0   可以合成
```
然后：
```
RuntimeError: IndexTTS 执行失败：{"node_id": "2", "node_type": "IndexTTS25BaseNode",
 "exception_message": "No module named 'contractions'\n", "exception_type": "ModuleNotFoundError"}
```
**三关只查模型文件在不在，一个字都没查 Python 依赖。**

**修法**：加第 4 关（依赖关，读 28 个 requirements 包，`importlib.metadata` 查分发名，
不 import，28/28）+ 第 5 关（冒烟关，40 个模块分「只查在不在」/「真 import ✓」），
凑成**五关闸门**。

**规矩**：**判据说「过」要先问它作用域覆盖到哪。**
「文件在」和「能跑」之间隔着一整层依赖。

### 5.2 `配音.py _上传()` 问本地文件系统，不问服务端

**原代码**：
```python
输入夹 = COMFY根 / "input"
if (输入夹 / 名).is_file():
    return 名          # ← 本地有就当服务端也有
```
**它是错的**：ComfyUI 用 `--input-directory` 指向了
`D:\Comfy-Desktop\ComfyUI-Shared\input`，而 `COMFY根` 是**程序目录**。
程序目录的 `input\` 里躺着 02:43 的旧文件 → 直接 return → 服务端那份根本不存在 →
`LoadAudio: Invalid audio file`。

**修法**：删掉「本地存在就跳过」的捷径，**无条件走 HTTP 上传**，失败才回退到拷贝。

**规矩**：**判据必须问服务端，不能问本地文件系统。**
本地有文件 ≠ 服务端看得见。这和 `Test-Path pagefile.sys` 是同一个形状。

### 5.3 `映射命中: 0` 把三件事混成了一个 0

**现场**：`dub` 跑 4 句台词，报 `映射命中: 0`，看起来像映射表是空的。
**真相**：表是好的（2067 B，里面有凌霜），它跑的时候**只给了 `音色` 没给 `角色`**，
而 `批量()` 查映射的条件是「有 `角色` 字段」。

同一个 `0` 可以是三种完全不同的情况：
- 表是空的
- 没给角色字段
- 角色名写错了

**三者要做的动作完全不同**，而字段名把它们混成了一个。

**规矩**：**汇总计数要能拆开。** 一个 0 必须能回答「为什么是 0」。

### 5.4 只搜子目录就报「文件没了」

**现场**：只 grep 了 `网盘\下载`，就向用户报 31.67 GB 的
`FeiHou_MiniMax-H3_Remix_v0.6_int8_convrot_v2.safetensors`「没了」。
**它一直在 `网盘\HF\diffusion_models\` 下（34,004,449,966 B），`下载\` 里从来没有过。**

**规矩**：**报「找不到」之前，先说清楚搜的是哪棵树。**

## 六、族六（跨类）：**两处各自拼路径，一定在分隔符上分叉**

**现场**：映射表用反斜杠，`音色库.json` 里 `相对` 存的是正斜杠（`Path.as_posix()` 风格）。
**同一个文件，被判「不存在」。**

**规矩**：归一化函数必须同时管**大小写/空白**和**分隔符**。

## 七、一条跨所有族的规矩

上面七次里有 **三次** 的后果是「差点做破坏性动作」：
- 差点重建一个**正在用**的页文件
- 差点重新下载 **20 GB**
- 差点误删 **63 GB**

所以：

> **破坏性动作前，用一个和主判据无关的第二判据复核一遍。**
> 说「在」的要两个说在；说「不在」的也要两个说不在。
> 只有一个判据支持的删除，不做。

## 八、族八（反向）：判据说**「有问题」**，其实什么都没量

> 前面七族都是「检查说 OK，其实没量」。这一族方向相反 —— **我说「这里有毛病」，
> 同样一个字都没量。** 危害不比前七族小：前七族会让我以为做完了，
> 这一族会让我去做一件**本来不必做**的事，而且**在做之前就把结论报给了用户**。

### 8.1 ★ 2026-10-15 06:55 「《觉醒》台词挤得太靠后」

**我说的话**：「新发现但没动：**《觉醒》台词挤得太靠后**（前 60 秒只 4 条，
第 190–240 秒一分钟塞 11 条）。这个要改得重排台词轴，不是改文字。」

**真值**（`作品\觉醒\配音\台词.srt`，66 条，逐条量）：

| 窗口 | 条数 | 字数 | | 窗口 | 条数 | 字数 |
|---|---|---|---|---|---|---|
| 0–30s | 5 | 47 | | 150–180s | 8 | 54 |
| 30–60s | 7 | 54 | | 180–210s | 4 | 28 |
| 60–90s | 6 | 55 | | 210–240s | 7 | 40 |
| 90–120s | 6 | 44 | | 240–270s | 8 | 74 |
| 120–150s | 9 | 64 | | 270–300s | 6 | 42 |

- **前 60 秒是 12 条，不是 4 条** —— 第 4.30 秒就有第一条，第 8.26 秒第二条。
- **两个数不是同一把尺子**：「一分钟塞 11 条」是 **180–240 这 60 秒**的条数；
  同一个口径下前 60 秒是 **12 条** —— **12 比 11 还多**，「挤在后面」这个趋势根本不存在。
- 超过一格时长（4.4583 秒）的台词**只有 2 条**，溢出 0.09s / 0.41s。全 66 条**中位 2.19 秒**。
- 「格65 有一条 40 字、12.64 秒的台词」**也是编的** —— 没有这样一条。

**病根**：我读到 `_成片_觉醒.py` 自己打的一句**提示性**信息
（`格65 说到 259.71s，已经进了下一格（下一格 257.29s 起）`），
把它当成了「缺陷」，然后**顺着这个结论去凑证据** —— 凭印象报出「4 条」「11 条」「40 字」，
一条都没算。

**判据**（三条，写进 `记忆\经验\流程与脚本.md`）：

1. **说「有问题」之前，先把那个数算出来。** 一条 `print` 就能算的东西，不许凭印象说。
2. **比较两个数，先确认它们是同一把尺子**（同样的窗口宽度、同样的计数单位）。
   口径不同的两个数放进同一句话，会造出一个不存在的趋势。
3. **脚本自己打的提示 ≠ 缺陷。** 工具报「已经进了下一格」是在陈述事实；
   要不要当成毛病由我判断，而判断依据仍然只能是量出来的数。

**这一族的通用形状**：**结论先于测量**。前七族是「先写检查、后补理由」，
这一族是「先有印象、再找证据」。两族的解药是同一条 ——
**把判据写成一个能跑的数，而不是一句能说的话。**
