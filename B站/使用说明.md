# B站投稿通道 使用说明（biliup-rs）

这条通道负责把本机的 MP4 投稿到你的 B站账号。**全程不碰浏览器、不碰账号密码**：登录靠手机扫码，投稿靠一条命令行。

---

## 1. 装在哪 / 什么版本

| 东西 | 位置 |
| --- | --- |
| 投稿程序 | `D:\DSHworkspace\B站\biliup.exe` |
| 登录凭证 | `D:\DSHworkspace\B站\cookies.json`（登录后自动生成） |
| 扫码登录脚本 | `D:\DSHworkspace\B站\登录B站.ps1` |
| 上传脚本 | `D:\DSHworkspace\B站\上传视频.ps1` |
| 配置文件模板（可选） | `D:\DSHworkspace\B站\config.yaml` |
| 上传日志 | `D:\DSHworkspace\B站\upload.log` |

- 版本：`biliup-cli 0.2.4`（`biliup.exe --version` 实测输出）
- 来源：GitHub release `biliup/biliup-rs` 的 `v0.2.4`，asset `biliupR-v0.2.4-x86_64-windows.zip`，解出来就是**一个单文件 exe**，没有附带 dll。
- ⚠️ 上游仓库 `biliup/biliup-rs` **已经归档**（README 让人迁移到 `biliup/biliup`，那个是 Python 版，不是同一个东西）。0.2.4 是目前最后一个 Windows 版。它短期内够用，但如果哪天 B站接口大改，这个 exe 会失效，届时要么找社区 fork，要么换 Python 版。

## 2. 第一次：扫码登录（你只需要做这一步）

在 PowerShell 里跑：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File "D:\DSHworkspace\B站\登录B站.ps1"
```

（如果你的终端里没有 `pwsh`，把上面的 `pwsh` 换成 `powershell` 一样可以。）

**接下来会发生什么：**

1. 脚本弹出**一个新的黑色命令行窗口**，里面有 6 个选项：账号密码 / 短信登录 / 扫码登录 / 浏览器登录 / 网页Cookie登录1 / 网页Cookie登录2。
2. 脚本会等你 4 秒，然后**自动按 ↓ 和回车**，帮你选中第 3 项「扫码登录」。
   - 只有它确认那个窗口确实在前台才会按键；否则它会让你手动按。看到 `[OK] 已尝试自动选择「扫码登录」` 就说明自动选成功了。
3. biliup 在窗口里画出二维码，同时**存成 `D:\DSHworkspace\B站\qrcode.png`，脚本会自动弹出这张图片**。
4. 用**手机 B站客户端**（不是微信）扫码 → 手机上点确认。
5. 窗口自己关闭，脚本打印 `[OK] 登录成功！` 和你的账号 mid。

二维码有效期约 180 秒。**过期了就直接关掉那个黑窗口，重新跑一次脚本**——脚本已经把旧的 `qrcode.png` 清掉了，不会给你看一张废码。

### 登录相关的其它操作

```powershell
# 换账号，或者 cookie 失效了重新登（旧的会先备份成 cookies.json.bak.时间戳）
pwsh -NoProfile -ExecutionPolicy Bypass -File "D:\DSHworkspace\B站\登录B站.ps1" -重新登录

# 不想让脚本自动按键，自己手动选（比如自动选偏了）
... -手动选择

# 不想被弹出图片查看器打扰，只看路径
... -不打开二维码

# 等久一点（默认 300 秒）
... -超时秒 600
```

登录凭证 `cookies.json` 里除了 cookie 还有 `access_token` + `refresh_token`（TV 端登录态）。biliup 每次投稿前会自动校验并按需刷新，**正常用不会自己过期**，不用频繁重登。

## 3. 投稿

最简的一条：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File "D:\DSHworkspace\B站\上传视频.ps1" `
    -视频路径 "D:\成品\第1集.mp4" `
    -标题 "AI短动画 第1集" `
    -标签 "AI动画,AI短片,原创动画" `
    -分区 47 `
    -AI生成声明
```

**加 `-试运行` 可以先看它准备提交什么，不会真的投出去**（强烈建议第一次这么干）：

```powershell
... -试运行
```

### 全部参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `-视频路径` | **必填**，一个或多个 MP4 路径 | — |
| `-标题` | **必填**，≤80 字 | — |
| `-简介` | 简介正文 | 空 |
| `-标签` | 逗号分隔字符串，或字符串数组，≤10 个 | 空 |
| `-分区` | 分区 tid（见第 5 节） | `47` 短片·手书·配音 |
| `-封面` | 封面图路径（jpg/png） | 空＝B站自动截帧 |
| `-定时发布时间` | `"2026-10-20 20:00"` / `"1761000000"`(10位时间戳) / `"+6h"`；**必须比现在晚 4 小时以上** | 立即发 |
| `-AI生成声明` | 在简介**最前面**插入一行 AI 声明 | 关 |
| `-AI声明文本` | 自定义那句声明 | 内置一句 |
| `-线路` | `bda2`/`ws`/`qn`/`bldsa`/`tx`/`txa`/`bda`/`alia` | biliup 自己选 |
| `-并发数` | 单文件最大并发 | `3` |
| `-提交接口` | `client`/`app`/`web`（**三个最终都走 APP 接口**，见第 6 节） | `client` |
| `-转载` / `-转载来源` | 标记为转载并写来源 | 自制 |
| `-禁止转载` | 禁止他人转载 | 关 |
| `-开启充电` | 允许充电 | 关 |
| `-关闭评论` / `-关闭弹幕` | 关闭评论 / 弹幕 | 关 |
| `-精选评论` | 开启精选评论 | 关 |
| `-空间动态` | 投稿同时发一条空间动态 | 空 |
| `-额外参数` | JSON 字符串，透传给 biliup，平铺进投稿请求体 | 空 |
| `-跳过确认` | 不打印确认、直接投（自动化用） | 关 |
| `-试运行` | 只打印，不投稿 | 关 |
| `-Cookie文件` `-日志文件` `-根目录` | 覆盖默认路径 | 脚本目录 |

脚本做的事：**先校验**（文件在不在、标题长度、标签个数、封面存在、定时时间够不够 4 小时）→ **打印一张元数据表让你按回车确认** → 拼 biliup 命令 → 执行 → **把完整命令和原始输出都追加进 `upload.log`**。失败时日志里保留 biliup 的原始报错。

### ⚠️ AI 声明这条要特别注意

- biliup-rs 0.2.4 **没有** AI 声明的专用参数（`upload --help` 和源码里都没有这个字段），这点已经查证过。
- 所以 `-AI生成声明` 的做法是**往简介文本里写一行声明**——不是 B站那个官方勾选框，只是给观众看的文字。
- 如果你要的是**官方那个 AI 标注开关**，得自己在网页端投稿页勾一次。`-额外参数 '{"字段名":值}'` 是留给这种需求的逃生通道（它会把 JSON 平铺进投稿请求体），但**具体字段名我没有验证过**，别盲目当它有效。

## 4. 用配置文件投稿（可选，进阶）

`config.yaml` 是模板，想批量/固定多套参数时用。**通过配置文件投稿时，命令行上的 `--title` `--tag` `--tid` 等全部被忽略**（这是 biliup 的设计，两条路互斥）。

```powershell
D:\DSHworkspace\B站\biliup.exe -u "D:\DSHworkspace\B站\cookies.json" upload -c "D:\DSHworkspace\B站\config.yaml"
```

两个必须知道的点：

1. **配置文件只能是 YAML**，不能改成 `.toml`。biliup 0.2.4 源码里是 `serde_yaml::from_reader(...)` 写死的，喂 TOML 会直接报解析错。模板里九个字段（`copyright` `source` `tid` `cover` `title` `desc_format_id` `desc` `dynamic` `tag`）**一个都不能省**，其余可以省。
2. ⚠️ **`config.yaml` 模板本身没有实机验证过**。原因：biliup 是先校验登录态、再读配置文件，我手上没有有效 cookie，所以无法真的跑一遍解析。模板是照 0.2.4 源码的 `Studio` 结构体逐字段推导出来的。**你登录后第一次用之前，先拿一个视频试一次**，如果报 YAML 字段错，按报错信息调（多数字段都有默认值，缺字段比多字段更容易出问题）。

## 6. 常见错误

| 现象 | 原因 / 怎么办 |
| --- | --- |
| `Error: IO error: not a terminal` | `biliup login` 必须在**真终端**里跑，用管道/重定向喂输入会直接失败。别自己写程序调用它——用 `登录B站.ps1`。 |
| `无法加载文件 ... 因为在此系统上禁止运行脚本` | 执行策略。用 `pwsh -NoProfile -ExecutionPolicy Bypass -File "路径"` 调用，或先 `Set-ExecutionPolicy -Scope Process Bypass`。**不要**改成 `RemoteSigned` 全局了事。 |
| 脚本里中文乱码 / 找不到中文路径 | `.ps1` 必须是 **UTF-8 带 BOM** 保存。这两个脚本已经加了 BOM，如果你自己改过，用记事本另存为「UTF-8 带 BOM」或 VSCode 右下角改编码。 |
| `请先登录` / cookie 相关报错 | 跑 `登录B站.ps1 -重新登录` 重新扫码。 |
| `延时发布时间` 相关报错 | 定时时间必须**比现在晚 4 小时以上**，B站的硬规则。想立刻发就别传 `-定时发布时间`。 |
| 标题被拒 | 上限 80 字（脚本会提前拦）。标题里别放 `【】` 以外的特殊符号堆砌，容易被判标题党。 |
| 标签被拒 | 上限 10 个（脚本会提前拦）。 |
| 二维码扫了没反应 / 提示过期 | B站二维码约 180 秒失效。关掉黑窗口，重跑 `登录B站.ps1`。 |
| 上传很慢 / 中途断 | 换线路：`-线路 bda2` 或 `-线路 qn`；也可以降并发 `-并发数 1`。 |
| `--submit web` 好像没用 | 正常。0.2.4 里 client/web 两个接口都已被上游标记失效，最终都会 fallback 到 APP 接口 `https://member.bilibili.com/x/vu/app/add`。所以 `-关闭评论`/`-关闭弹幕`/`-精选评论` 实际都能用。 |
| 上传成功但稿件不见了 | 用 `D:\DSHworkspace\B站\biliup.exe -u cookies.json list --is-pubing` 看审核中的稿件；`show <vid>` 看某个稿件详情。 |

## 7. 哪些是实测过的，哪些不是

**实测过（可信）：**
- `biliup.exe --version` → `biliup-cli 0.2.4`
- 所有子命令的 `--help` 原文（本文档里的参数名都是从实际输出抄的）
- `登录B站.ps1` 的完整链路：开窗 → 自动选中「扫码登录」→ 生成 `qrcode.png` → 超时正确退出（exit 2）。**扫码那一下没测**（没有你的手机，也不该替你登录）。
- `上传视频.ps1` 的 `-试运行` 全链路、以及全部校验报错路径（文件不存在/标题超长/标签超限/定时时间不合规/封面不存在/JSON 非法/未登录），都返回正确退出码。
- cookies.json 的结构（照源码 `credential.rs` 的 `LoginInfo` 写死的校验）。

**没验证（用之前留意）：**
- `config.yaml` 能否被 biliup 真正解析（没有 cookie，跑不到那一步）—— 见第 4 节。
- AI 的官方标注字段名 —— 没查到，也没验证。
- 真实上传（没有 cookie，且不应该替你投稿）。

# 附：整条流水线（情报 → 选题 → 出片 → 审片 → 投稿）

投稿通道只是末端。前面还有四段，都在 `D:\DSHworkspace\B站\` 下。

## 一条铁律：做完先给你看，你点头才上传

**这东西不会自己把片子发出去。** 投稿那一步有两道锁，缺任何一道都停在第 4 段：

1. **落盘的 `_审批.json` 必须是「通过」** —— 这个文件只能由你显式签字产生，`投稿.py` 自己写不出来
2. **还得显式加 `-投稿`**

代码里**故意没有 `--强制` / `-直接投` 这类绕过开关**。半夜自动跑、或者手滑多敲个参数，都发不出去。

## 一个入口

```powershell
# 出片 → 生成审核页 → 停下等你表态
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\DSHworkspace\B站\一条龙.ps1" `
    -脚本 "D:\DSHworkspace\B站\制作\它记得.json" -线 14b

# 你看完签字放行之后，再跑一次加 -投稿，才真的发
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\DSHworkspace\B站\一条龙.ps1" `
    -脚本 "D:\DSHworkspace\B站\制作\它记得.json" -线 14b -投稿
```

| 参数 | 作用 |
|---|---|
| `-脚本` | 要出的片子（脚本.json）。不填则只跑到选题为止 |
| `-线` | 动态镜头用 `14b`（默认，质量优先）或 `5b`（快） |
| `-出图线` | `zimage`（默认）或 `qwen`（写实） |
| `-投稿` | **只有在已签字放行时**才真的投；不加则出完片停下 |
| `-只合成` | 图已定稿，不重新出图（换动态线重跑时用） |
| `-跳过动态` | 动态镜头退化成静帧运镜 |
| `-只情报` / `-只选题` | 只跑前两段 |

## 五段分别是什么

**① 情报**（`run_daily.ps1` → `抓热榜.py` + `分析.py`）
产出 `情报\热榜日报_<日期>.csv`（30 列明细）和 `题材分析_<日期>.md`。
三条硬结论：活动 tag 有 **41.6× 杠杆**；播放量和投币率在不同题材上**背离 42 倍**；**粉丝数不是门槛**（小号放大倍数 103× vs 大号 8.1×）。

**② 选题**（`选题决策.py`）
读 CSV 出 `本周片单_<日期>.md`。
⚠️ 数据池里有三个量级差 3 万倍的池子（近 30 天热榜 / 总榜 / 按发布时间），**必须分开算**，混算会得出「热榜里有 119 播放的视频」这种鬼话。

**③ 出片**（`制作\出片.py`）
```
脚本.json → [出静帧] → [Wan 2.2 I2V 出动态镜头] → [PyAV 混编] → 成片.mp4
```
镜头加 `"动态": 5.0` 就变成真运动镜头。实测产能：

| 环节 | 耗时 |
|---|---|
| Z-Image 出静帧 | ~5 秒/张 |
| Qwen-Image 出静帧（20 步） | 45.1 秒/张 |
| Qwen-Image 出静帧（4 步 + Lightning LoRA） | **6.0 秒/张** |
| 图集运镜合成 | ~2.8 秒/张 |
| Wan 14B 动态镜头 | **12.5~13.8 秒/秒视频** |
| Wan 5B 动态镜头 | 5.6 秒/秒视频 |

出片这步**只备好文案，不投**。

**④ 审片**（`制作\审片.py`）
把一支片子的全部待判材料汇成一页 `审核.html`：成片播放器 → 技术参数 → 投稿文案 → 封面 → 12 帧分镜。看完签字：

```powershell
$PY = "D:\Comfy-Desktop\ComfyUI-Installs\ComfyUI\ComfyUI\.venv\Scripts\python.exe"
& $PY "D:\DSHworkspace\B站\制作\审片.py" "D:\DSHworkspace\B站\成片\它记得" --通过 -备注 "可以投"
& $PY "D:\DSHworkspace\B站\制作\审片.py" "D:\DSHworkspace\B站\成片\它记得" --打回 -备注 "第3镜太暗"
```

签完字会在成片目录写 `_审批.json`，这就是第 ⑤ 步的钥匙。

**⑤ 投稿**（`制作\投稿.py` → `上传视频.ps1`）
先查 `_审批.json`，没有或不是「通过」就**直接退出（退出码 2）**，连确认提示都不给。
过了闸门才做校验（标题 80 字 / 简介 2000 字 / 标签 10 个 / 封面存在且格式对），再调上传脚本。

**默认走 14B**：5B 会让角色漂移、末帧形变、高光过曝；14B 锁得住姿态。2.3 倍代价买「角色不变形」很划算。纯风景镜头才用 5B 省时间。

## 出图有两条线（`--出图线`）

| | `--出图线 zimage`（默认） | `--出图线 qwen` |
|---|---|---|
| 模型 | Z-Image-Turbo `z_image_turbo_int8_convrot`（5.78 GB） | Qwen-Image 2512 `qwen_image_2512_fp8_e4m3fn`（19.03 GB） |
| 文本编码器 | `qwen_3_4b_fp8_mixed`（5.25 GB） | `qwen_2.5_vl_7b_fp8_scaled`（8.74 GB） |
| VAE | `ae.safetensors` | `qwen_image_vae.safetensors` |
| 步数 / cfg | 8 步 / **cfg=1.0** | 4 步 + Lightning LoRA / **cfg=1.0** |
| 1024×1024 耗时 | **~5 秒** | **~6 秒** |
| 1536×864 耗时 | ~4 秒 | 7~19 秒 |
| 画风 | 动画电影感、扁平插画 | 写实 CG 渲染感、材质细节丰富 |
| 负面提示词 | **无效**（`ConditioningZeroOut`） | **有效**（cfg>1 的真负面） |

> Qwen 的 4 步快线靠 `Qwen-Image-2512-Lightning-4steps-V1.0-fp32.safetensors`（1.58 GB）。
> 原生 20 步要 **45.1 秒**，挂上 LoRA 只要 **6.0 秒**——**7.5 倍**，画质肉眼看不出差别。
> 传 `--lora ""` 可以退回 20 步原生（cfg 会自动改成 4.0）。

```powershell
python 出片.py 它记得.json --出图线 qwen --只出图
```
`一条龙.ps1` 也有对应开关：`-出图线 qwen`。

**怎么选**：要「动画感」用 Z-Image（快、扁平、赛璐璐）；要「照片级质感」用 Qwen（材质、锈迹、金属反光强得多）。实测同一个机器人的提示词，Z-Image 出的是动画角色，Qwen 出的是能数清铆钉的写实机体。

## 脚本.json 的格式

```json
{
  "标题": "它记得",
  "画布": "1920x1080",
  "每张秒": 5.0,
  "转场秒": 0.8,
  "风格前缀": "cinematic anime film still, dramatic golden hour light, ",
  "角色": "a lone small round-bodied robot, single large round glass eye, ",
  "输出目录": "D:/DSHworkspace/B站/成片/它记得",
  "投稿": {
    "活动": "AI MV 大赛",
    "副标题": "废弃城市里，它还在原地等一个不会回来的人",
    "简介": "...",
    "标签": ["AI动画", "AI短片"],
    "分区": 27,
    "AI声明": true
  },
  "镜头": [
    {"提示词": "sitting on the edge of a ruined rooftop...", "运镜": "推近", "动态": 5.0},
    {"提示词": "extreme close-up of a note in a door gap...", "运镜": "推近",
     "字幕": "第七天，纸条上的字变了",
     "有声": {"秒": 15, "提示词": "Cinematic night scene, a note in a door gap..."}},
    {"提示词": "macro close-up of its single round glass eye...", "运镜": "右到左",
     "字幕": "它把整座城市记了三十年。"}
  ]
}
```

一句话：**三种镜头，按字段自动分流**。

| 字段 | 走哪条线 | 耗时 | 用途 |
|---|---|---|---|
| `有声` | MiniMax-H3 文生视频 | **约 21 分钟 / 15 秒** | 唯一能出声音的（对白、呼吸、环境音跟画面一起生成） |
| `动态` | Z-Image 出图 → Wan 2.2 I2V | 约 75 秒 / 5 秒（14B） | 有动作但不说话的镜头 |
| （都没有） | Z-Image/Qwen 静帧 + Ken Burns | 约 5~7 秒 | 大多数镜头，性价比最高 |
| `字幕` | 任意镜头可加 | 0 | 底部居中白字黑描边，自动折行 |

BGM 挂在脚本顶层：`"BGM": "D:/.../music.mp3"`、`"BGM音量": 0.16`。

跑 `python 出片.py --示例` 能打出完整示例。

## 做短剧：`做短剧.py`（声音优先）

`出片.py` 管画面，镜头时长是写死的；**短剧的节奏由台词决定**，所以另有一个编排层：

```powershell
python 做短剧.py 剧本.json                 # 一 keyboard 到底
python 做短剧.py 剧本.json --只配音         # 先听一遍台词
python 做短剧.py 剧本.json --跳过配音       # 改了画面重出（复用已有 wav）
python 做短剧.py 剧本.json --跳过混音       # 只要无声画面
```

它比 `出片.py` 多一层「声音优先」，四步：

1. 收集剧本里所有 `说` 字段 → 调 `配音生成.py`（IndexTTS-2）批量出 wav
2. **用配音的实际长度反推每个镜头该停多久**（`前留白 0.45s` + 台词 + `后留白 0.75s`，下限 1.6s、上限 12s）
3. 把算好的时长写成派生剧本，交给 `出片.py` 出图/动态/合成（画面 + 字幕）
4. 按镜头累计时间算出**每句台词的绝对起点**，写成 `_旁白表.json`，调 `配音.py --旁白表` 混上对白和 BGM

剧本在 `出片.py` 格式上多三个字段：

| 字段 | 位置 | 作用 |
|---|---|---|
| `说` | 镜头 | 这句台词交给 IndexTTS-2 念，而且**决定这个镜头多长** |
| `无角色` | 镜头 | `true` 则这一镜去掉角色锁（空镜/环境镜用） |
| `参考` / `情绪` | 镜头或顶层 | 指定音色参考 wav / 情绪标签 |

实测一条 3 镜（2 句台词）：TTS 24 秒 → 出图 3×5 秒 → 合成 232 帧 → 混音，**旁白精确落在 0.45s / 3.26s**（两个有台词镜头的起点），成片带字幕、对白、BGM。

> ⚠ 角色锁是**全片生效**的，所以「空走廊」「城市远景」这类镜头必须写 `"无角色": true`，
> 否则模型会把主角硬塞进去（实测踩过）。


## 声音是怎么来的（重要）

**本机唯一能出声的是 MiniMax-H3**（视频 + 音频联合生成）。它很贵——15 秒要 21 分钟——所以只给真正需要说话/出声的镜头用，其余靠静帧 + BGM。

`视频拼接.py` 会自动处理声音：
- 任何片段带音轨 → 输出 AAC 48kHz 立体声（`🔊`）
- 没音轨的片段自动补等长静音（`·（静音补）`）
- **画面和声音共用同一套交叉溶解裁剪**，不会错位
- BGM 循环铺满、两端 1.2 秒淡入淡出、超 0.99 峰值自动限幅
- 想强制静音：`--无声`

## 角色一致性：三条踩过的坑（重要）

1. **别写「The recurring character, identical in every shot」**——`recurring` / `every shot` 是复数语义，模型照着画一群。实测五个镜头出了 2/2/3/3/2 个机器人。
2. **别加「exactly one robot in the entire frame」**——Z-Image 是 guidance 蒸馏模型（cfg=1.0），负面条件走 `ConditioningZeroOut`，**否定句完全无效**，反而因为重复提及 `robot` 让数量更多（镜头 5 出了 5 个）。
3. **唯一有效的写法**：把角色描述压成**主语前的形容词短语**放 `角色` 字段，每条提示词前拼一次，全句只出现一次，用 `lone` 限定。

## 下载模型的两个坑

- **续传 + HTTP 错误页 = 静默文件损坏**。曾出现文件大小和 Content-Length 完全一致、进度条 100%，但头 15 字节是 ASCII `Entry not found`（错误页），ComfyUI 报 `The safetensors header is too large`。**所有 `curl` 下载都要加 `--fail`**，让 HTTP 错误码直接失败，绝不把错误页存成文件。
- **lightx2v 的 Lightning LoRA 按底模分多个仓库**，别猜路径。先 `hf-mirror.com/api/models/<repo>` 看文件表再下（`Qwen-Image-Lightning` 里没有 2512 版，2512 版在独立的 `Qwen-Image-2512-Lightning`）。

## 环境上的两个硬坑

- **本机没有 PowerShell 7**，`pwsh` 不在 PATH，实际跑的是 Windows PowerShell **5.1**。它会把**无 BOM 的 UTF-8** 当 GBK 读，脚本里的中文全变乱码 → **所有 `.ps1` 必须存成 UTF-8 带 BOM**。用 `edit` 工具改完 BOM 会丢，得用 `io.open(p,'w',encoding='utf-8-sig')` 重写。
- **ffmpeg 不在 PATH**，`D:\Comfy-Desktop` 下也搜不到。但 ComfyUI 的 venv 里有 **PyAV**，所以视频编码走 PyAV，不需要 ffmpeg（字幕也是 PIL 预渲染 + alpha 合成，不依赖 ffmpeg 的 subtitles 滤镜）。
